# 橱窗待售进度商品级联合覆盖设计

日期：2026-07-17
联合覆盖修订：2026-07-20
目标项目：`D:\Project\ProjectRest\project-rest-new`

## 1. 背景与目标

当前版本已用格子内的半透明覆盖替代旧 5px 横向进度条，但每个占用格分别裁切并重新计算覆盖高度。横向商品会显露格子分块，纵向商品还会把一条整体进度错误地重复到每一格，无法把多格商品读成一个整体。

本次改造将待售进度改为“商品级联合液面覆盖”：同一商品的全部占用格先组成一个联合轮廓，再由一条全局液面从联合轮廓底部向上增长。进度只绘制在真实占用区域内，但不会在每个格子内重新开始一次。商品成交时，整个联合轮廓与所有占用格同步播放一次短促反馈。

本次只改进度呈现和成交瞬间反馈，不改变销售速度、库存、经营轮次、结算、存档或拖拽规则。

## 2. 玩家可见行为

### 2.1 常态进度

- 仅在经营阶段为库存大于零的商品显示进度覆盖。
- 同一商品只拥有一个进度覆盖实例和一条全局液面，不按占用格分别创建独立进度。
- 商品全部占用格的外接高度作为液面行程；覆盖高度为 `商品联合轮廓外接高度 × 当前销售进度`，方向从下向上。
- 横向相邻格共享一条连续液面与连续亮边，不在格子边界重新裁切或重启进度。
- 纵向两格商品在 50% 进度时，下方格完整覆盖、上方格不覆盖；不是两格各覆盖一半。
- L 形等不规则商品只在真实占用格与液面覆盖区域的交集中绘制，不覆盖外接矩形中的空格或孔洞。
- 覆盖层使用高饱和琥珀橙 `#F06400`、45% 不透明度；商品图案在覆盖层下仍可辨认，同时与浅色商品形成足够对比。
- 液面亮边使用暖金黄 `#FFE08A`、100% 不透明度，负责清晰标示当前进度位置。
- 液面顶部显示一条较亮的细边，以强化当前进度高度。
- 调整阶段、无商品格和库存耗尽商品不显示覆盖层。

### 2.2 成交反馈

- 一件商品成功售出后，该商品的所有占用格同步播放约 0.2 秒的“亮边脉冲 + 轻微闪白”。
- 成交反馈结束后，若商品仍有库存，覆盖层归零并开始显示下一件商品的销售进度。
- 若商品库存耗尽，覆盖层与成交反馈结束后保持隐藏，继续使用现有售罄灰态。
- 成交反馈只响应已经确认并应用的销售事件，不根据进度值自行推测成交。

### 2.3 交互与视觉层级

- 商品级进度覆盖统一使用 `MOUSE_FILTER_IGNORE`，不得截获悬停、拖拽、放置或右键输入。
- 视觉层级从低到高为：格子底色、商品图案、销售进度覆盖、名作光效与边框、预览色、商品分组轮廓、状态徽章。
- 原有整件商品底部 5px 进度条移除，避免同一信息重复表达。
- 扩建格、道具格、拖拽预览格和未解锁格不显示销售进度覆盖。

## 3. 组件设计

### 3.1 `showcase_sale_progress_group.tscn`

新增一个可复用的商品级覆盖场景，实例挂在 `ShowcaseFeedbackLayer`：

```text
ShowcaseSaleProgressGroup (Control)
└── 由脚本 _draw() 绘制联合填充、全局液面亮边和成交边缘脉冲
```

- 场景保存覆盖色 `#F06400 / 45%`、亮边色 `#FFE08A / 100%`、亮边宽度和 `MOUSE_FILTER_IGNORE` 等稳定视觉属性。
- 实例按商品 `recipe_id` 唯一存在，不按占用格重复创建。
- 控件范围使用商品所有有效占用格的外接矩形；输入的格子矩形转换为控件局部坐标。
- `_draw()` 先计算全局液面 Y 坐标，再仅绘制每个真实占用矩形与液面覆盖区域的交集。
- 亮边只沿液面穿过的真实占用区间绘制；横向相邻区间合并，避免重复线段和格子接缝。
- 调整阶段、售罄或无有效占用格时隐藏实例。拖拽预览与真实商品占用格相交时隐藏整个商品级覆盖，避免只隐藏部分轮廓；无关预览格不影响该商品。

### 3.2 `showcase_slot.tscn` 与 `showcase_slot.gd`

- 格子内的 `SaleProgressClip`、`SaleProgressFill` 和 `SaleProgressEdge` 不再承担常态销售进度，防止商品再次被拆成独立小块。
- `SaleCompleteFlash` 继续保留在格子场景中，用于成交时让所有真实占用格同步闪白。
- `play_sale_complete_feedback()` 继续安全重启格子闪白；商品级亮边脉冲由对应的 `ShowcaseSaleProgressGroup` 播放。
- `clear_product_visual()` 仍须清理格子成交反馈，防止动态复用格子时遗留状态。

### 3.3 `main_view.gd`

- 继续使用 `_showcase_round_item_view(recipe_id)` 返回的 `progress`、`phase` 和 `quantity`，不新增计时来源。
- 维护 `recipe_id -> ShowcaseSaleProgressGroup` 的显示层实例映射；刷新时复用现有实例并清理已经下架的商品实例。
- 从真实格子控件的 `global_rect` 生成商品联合轮廓坐标，不根据配方外接矩形臆造占用格。
- 在确认并应用销售事件、完成售罄格刷新后，通知商品级覆盖播放亮边脉冲，并继续按 `cell_indices` 通知格子闪白。
- 保留旧 `ShowcaseSaleProgress_*` 动态 `ProgressBar` 的删除状态；新的商品级覆盖不是 `ProgressBar`，也不拥有独立计时器。
- `ShowcaseFeedbackLayer` 继续承载连锁箭头、断链标记和成交反馈；商品级覆盖使用独立名称前缀，清理逻辑不得误删其他反馈节点。

## 4. 数据流

```text
ShowcaseRoundSaleService.advance
        │
        ├── item_states.cycle_elapsed_ms / duration_ms
        │          │
        │          └── _showcase_round_item_view.progress
        │                         │
        │                         └── 商品级 ShowcaseSaleProgressGroup
        │                                      │
        │                                      └── 全局液面与联合轮廓交集
        │
        └── 已确认 sale event.cell_indices
                                   │
                                   ├── 商品级覆盖播放亮边脉冲
                                   └── 每个占用格播放 SaleCompleteFlash
```

进度覆盖只消费现有运行时数据。它不拥有计时器、不写入游戏状态，也不参与销售结算。

## 5. 边界与异常状态

- `progress` 缺失或类型异常时按 `0.0` 处理；超出范围时裁切到 `0.0–1.0`。
- 格子节点无效、索引越界或商品占用格为空时，只剔除无效矩形；没有任何有效矩形时隐藏该商品覆盖，不影响其余商品刷新。
- 商品横跨多行时，液面行程按所有有效占用格的外接高度计算；行内空格不参与绘制，但不会改变全局液面高度。
- 窗口尺寸、橱窗格尺寸或扩建模式变化后必须重新采集格子矩形，不能复用过期像素坐标。
- 若同一帧发生多个成交事件，每个事件只通知自己的 `cell_indices`。
- 若成交后立刻售罄，允许短促成交反馈完成；反馈结束后保持进度层隐藏。
- 打开全局弹窗时沿用当前橱窗页面的显示策略，不为进度覆盖增加新的暂停或结算分支。

## 7. 完成标准

- 玩家无需查看细小横条，即可从商品占用格直接判断当前销售进度。
- 多格商品只有一个从联合轮廓底部向上增长的全局液面，不在每个格子中重复进度。
- 多格和不规则形状商品只覆盖真实占用格，不覆盖外接矩形中的空格。
- 成交瞬间有明确但不过度喧闹的视觉节拍。
- 原有拖拽、右键、预览、名作视觉、售罄状态、销售结算和存档行为保持不变。
