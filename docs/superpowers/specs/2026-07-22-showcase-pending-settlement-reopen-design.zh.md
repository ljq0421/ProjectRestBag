# 待结算按钮重新打开结算弹窗设计

## 目标

营业轮进入 `settlement` 阶段后，如果玩家关闭“本轮营业结算”弹窗，橱窗上的“待结算”按钮应保持可点击。点击该按钮重新打开当前待结算弹窗，让玩家继续完成余货处理和轮次确认。

本次只补充结算弹窗的恢复入口，不改变营业计时、成交收益、余货决策、挑战评价、教程事件或存档字段。

## 状态与按钮语义

按钮同时读取 `active_business_round.phase` 和 `pending_showcase_settlement`：

| 轮次阶段 | 待结算数据 | 按钮文字 | 是否可点击 | 点击结果 |
| --- | --- | --- | --- | --- |
| `adjusting` | 无 | 开始营业 | 是 | 按现有流程开始新一轮营业 |
| `running` | 无 | 营业中 | 否 | 无 |
| `settlement` | 有 | 待结算 | 是 | 重新打开当前结算弹窗 |
| `settlement` | 无 | 结算异常 | 否 | 无，并通过提示说明需重新加载 |

正常营业结束时，即使没有可处理余货，`pending_showcase_settlement` 仍应包含稳定的 `settlement_id` 和营业摘要。因此，`settlement` 阶段缺少待结算数据不是“可以开始下一轮”的信号，而是状态不一致。

## 交互路径

复用现有 `ShowcasePanel.start_round_requested` 信号和 `_start_showcase_business_round()` 入口，不新增场景按钮或公共信号。

入口按以下顺序处理：

1. 当前阶段为 `settlement` 且存在待结算数据时，调用 `_present_showcase_round_settlement()`，返回成功，不运行开始营业逻辑。
2. 当前阶段为 `settlement` 但缺少待结算数据时，显示明确的结算异常提示并返回失败。
3. 其他阶段继续执行现有的功能解锁、扩建模式、库存和开始营业校验。

重新打开弹窗只读取已经保存的待结算报价，不重新生成报价、不发放收益、不增加营业次数，也不改变轮次阶段。只有弹窗发出 `settlement_confirmed` 后，现有原子结算路径才应用决策并进入下一轮 `adjusting`。

## 控件刷新

`_refresh_showcase_round_controls()` 不再把所有非 `adjusting` 阶段统一禁用：

- `settlement` 且有待结算数据时，“待结算”按钮启用。
- `settlement` 且无待结算数据时，按钮显示“结算异常”并禁用。
- `running` 仍显示“营业中”并禁用。
- `adjusting` 保留现有解锁、扩建模式、空橱窗和库存校验。

异常状态的按钮工具提示说明结算数据缺失，需要重新加载存档；不得静默重置轮次或跳过结算。

## 验证

聚焦回归应覆盖：

1. 正常营业结束后进入 `settlement`，结算弹窗可见，“待结算”按钮可点击。
2. 隐藏结算弹窗后触发同一按钮，断言弹窗重新显示。
3. 重新打开弹窗前后，金币、营业次数、轮次 ID、待结算报价和已应用结算 ID 均不变化。
4. 确认结算后进入 `adjusting`，待结算数据清空，按钮恢复为“开始营业”。
5. 构造 `settlement` 但待结算数据为空的异常状态，断言按钮显示“结算异常”且禁用，不允许开始下一轮。
6. 保留现有营业锁定、空橱窗和结算原子性回归。

## 非目标

- 不禁止标题栏、Esc 或其他方式关闭结算弹窗。
- 不新增独立“处理结算”按钮。
- 不自动重建缺失的待结算报价。
- 不为异常状态增加存档迁移或静默修复。
