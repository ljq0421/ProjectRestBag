# 米浆饮料配方图标清晰度试样设计

## 目标

仅使用 `rice_milk_drink` 的三阶段 1024×1024 源图验证新的运行时图标生成规则，解决当前多次缩放和尺寸不匹配造成的明显模糊。试样确认前不批量处理其他配方。

阶段映射保持不变：

- `_1`：试作品；
- `_2`：人气款；
- `_3`：招牌款。

## 范围

本次只改动 `rice_milk_drink` 在以下五个显示面：

| 显示面 | 目标资源尺寸 | 实际控件尺寸 |
| --- | ---: | ---: |
| 研发结果 | 128×128 | 128×128 |
| 图鉴 | 112×112 | 112×112 |
| 库存及库存拖拽 | 80×80 | 80×80 |
| 制作操作行 | 32×32 | 32×32 |
| 上架切片 | 每格 72×72 | 每格 72×72 |

`resources/ui/icons_v1/rice_milk_drink_1.png`、`_2.png`、`_3.png` 始终保留为 1024×1024 源文件。其余九个已经接入阶段图标的配方不改变资源、manifest 条目或运行行为。

## 方案

### 普通显示面

扩展 `tools/install_staged_recipe_icons.py`，让各显示面从 1024 源图直接生成最终控件尺寸，不再先生成较大中间图再由 Godot 二次缩放。

缩放使用高质量降采样。缩放完成后仅对 RGB 通道执行轻量锐化，alpha 通道直接沿用缩放结果，避免锐化透明边缘导致白边、黑边或锯齿。32×32 制作图标允许使用比 80×80、112×112、128×128 略强的锐化参数，但不裁剪、不放大主体、不改变原构图。

### 上架显示面

扩展 `tools/generate_staged_showcase_recipe_icons.py`，支持按配方生成独立的每格像素尺寸。`rice_milk_drink` 使用 72×72 单格，其余配方继续使用现有 80×80 单格。

`rice_milk_drink` 的每个 manifest 条目记录自身 `cell_size: 72`，其 `regions`、画布宽高和旋转结果均按 72 像素计算。运行时继续只读取条目中的 regions，因此可以在同一 manifest 中兼容 72 和 80 两种切片尺寸。

上架主体仍遵守已有完整性规则：

- 旋转后再按最终连续占格区域内接缩放；
- 外边缘保留与 72 像素单格成比例的透明安全边距；
- L 形等不规则占格不得通过清空缺失格裁断主体；
- 试作品、人气款、招牌款及全部已有变体和旋转方向都要生成。

### 增量发布

生成器采用按配方替换策略：复制现有阶段上架资源包到临时目录，只删除并重建 `rice_milk_drink` 文件和 manifest 条目，验证通过后再原子替换输出目录。这样试样不会删除或重生成其他九个配方。

生成失败时保留现有运行时文件，不发布半成品。

## 清晰度验收

清晰度不能只用文件尺寸判断。试样同时采用以下验收：

1. 确认五个显示面生成尺寸与控件逻辑像素尺寸一致，不在控件内部进行额外二次缩放；
2. 确认锐化前后 alpha 通道完全一致；
3. 确认透明边缘没有新增白边、黑边或裁剪；
4. 检查三阶段普通图标和至少一个 0°/90° 上架旋转图；
5. 对比旧图与新图的局部边缘和主体细节，由用户判断锐化强度是否合适；
6. 32×32 图标如果仍无法保留复杂细节，记录为需要独立简化图形的限制，不继续无限增强锐化。

## 自动验证

- 更新普通图标生成器测试，验证四个目标尺寸、源文件不变和 alpha 保持；
- 更新阶段上架生成器测试，验证混合 cell size、增量替换、72×72 regions、旋转和不规则形状完整性；
- 更新资产审计，允许 manifest 条目使用独立 `cell_size`；
- 运行配方图标服务、上架图标服务、真实主场景上架路径、拖拽预览和 MVP 自检；
- 运行 `git diff --check`，确认没有修改其他配方的二进制资源。

## 回退

试样只修改 `rice_milk_drink` 的派生运行时资源和对应 manifest 条目。若视觉结果不理想，可以调整锐化参数后重新生成；若放弃方案，可从试样前 Git 版本恢复这些派生文件，1024 源图不受影响。
