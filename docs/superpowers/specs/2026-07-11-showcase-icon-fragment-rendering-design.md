# 橱窗跨格配方图标设计

## 目标

将橱窗中当前“每个占用格重复显示完整配方图标”的表现，改为“一张连续配方图跨越全部占用格”。图标必须遵循配方的标准形状、异形 `shape_cells`、上架变体和当前旋转方向，同时保留现有拖拽、锁定格、销售、存档和局部刷新行为。

## 已确认的产品规则

- 多格商品显示为一张连续图片，不在每个格子重复完整图标。
- 异形商品只在实际占用格显示图片，缺失格保持透明并继续显示普通空格。
- 商品旋转时，图标方向与占格形状同步旋转。
- 占用格内不重复显示配方名称。
- 完整名称、数量、变体、倒计时和收益信息通过悬停提示显示。
- 只有商品锚点格显示紧凑状态徽标。
- 橱窗专用图标放在 `res://resources/recipe_icons_showcase/`，原始 `res://resources/recipe_icons/` 保持不变。

## 方案选择

采用“离线生成形状画布，运行时通过 `AtlasTexture` 按格切片”的方案。

不采用跨网格覆盖层，因为覆盖层需要额外同步绝对坐标、异形遮罩、输入穿透和 `GridContainer` 布局变化。不采用每格独立 PNG，因为它会产生大量碎片文件并增加资源命名和维护成本。

选定方案继续保留现有 100 个橱窗格按钮。每个按钮只显示所属商品画布的一块切片，因此不会改变拖拽落点、锁定格、点击和局部刷新的基本结构。

## 尺寸规则

橱窗单格尺寸保持 `44×44`。图标在格内的有效区域为 `40×40`，相邻格间距为 `4px`。

形状画布尺寸按外接矩形计算：

```text
width  = columns * 40 + (columns - 1) * 4
height = rows    * 40 + (rows    - 1) * 4
```

典型尺寸：

- `1×1`：`40×40`
- `1×2`：`84×40`
- `2×1`：`40×84`
- `2×2`：`84×84`
- 三格 L 形：`84×84`，缺失格区域透明

## 资源生成

新增仓库内生成器，以以下文件为输入：

- `resources/recipe_icons/<recipe_id>.png`
- `doc/recipe_display_config.json`
- 与 `ShowcaseRuleService.variant_definition()` 一致的变体形状规则

生成器为每种实际可用的“配方、变体、唯一方向”生成形状画布。建议命名：

```text
<recipe_id>__<variant_id>__r<degrees>.png
```

例如：

```text
apple_pie__standard__r0.png
apple_pie__standard__r90.png
apple_pie__small__r0.png
apple_pie__gift_box__r0.png
```

生成步骤：

1. 读取原图并转换为 RGBA。
2. 根据透明通道裁去外围空白。
3. 使用 LANCZOS 保持比例缩放到目标形状画布，不拉伸主体。
4. 对异形缺失格强制清空透明。
5. 当前运行时允许所有多格商品右键旋转，因此所有多格形状都生成不同的方向；旋转后形状相同的方向不重复输出。`rotatable` 仅保留为配置元数据，本功能不以它收窄现有旋转行为。
6. 输出 `showcase_icon_manifest.json`，记录文件路径、配方、变体、方向、画布尺寸、占用格和每格裁剪区域。

生成器先在临时目录完成全部资源和清单校验。只有全部配方成功后，才替换正式输出目录，避免部分生成结果覆盖现有资源。原始图标目录始终只读。

## 场景结构

`showcase_slot.tscn` 保持单格 `44×44`，稳定视觉节点在场景中声明：

```text
ShowcaseSlot (Button)
├─ RecipeIcon (TextureRect, 40×40)
├─ PreviewTint (Control)
└─ StatusBadge (Label 或 PanelContainer + Label)
```

- `RecipeIcon` 和 `StatusBadge` 使用 `MOUSE_FILTER_IGNORE`，不截获拖拽和点击。
- `RecipeIcon` 只显示当前格对应的缓存切片。
- `PreviewTint` 只表达有效或无效拖拽预览状态。
- `StatusBadge` 只在锚点格可见，位于右下角。
- 空格、锁定格和异形缺失格不显示配方切片。

新增专用 `showcase_slot.gd`，继承现有 `output_cell.gd` 的拖放能力，只封装单格视觉操作：设置或清除切片、状态徽标、预览透明度和四边轮廓。格子脚本不读取配方配置，也不计算形状。

## 图标服务与缓存

新增独立橱窗图标服务，职责为：

- 读取并缓存 `showcase_icon_manifest.json`。
- 根据 `recipe_id`、`variant_id`、方向和局部格坐标解析画布及裁剪区域。
- 懒加载实际使用的画布纹理。
- 缓存 `AtlasTexture` 切片。
- 对缺失或不匹配资源执行一次性警告和无图回退。

切片缓存键：

```text
recipe_id + variant_id + rotation + local_cell
```

缓存服务不参与倒计时刷新，也不在运行时缩放、旋转或处理图片像素。

## 运行时数据流

正式展示流程：

1. `main_view.gd` 从当前展示状态取得配方、变体、锚点和所有占用格。
2. 将实际占用格归一化为局部形状，并匹配清单中的方向。
3. 为每个占用格计算局部坐标并从图标服务取得缓存切片。
4. 将切片分发给对应的 `ShowcaseSlot`。
5. 清空占用格原有按钮文字，只在锚点显示状态徽标。
6. 根据上下左右是否有同商品相邻格，只绘制商品外轮廓，隐藏内部边框。
7. 鼠标进入任一占用格时，整体商品外轮廓同步高亮。

拖拽预览流程复用同一套方向匹配和切片结果。有效目标格显示半透明切片；无效目标保留当前拒绝色，不残留图标。预览仅刷新旧、新占用格的并集。

移动、旋转和删除商品时，只清理旧占用格并更新新占用格，不重新创建全部 100 个橱窗按钮。

## 状态徽标与悬停信息

状态徽标按以下优先级显示：

1. 等待销售时显示剩余秒数，例如 `12s`。
2. 到期后显示 `可售`。
3. 无活动倒计时且数量大于一时显示 `×3`。
4. 其他情况隐藏徽标。

所有占用格使用同一份完整悬停提示，包含配方名称、变体、库存数量、销售状态、预计收益和已有规则说明。

## 性能约束

- 缩放、裁剪、透明遮罩和旋转只在离线生成阶段执行。
- 运行时只懒加载实际上架或预览的画布。
- 同一缓存键的 `AtlasTexture` 只创建一次。
- 倒计时刷新只更新锚点徽标文本，纹理缓存数量必须保持不变。
- 拖拽预览继续使用新旧占用格并集，不允许刷新全部 100 格。
- 场景不增加跨格覆盖节点；每个格子继续只使用现有图标节点。

若按 149 个配方、5 种变体、4 个方向且每张都达到 `84×84` 的极端情况估算，全部生成资产的未压缩 RGBA 像素理论上限约为 80 MB。实际会因重复方向去除、较小形状和 PNG 压缩而明显低于该值；运行时采用懒加载，只保留当前上架或预览所需的画布和切片，不会一次加载全部生成资产。

## 错误处理

- 生成阶段发现缺少原图、形状无效、输出尺寸错误、清单缺项或变体规则不一致时，以非零状态退出，不替换正式资源目录。
- 运行时发现资源缺失、清单缺项或实际形状无法匹配时，商品保持无图显示，但上架、拖拽、旋转、销售和存档继续工作。
- 每个缺失资源键只记录一次警告，避免周期刷新反复输出日志。
- 无图回退不改变商品边框、状态徽标和悬停信息。

## 验证

Python 生成器测试：

- 覆盖全部 149 个配方、变体和唯一方向。
- 验证画布尺寸、RGBA 模式、透明缺口、旋转结果和清单裁剪区域。
- 验证原始 `recipe_icons` 字节不变。
- 验证失败时不会覆盖已有正式输出。

Godot 聚焦自检：

- 覆盖 `1×1`、横向、纵向、`2×2`、L 形和旋转后的切片分布。
- 确认缺失格没有切片，内部边框隐藏，外轮廓连续。
- 确认只有锚点显示状态徽标，所有占用格共享完整悬停信息。
- 确认有效拖拽预览显示半透明切片，无效预览不残留切片。
- 确认倒计时刷新前后纹理及切片缓存数量不变。
- 确认拖拽预览刷新范围仅包含新旧占用格并集。

回归验证继续运行现有橱窗放置、旋转、变体、收益、拖拽性能和输出布局自检。

## 非目标

- 不修改橱窗 `10×10` 网格、中心 `6×6` 解锁规则或单格 `44×44` 尺寸。
- 不改变商品占格、变体、旋转、销售、收益或存档规则。
- 不修改图鉴和制作页面的图标目录或布局。
- 不修改原始 512×512 配方图标。
