# 任务驱动的店铺升级设计

## 背景

当前 `project-rest-new` 已实现店铺升级条件与扣款逻辑，但玩家界面没有“营业手册”或其他店铺升级入口。`game_data.json` 中“在营业手册手动升级”的文字已经与运行时界面脱节。

本次调整把店铺升级正式纳入任务页：升级条件作为一个始终可见的成长任务展示，玩家达标后直接在任务详情中确认升级。课程任务与升级任务并行，课程、指定配方和指定经营方式都不阻塞等级提升。

## 玩家规则

- Lv.0 → Lv.1 继续由完整营业教学完成后自动生效，不扣金币。
- 玩家进入 Lv.1 后，任务页立即显示“店铺升级｜升至 Lv.2”。
- Lv.1 及以后，每一级都动态生成一个指向下一等级的店铺升级任务。
- 升级任务与当前等级的教学、成长或经营任务并行显示。
- 升级条件只有两个：
  - 当前持有金币达到本级升级成本；
  - 累计口碑达到本级要求。
- 达标前，“升级店铺”按钮禁用，并显示还缺多少金币与口碑。
- 达标后，玩家点击“升级店铺”：
  - 扣除升级金币；
  - 累计口碑不扣除；
  - 店铺等级提升一级；
  - 沿用现有升级通知，说明新等级和新设备；
  - 当前升级任务消失，并立即生成下一等级的升级任务。
- 升级任务不是待领取奖励，不进入“一键领取奖励”，也不留下已完成待领取卡。

## 任务页信息架构

任务页保持两个页签：

- “当前目标”更名为“成长任务”；
- “支线任务”保持不变。

“成长任务”允许显示多个并行条目，内容包括：

1. 当前等级的动态升级任务；
2. 当前可进行的教学或成长任务；
3. 已完成但奖励尚未领取的成长类任务；
4. Lv.6 后已选择的经营合同。

现有成长课程仍按自己的前置关系依次开放，但它们不再占用唯一的“当前目标”槽位，也不影响升级任务的出现和操作。

## 升级任务模型

升级任务由当前运行状态和 `Catalog.get_upgrade_definition(level + 1)` 动态构造，不在 `game_data.json` 中为每一级复制静态任务。

建议任务条目字段：

- `id`: `shop_upgrade_<目标等级>`；
- `type`: `upgrade`；
- `level`: 当前店铺等级；
- `title`: `店铺升级｜升至 Lv.<目标等级>`；
- `status`: `active`；
- `action_kind`: `shop_upgrade`；
- `can_upgrade`: 来自 `GameState.upgrade_eligibility()`；
- `missing_coins`、`missing_reputation`: 来自同一资格结果；
- 两个动态目标：升级资金、累计口碑。

升级资金显示 `min(当前金币, 所需金币)/所需金币`，累计口碑显示 `min(当前口碑, 所需口碑)/所需口碑`。即使数值超过要求，任务卡也只显示满额进度，详情可继续显示玩家实际持有量。

动态升级任务不写入 `completed_tasks`、`claimed_tasks` 或普通任务进度。等级变化后，任务 ID 自然变化，因此不会重复扣款或残留旧卡。

## 数据流与职责

### `Catalog`

继续作为每个目标等级升级成本、口碑要求和解锁设备的唯一来源。Lv.1～Lv.5 使用明确配置，Lv.6 以后使用现有生成公式。

### `GameState`

继续由 `upgrade_eligibility()` 判断资格，由 `upgrade()` 原子执行扣款和等级提升。任务 UI 不自行修改金币、口碑或等级。

`upgrade()` 成功后继续负责：

- 扣除金币；
- 保留累计口碑；
- 更新等级；
- 写入升级任务事件；
- 加入升级通知。

### `TaskService`

- 构造动态升级任务；
- 将升级任务与当前可进行的成长任务一起放入 `current_entries`；
- 不再只返回一个串行成长任务，而是返回所有当前可用、尚未完成的教学/成长任务；
- 不把升级任务加入完成或待领取集合。

### 任务界面

- 页签文案使用“成长任务”；
- 识别 `action_kind == shop_upgrade`；
- 升级任务详情按钮显示“升级店铺”；
- 按 `can_upgrade` 控制按钮启用状态；
- 点击后由主界面调用 `GameState.upgrade()`，保存游戏并刷新资源栏、任务快照和通知队列。

普通任务仍使用“前往”“领取奖励”“选择合同”等既有动作，不受升级按钮逻辑影响。

## 边界与失败处理

- Lv.0 不生成升级任务，防止绕过完整营业教学。
- 调用升级时再次执行资格校验，不能只依赖按钮先前的启用状态。
- 若点击瞬间金币或口碑不足，不扣资源、不改变等级；刷新任务卡并显示具体缺口。
- 一次点击只提升一级；即使玩家资源足够连续升级，也必须在刷新后的下一张升级卡再次确认。
- 成功升级后立即保存，避免扣款与等级变化只存在于界面状态。
- 当前版本仍处于开发阶段，不增加旧存档迁移逻辑。
- 删除或改写所有“在营业手册手动升级”相关玩家文案，统一指向任务页中的升级任务。

## 验收与测试

实现采用测试先行，至少覆盖以下行为：

1. Lv.0 不显示升级任务。
2. 进入 Lv.1 后，同时显示 Lv.2 升级任务和“销售节奏”，课程不阻塞升级任务。
3. 升级任务正确显示 `升级资金 180/180` 与 `累计口碑 8/8`。
4. 任一条件不足时，“升级店铺”禁用，并返回准确缺口。
5. 满足条件后点击升级，等级变为 Lv.2、金币恰好扣除 180、口碑仍为 8。
6. 成功后 Lv.2 升级任务消失，并出现指向 Lv.3 的升级任务。
7. 升级任务不进入完成、待领取或一键领取列表。
8. 多个成长任务能够同时出现在“成长任务”页签。
9. 升级失败不修改金币、口碑或等级。
10. Lv.6 以后仍从动态升级定义生成正确的任务和条件。

优先扩展现有任务与等级自检；必要时新增聚焦的任务升级 UI 自检。Godot 头部测试必须按仓库要求把 `--log-file` 指向可写临时路径。
