# 橱窗经营入口弹窗尺寸与背景关闭设计

## 目标

优化“橱窗经营”页中由入口按钮打开的非强制弹窗：缩小“特殊挑战”弹窗，并让同类弹窗在点击背景时关闭。

## 交互范围

采用“非强制入口弹窗可背景关闭，关键流程弹窗保持强制确认”的边界：

- 支持背景关闭：特殊挑战、最近营业报告、规则说明等只用于查看或预选的入口弹窗。
- 保持模态：购买确认、营业结算、成长选择等会立即影响金币、库存、结算或流程推进的弹窗。
- 点击背景与点击标题栏关闭按钮最终都走同一隐藏路径，不触发底层页面按钮。

本次实现先覆盖“橱窗经营”页当前直接声明的两个入口弹窗：`StorefrontChallengeDialog` 和 `StorefrontRecentReportDialog`。规则说明已有独立场景，按相同分类检查其配置；若其内部流程属于纯查看，则同步采用背景关闭契约。

## 尺寸与布局

“特殊挑战”弹窗采用紧凑固定尺寸，目标打开尺寸为 `560 × 330`：

- 标题保持“特殊挑战”。
- 说明区域限制高度并继续支持自动换行。
- 三个挑战按钮保留横向并排，不改变可用性、锁定状态或选择逻辑。
- 内容超出时由说明区域内部承载，不扩大整个窗口。

“最近营业报告”保持现有信息密度，但使用明确的紧凑打开尺寸，避免随内容或系统默认值异常放大。

## 技术方案

- 在场景中将非强制入口 `AcceptDialog` 设置为非独占窗口，使 Godot 的窗口外点击产生 `close_requested`。
- 连接 `close_requested` 到统一处理函数，由处理函数调用 `hide()`。
- 打开弹窗时使用显式 `popup_centered(Vector2i(...))`，不再依赖场景默认尺寸。
- 不增加全屏透明遮罩，避免遮罩点击穿透或改变底层控制状态。

## 验证

- 场景测试断言“特殊挑战”以 `560 × 330` 打开，且明显小于当前窗口。
- 对“特殊挑战”和“最近营业报告”分别触发 `close_requested`，断言弹窗隐藏。
- 断言两个弹窗为非独占；底层入口按钮不会因关闭动作再次触发。
- 现有挑战选择、最近报告内容、规则书及橱窗经营布局测试继续通过。

## 非目标

- 不修改挑战奖励、解锁等级或选择规则。
- 不改变营业结算、购买确认、成长选择等关键流程弹窗的模态策略。
- 不重构全局弹窗系统。
