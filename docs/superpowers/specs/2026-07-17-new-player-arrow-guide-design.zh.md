# 新手箭头引导设计

## 背景

`project-rest-new` 已有任务进度、关键解锁通知和采购、产出、研发制作、橱窗经营等完整业务入口，但新玩家仍需要自行理解页面之间的先后关系。此次增加一条只覆盖核心闭环的轻量箭头引导，不恢复大量独立教学任务，也不把教学扩展成逐控件说明。

引导只服务新存档第一次体验，按真实业务成功事件推进。玩家可以逐步跳过当前提示；只有完成后主动关闭，才使该存档不再自动出现。

## 目标

- 用一个始终可见的箭头和一句短提示，指出当前应该操作的控件。
- 只覆盖十个连续阶段：采购水稻种子、手动产出大米、研发米浆饮、制作米浆饮、上架米浆饮、查看构筑规则、调整橱窗商品、开始经营、查看橱窗经营、完成。
- 阶段可以在内部更换箭头目标，用于完成同一业务动作所需的必要操作，但不增加任务式步骤计数。
- 只在业务操作真实成功后推进，不以页面访问、普通点击或库存推断代替成功事件。
- 自动进入当前阶段对应页面，避免再增加“先点击页面标签”的教学步骤。
- 保存当前阶段；退出并重新进入后，从未完成的阶段继续。
- 提供“跳过本步”，只推进到下一阶段，不补资源、不解锁内容，也不代替真实业务操作。

## 非目标

- 不覆盖任务、目录、星芒、自动化、扩建、经营结算或高级橱窗规则。
- 不阻止玩家操作未被指向的控件，也不实现强制遮罩点击区。
- 不为旧存档推断或迁移教学进度；本项目仍在开发阶段，只保证新存档初始值正确。
- 不新增第二套采购、生产、研发、制作或上架逻辑。
- 不根据日志文本反推进度。

## 采用方案

采用“场景内全局引导层 + 十阶段状态机 + 真实事件推进”。

稳定 UI 结构放在独立场景 `scenes/ui/overlays/tutorial_guide_overlay.tscn`，由 `scenes/Main.tscn` 实例化。组件脚本负责箭头绘制、提示卡布局、目标矩形跟踪和跳过本步信号；`scripts/main_view.gd` 负责页面路由、动态目标解析以及把真实成功事件交给状态服务。存档状态仍由 `scripts/game_state.gd` 持有。

不把引导节点动态拼装在 `main_view.gd` 中。箭头、提示文本和跳过按钮属于稳定视觉结构，应保留在 `.tscn`；脚本只做状态、目标绑定与刷新。

## 新存档初始资源

- 新存档默认持有 `1 个泉水引（spring_water_starter）` 和 `10 单位泉水（spring_water）`，不再默认持有水稻种子。
- 第一阶段要求玩家通过真实采购获得至少 `1 个水稻种子（rice_seed）`。
- 产出阶段只要求农场手动收获大米，不要求使用泉水引或从水塘收获泉水。
- 按当前产地配置，第一次农场收获获得 `3 大米`；研发消耗 `1 大米 + 1 泉水` 后，仍有足够材料制作一次米浆饮。
- `spring_water_starter` 与 `sugar` 的购买解锁等级均为 Lv1，正常显示在 Lv1 采购列表中；引导本身不要求购买它们。
- “一键收获”继续由现有“手动收获 10 次”条件解锁；新手箭头引导不指向、不调用也不临时解锁“一键收获”。

## 状态模型

`GameState` 新增：

```gdscript
var tutorial_guide_step: String = "purchase"
var tutorial_guide_finished: bool = false
var tutorial_guide_skipped: bool = false
var tutorial_guide_harvested_ids: Array[String] = []
var tutorial_guide_showcase_moved: bool = false
var tutorial_guide_showcase_rotated: bool = false
```

允许的阶段 ID 固定为：

```text
purchase -> output -> research -> craft -> list -> rulebook -> arrange -> business -> storefront -> complete
```

约束：

- `new_game()` 从 `purchase` 开始，两个结束标记均为 `false`。
- `from_dict()` 只接受允许的阶段 ID；非法值回退到 `purchase`。
- `tutorial_guide_finished` 或旧存档中的 `tutorial_guide_skipped` 任一为 `true` 时，引导保持隐藏；新版“跳过本步”不再写入 `tutorial_guide_skipped`。
- 到达 `complete` 时显示完成面板，但暂不设置 `tutorial_guide_finished`；玩家点击“关闭引导”后才写入完成标记。
- `tutorial_guide_harvested_ids` 只记录产出阶段已真实收获的 `rice`，用于跨存档恢复阶段内进度。
- `tutorial_guide_showcase_moved` 与 `tutorial_guide_showcase_rotated` 分别保存调整阶段是否完成过一次真实移动和一次真实右键旋转；两者均为 `true` 才能离开 `arrange`。
- “再来一遍”只重置上述引导状态和阶段，不重置金币、库存、已知配方、橱窗布局或正在进行的经营轮次。
- 本次不增加旧存档进度推断；载入数据缺少全部引导字段时，按既有存档处理并设为已跳过，避免旧存档突然出现新手引导。

## 十个阶段

### 1. 采购

- 自动显示采购页。
- 箭头指向水稻种子行的“+”按钮，提示“购买一份水稻种子，准备第一次种植”。
- 购物车已包含至少 `1 个水稻种子` 后，同一阶段把箭头改指“购买”，提示“结算水稻种子”。
- 仅 `_purchase_cart_items()` 完整成功且本次实际买到至少 `1 个 rice_seed` 后推进到 `output`；同时购买其他商品不影响完成。
- 购物车为空、金币不足或结算不完整时不推进。

### 2. 产出

- 采购小票关闭后自动显示产出页，避免箭头被弹窗遮挡。
- 箭头指向农场空位；教学阶段点击该空位后，主视图直接复用现有 `_start_output_item_in_site(...)` 入口，以水稻种子开始产出，不打开需要玩家再次猜选项的产出菜单。
- 等待成熟期间，提示卡显示“等待大米成熟”，箭头暂时隐藏；不指向刷新按钮或任何批量操作。
- 成熟后，箭头指向对应农场产出槽及其“收获产出”操作，要求玩家手动收获。
- 整个阶段从不把“一键收获”作为回退目标；该功能默认未解锁，后续仍由现有“手动收获 10 次”条件开放。
- 只有 `ProductionSite.harvest_slot()` 真实成功，并通过 `TutorialProgress.on_ingredient_harvested(...)` 记录到 `rice` 后，才推进到 `research`。
- 大米收获后，现有教学任务应即时解锁 `round_pot`；箭头等待解锁通知关闭后再进入研发页。
- 检查未成熟槽位或刷新页面不推进。

### 3. 研发

- 自动显示研发制作页。
- 箭头依次指向当前缺失的必要输入：大米材料槽、泉水材料槽、蒸煮一体的圆锅工具槽、主“研发”按钮。任一时刻只显示一个箭头。
- 继续使用现有研发选择与 `RecipeBook.research(...)` 路径。
- 当前米浆饮的权威配方保持为 `rice + spring_water`，设备为 `round_pot`，不需要白糖。
- 首次引导仅在真实解锁 `rice_milk_drink` 后推进到 `craft`。
- 非破坏性重播时，若米浆饮已解锁，玩家再次正确选择 `rice + spring_water + round_pot` 并点击“研发”即可推进；不删除配方、不重复消耗材料。
- 其他已知配方、加工成功或研发失败不推进。

### 4. 制作

- 留在研发制作页并刷新配方行。
- 箭头指向米浆饮配方行的“制作”按钮；第一次产出的数量在研发消耗后应自然剩余一次制作所需的 `1 大米 + 1 泉水`，不插入补货步骤，也不额外赠送材料。
- 仅 `RecipeBook.make_product(...)` 成功制作 `rice_milk_drink` 并触发 `TutorialProgress.on_product_made(...)` 后推进到 `list`。
- 点击不可用按钮或制作失败不推进。

### 5. 上架

- 留在研发制作页。
- 箭头指向米浆饮配方行的“上架”按钮；该路径与拖拽上架共用现有橱窗状态出口。
- 只有 `TutorialProgress.on_product_displayed(...)` 收到 `rice_milk_drink` 的真实上架事件后推进到 `rulebook`。
- 仅打开库存、选中商品、拖拽预览或失败的摆放不推进。

### 6. 查看构筑规则

- 箭头指向橱窗上方 `ShowcasePanel/RoundControlBar/RulebookButton` 的“构筑规则”按钮。
- 仅玩家通过该按钮的 `rulebook_requested` 信号成功打开“橱窗构筑规则”弹窗后推进到 `arrange`。
- 弹窗打开期间沿用现有弹窗层级规则隐藏引导；关闭弹窗后恢复为调整橱窗商品阶段。
- 通过橱窗经营页“查看全部规则”等其他入口打开同一弹窗，不视为完成本阶段。
- 不要求玩家继续点击弹窗内分类，也不要求以关闭弹窗作为完成事件。

### 7. 调整橱窗商品

- 箭头指向已上架的米浆饮橱窗商品，提示卡同时显示“拖动一次”和“右键旋转一次”的完成状态。
- 拖动必须通过现有 `_move_showcase_product(...)` 真正改变锚点且返回成功，才记录 `tutorial_guide_showcase_moved = true`；原地释放、非法落点或失败摆放不计入。
- 旋转必须由鼠标右键触发现有 `_rotate_showcase_product(...)`，真正改变占用形状且返回成功，才记录 `tutorial_guide_showcase_rotated = true`；左键、不可旋转商品或失败旋转不计入。
- 两项操作顺序不限，均完成后推进到 `business`。

### 8. 开始经营

- 箭头指向橱窗区域的“开始营业”按钮。
- 仅 `_start_showcase_business_round()` 返回成功、经营轮次真实启动后推进到 `storefront`。
- 若非破坏性重播到达本阶段时上一轮仍在经营，提示卡说明等待当前经营结束，状态不自动跳过且不强制中断经营。

### 9. 查看橱窗经营

- 箭头指向主工作台页签中的“橱窗经营”按钮，提示“点击查看商品的经营状态”。
- 必须由该按钮的实际按下信号进入橱窗经营页后推进到 `complete`；代码主动调用 `_show_page(PAGE_STOREFRONT_MANAGE)` 不视为玩家完成。

### 10. 完成

- 隐藏箭头与普通提示卡，显示紧凑完成面板，文案为“引导已完成”。
- “关闭引导”设置 `tutorial_guide_finished = true`，保存后关闭面板，本存档不再自动显示。
- “再来一遍”把阶段重置为 `purchase`，清空大米收获、拖动和旋转的引导记录，并立即从采购阶段重播；不修改任何业务数据。

## 引导层交互与视觉

引导层保持轻量，不使用整屏变暗和强制点击穿孔。场景至少包含：

- `TutorialGuideOverlay`：覆盖主视口的 `Control`，鼠标过滤为忽略，不吞掉游戏操作。
- `Arrow`：由脚本绘制或使用主题色矢量多边形，朝向目标矩形最近边；进行轻微往返动画。
- `HintPanel/StepLabel`：显示 `1/10` 至 `10/10`。
- `HintPanel/MessageLabel`：一句操作提示，不承载机制长文。
- `HintPanel/SkipButton`：文字为“跳过本步”，是普通提示卡中唯一需要接收鼠标的控件。
- `CompletionPanel`：只在 `complete` 阶段出现，包含“引导已完成”、“关闭引导”和“再来一遍”。

普通提示卡从原先约 `252×98` 缩为约 `200×66`：步骤号使用 12–13px 辅助字号，主提示使用 14px，最多两行；跳过入口使用紧凑文字按钮，不再占据独立大行。完成面板可以略宽，但仍保持内容自适应且不遮挡橱窗经营的关键数据。

箭头和提示卡每帧或在目标布局变化时读取目标控件的全局矩形，确保窗口缩放、滚动列表、动态重建配方行后仍然指向正确位置。提示卡优先放在目标的空闲侧，并限制在视口安全区内；箭头目标无效或不可见时暂时隐藏箭头，下一次刷新重新解析，不得指向旧实例。本次不调整提示卡与箭头之间的相对位置。

弹窗层级规则：采购小票、通知、确认框等全局弹窗可见时，引导层暂时隐藏；弹窗关闭后恢复当前阶段。跳过按钮不覆盖弹窗。

## 目标解析

固定目标直接使用 `Main.tscn` 中的稳定节点引用，例如主操作按钮和“橱窗经营”按钮。动态目标不保存节点实例，而是按语义重新查找：

- 采购数量行：通过物品元数据找到目标行及其“+”按钮。
- 产出槽：通过槽位索引或教学物品 ID 找到当前渲染控件。
- 研发材料、工具与库存项：通过槽位索引或物品 ID 找到当前控件。
- 配方制作/上架按钮：通过 `recipe_id` 与 `recipe_action` 元数据查找。

动态组件继续由各自场景创建，但应暴露一个小型、稳定的目标查询接口或明确元数据。`main_view.gd` 只询问“当前阶段的目标控件”，不依赖子场景内部脆弱的子节点路径。

## 事件推进

扩展 `TutorialProgress` 为引导进度的唯一业务事件入口，保留现有任务记录行为：

- 新增采购成功入口，接收本次实际购买的物品 ID 与数量；只有 `rice_seed >= 1` 能推进采购阶段。
- `on_ingredient_harvested(...)` 同时记录任务事件并尝试推进 `output`。
- `on_recipe_unlocked(...)` 同时记录任务事件并尝试推进 `research`。
- `on_product_made(...)` 同时记录任务事件并尝试推进 `craft`。
- `on_product_displayed(...)` 同时记录任务事件并尝试推进 `list`。
- 新增构筑规则打开成功入口，只允许橱窗上方“构筑规则”按钮的真实信号调用，并从 `rulebook` 推进到 `arrange`。
- 新增橱窗商品移动和右键旋转成功入口，分别记录 `arrange` 的两个必要子条件。
- 新增经营成功启动入口，只在真实创建经营轮次后推进 `business`。
- 新增玩家点击橱窗经营入口，只从按钮按下回调调用。
- 新增关闭与重播入口；关闭只终止引导，重播只重置引导进度。

推进函数必须检查当前阶段，只允许按固定顺序前进一次。提前发生、重复发生或来自其他阶段的事件保持无副作用。每次有效推进后立即保存，并通知主视图刷新页面与目标。

为了避免业务状态类直接持有 UI，`TutorialProgress` 只修改 `GameState`；`main_view.gd` 在真实操作成功出口调用统一的 `_refresh_tutorial_guide()`。主视图初始化、页面重建、弹窗关闭和视口变化时也调用该刷新入口。

## 跳过、页面路由与恢复

- “跳过本步”按十阶段固定顺序只前进一个阶段并立即保存，不设置 `tutorial_guide_skipped`。
- 跳过不增加二次确认，不补发水稻种子、大米、米浆饮等资源，不解锁设备或配方，不触发任务事件，也不模拟采购、收获、研发、制作、上架、布置或经营操作。
- 从 `storefront` 跳过后进入 `complete` 并显示完成面板；完成面板不显示“跳过本步”。
- 每次进入一个新阶段时，主视图只自动切换到该阶段对应页面一次；随后玩家手动切换页面时，引导不得反复将页面拉回。
- 因此玩家跳过采购进入产出后，如果发现没有水稻种子，可以手动切回采购补齐条件；引导状态仍停留在产出，业务条件满足后可继续完成。
- 主视图用当前运行期的“最后已自动路由阶段”记录控制单次自动切页，不新增存档字段；重新载入游戏后该记录为空，因此仍会自动进入保存阶段对应页面一次。
- 保存只记录宏观阶段，不记录材料选择、购物车或某个动态子目标；恢复后根据当前业务状态重新推导阶段内目标。
- 调整阶段的移动/旋转完成标记属于必要的阶段内持久状态，例外地随存档保存，避免退出后要求重复已经成功的手势。

## 边界情况

- 玩家在引导前已完成后续动作：提前事件不跳步；当前阶段仍需一次对应的真实成功操作。
- 玩家跳过存在前置条件的步骤：只推进引导，不补条件；玩家可以自由切回其他页面补齐条件，当前阶段不会强制拉回页面。
- 玩家连续点击“跳过本步”：每次有效点击只推进一个阶段并保存；到达完成态后普通提示卡隐藏，不能继续越过完成面板。
- 目标因列表滚动不在可视区域：目标解析器先把对应项滚动到可视区域，再显示箭头。
- 当前阶段暂时没有合法目标：显示提示卡说明等待条件，箭头隐藏；状态不自动完成。
- 玩家金币不足或材料不足：沿用现有失败反馈，不新增资源赠送。新存档初始金币必须足以购买至少一个水稻种子。
- 采购小票或通知打开：暂停显示，关闭后恢复。
- 上架失败或橱窗格位不合法：不推进。
- 通过“查看全部规则”或代码直接打开构筑规则弹窗：不推进；只有橱窗上方被指向按钮的实际信号算完成。
- 拖动没有改变位置、非右键旋转或旋转失败：不推进对应子条件。
- 重播时米浆饮已知：正确研发操作仅推进引导，不重复扣除材料；错误组合仍沿用正常失败反馈。
- 重播时经营轮次仍在运行：不终止、不结算、不修改经营轮次，提示等待后继续。

- 新存档持有一个泉水引和 10 单位泉水，没有水稻种子；进入游戏后显示“采购水稻种子”阶段，只有一个箭头与一句短提示。
