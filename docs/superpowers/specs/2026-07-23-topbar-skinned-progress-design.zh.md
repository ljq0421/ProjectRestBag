# 顶部金币与口碑皮肤进度条设计

## 目标

把主界面顶部栏现有的金币、口碑升级进度条替换为 `resources/ui/skin_v1` 中的新甜品店素材，同时保留现有升级数据、提示语义、金币滚动动画和页面几何。

本次只改变顶部资源进度的视觉呈现，不改变升级条件、资源扣除、等级推进或存档结构。

## 已确认映射

- 口碑使用 `res://resources/ui/skin_v1/progress_cake.png`。
- 金币使用 `res://resources/ui/skin_v1/top_star_progress.png`。

两张源图保持不修改，作为顶部栏皮肤的原始素材。

## 视觉方案

采用分层动态进度条方案。每个资源模块仍占用 `180×44px`，但不再使用“文字在上、8px 细条在下”的布局，而是把资源数值叠放在素材的进度槽内部。

每个模块从后到前包含：

1. **皮肤图层**：完整显示蛋糕或星星、外框与阴影。
2. **空槽修正层**：在素材的槽体内部覆盖一层不透明棕色底槽，遮住源图中已经烘焙的固定黄色进度。
3. **动态填充层**：使用现有 `ProgressBar` 的真实 `value/max_value` 控制黄色填充长度。
4. **文字层**：在槽体内显示 `金币 当前值 / 要求值` 或 `口碑 当前值 / 要求值`，避开左侧蛋糕或星星图标。

空槽和动态填充只覆盖素材的内部槽体，不遮挡图标、奶油色边框、描边和投影。圆角、颜色和内边距分别按两张素材的槽体位置做局部配置，不把整张 PNG 当作可裁切填充纹理。

### 长度统一修订

蛋糕源图在 44px 高度下等比显示宽度约为 `173.6px`，星星源图约为 `153.9px`。两者不能继续直接使用相同的“整图等比居中”设置，否则金币条会明显短于口碑条。

金币皮肤使用一张派生单纹理：

1. 保留原始 `top_star_progress.png`，不直接修改源图。
2. 从原始 `584×167` 素材生成 `660×167` 的 `top_star_progress_174.png`。
3. 左侧星星和右侧圆角端帽保持原尺寸，只把中间平直槽体加长 76px。
4. 拼接边界位于平直槽体区域，并使用小范围渐变融合，保证边框、高光和阴影连续。
5. 运行时只绘制这一张派生纹理，不再把星星图标与槽体拆成两个 Atlas 图层。

`660×167` 与 `174×44` 的宽高比近似一致，运行时不需要非等比拉伸。金币与口碑的真实动态填充区域继续统一为 `125px` 长，使用相同的左右边界。

### 文字对比度修订

两组资源文字统一使用：

- 字号 `14px`。
- 浅奶油色文字 `#FFF4D1`。
- 深巧克力色描边 `#4A2414`。
- 描边宽度 `3px`。

该组合必须同时在未填充的棕色槽体和已填充的黄色槽体上保持清晰。不能只依赖阴影，也不能继续使用会与棕色底槽融合的深棕色文字填充。

## 几何约束

- `Root/TopBar` 高度保持 `44px`。
- `Root/Body` 顶部位置保持 `y=52`。
- `CoinsLabel` 与 `ReputationLabel` 各保持 `180×44px`。
- 两张皮肤的总显示长度统一为约 `174px`。
- 蛋糕皮肤继续按比例缩放并在模块中居中。
- 星星派生纹理保持图标和端帽比例，只延长中间槽体。
- 两个动态填充区域统一为 `125px` 长。
- 数值文字位于右侧槽体区域，不能覆盖左侧蛋糕或星星。
- 不增加顶部栏高度，不改变店名、金币、口碑、店铺等级的排列顺序。

两个皮肤在 180px 模块内保留约 3px 的水平安全留白。不得在运行时通过分层拼接或非等比拉伸整张星星源素材补齐长度。

## 场景结构

稳定结构继续写在 `scenes/Main.tscn` 中，并保留以下既有节点路径：

- `Root/TopBar/CoinsLabel`
- `Root/TopBar/CoinsLabel/UpgradeProgress`
- `Root/TopBar/ReputationLabel`
- `Root/TopBar/ReputationLabel/UpgradeProgress`

在两个资源标签下分别保留一个置于文字后方的 `SkinTexture` 视觉根节点：

- 金币 `SkinTexture` 直接绑定单张 `top_star_progress_174.png`，没有 `TrackTexture` 或 `IconTexture` 子层。
- 口碑 `SkinTexture` 绑定 `progress_cake.png`。

既有 `UpgradeProgress` 继续承担空槽与动态填充，不新增第二套进度状态。它的位置和大小调整到对应 PNG 的内部槽体，背景必须完全遮住源图的固定黄色填充。

标签通过相同的局部内容边距把文字限制在统一的 125px 槽体区域，并使用已确认的奶油色文字与深色描边。不得用在字符串前拼接空格的方式定位文字。

## 数据与状态

`scripts/main_view.gd` 继续使用 `GameState.upgrade_eligibility()` 作为下一等级要求的唯一数据源：

- 金币当前值来自 `state.coins`，要求值来自 `cost`。
- 口碑当前值来自 `state.reputation`，要求值来自 `required_reputation`。
- 标签保留真实当前值；超过要求时不截断文字。
- 动态填充在视觉上封顶为 100%。

金币结算滚动动画继续通过 `_set_coins_label_roll_value()` 更新文字和金币进度，不新增显示缓存。

提示语义保持不变：

- 金币提示说明升级会扣除所需金币。
- 口碑提示说明升级只检查累计口碑，不扣除口碑。

## 边界状态

- Lv.0 没有普通升级目标时，隐藏皮肤图层和动态进度条，回退为现有纯资源文字。
- `upgrade_eligibility()` 返回 `definition_missing` 时采用同样的纯文字回退，不显示虚构目标。
- 达到或超过要求时填充封顶，标签仍显示真实当前值。
- 升级完成后立即读取下一等级要求并刷新分母、填充和提示。

皮肤和进度条必须作为一个视觉状态同时显示或隐藏，不能出现只有装饰图但没有有效升级目标的情况。

## 实现边界

- 不修改 `GameState.upgrade_eligibility()`、`GameState.upgrade()`、`Catalog` 或任务服务。
- 不修改两张源 PNG。
- 允许新增由 `top_star_progress.png` 确定性派生的 `top_star_progress_174.png`。
- 不生成新的业务状态或存档字段。
- 不改动顶部栏以外的页面。
- 不覆盖工作区中现有的配方图片、图标或其他无关修改。

## 验证

扩展现有顶部栏聚焦自检，至少覆盖：

1. 金币绑定 `top_star_progress_174.png`，口碑绑定 `progress_cake.png`。
2. 两个 `UpgradeProgress` 的节点路径保持不变。
3. 有效升级目标下，皮肤与动态进度同时可见。
4. Lv.0 和 `definition_missing` 下，皮肤与动态进度同时隐藏并回退纯文字。
5. 金币、口碑当前值、分母、超额封顶和升级后分母切换继续正确。
6. 金币滚动动画继续同步更新数值与填充。
7. 源图中的固定黄色区域被空槽修正层完全覆盖，0% 时不残留伪进度。
8. 金币皮肤是单张 `660×167` 纹理，不存在 `TrackTexture/IconTexture` 分层接缝。
9. 星星图标与右侧端帽保持比例，只有中间槽体被延长。
10. 两个皮肤总显示长度均约为 `174px`，两个动态填充区域均为 `125px`。
11. 数值文字不覆盖左侧图标，并使用 `14px` 奶油色文字与 `3px` 深巧克力描边。
12. 文字在 0%、中间值和 100% 填充状态下均清晰可读。
13. `TopBar` 仍为 `44px`，`Body` 仍从 `y=52` 开始，资源模块仍为 `180×44px`。

运行 Godot 4.6.1 headless 自检时必须传入位于可写临时目录的 `--log-file`。除聚焦自检外，再运行场景解析、既有店铺升级自检和 `git diff --check`。
