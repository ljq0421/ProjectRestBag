# 字体清晰度与等比例缩放修复设计

## 背景

`project-rest-new` 以 1920×1080 为界面设计基准。当前项目使用 `window/stretch/mode="viewport"`：Godot 先把完整场景渲染到固定的 1920×1080 视口，再把该视口缩放到实际窗口。窗口尺寸不是 1920×1080 时，文字随整张中间画面一起插值缩放，因此在 2560×1440、编辑器嵌入窗口等输出环境中出现发虚。

项目没有证据表明字体文件或字体导入参数发生了导致模糊的变更。本设计只处理全局缩放路径，不替换字体，也不通过增大字号掩盖问题。

## 目标

- 文字按实际输出分辨率渲染，避免放大 1920×1080 中间画面造成的模糊。
- 保留现有 1920×1080 逻辑坐标和界面设计基准。
- 始终保持完整的 16:9 画面比例；实际窗口不是 16:9 时允许出现黑边。
- 不改变现有页面结构、控件尺寸、字体尺寸、图片资源和业务逻辑。

## 不包含

- 不为低于 1920×1080 的窗口重新设计响应式布局。
- 不替换或新增字体资源。
- 不修改主题颜色、字号体系或界面图片。
- 不改造根场景、输入坐标转换或弹窗定位算法。
- 不修改 `project-rest`，范围仅限 `project-rest-new`。

## 方案

### 项目缩放配置

在 `project.godot` 中保留：

```ini
window/size/viewport_width=1920
window/size/viewport_height=1080
```

将拉伸配置设为：

```ini
window/stretch/mode="canvas_items"
window/stretch/aspect="keep"
```

`canvas_items` 继续以 1920×1080 作为逻辑设计尺寸，但让 2D 界面和动态字体面向实际输出分辨率渲染。`keep` 锁定 16:9 比例；宽高比不匹配的区域由黑边承接，不拉宽、不压扁、不裁切设计画面。

### 回归约束

更新 `tests/ui_scaling_self_check.gd`，要求缩放模式为 `canvas_items`、缩放比例策略为 `keep`。现有 `tests/layout_refinement_self_check.gd` 已要求 `keep`，继续保留该断言。

本次不新增基于截图像素的自动断言。无头测试无法可靠判断主观字体锐度；清晰度由运行时输出检查确认，自动测试负责防止配置回退。

## 验证

使用 Godot 4.6.1，并为所有无头命令传入可写的 `--log-file` 路径。

自动验证至少包括：

1. `tests/ui_scaling_self_check.gd`：确认 `canvas_items + keep`。
2. `tests/layout_refinement_self_check.gd`：确认 16:9 保持策略及主布局约束。
3. `tests/viewport_1920_layout_self_check.gd`：确认 1920×1080 基准下主要页面和弹窗不溢出。
4. `tests/output_layout_self_check.gd`：确认主要产出页面布局不回退。
5. `tests/mvp_self_check.gd`：确认全局配置变更没有破坏主流程。
6. `git diff --check`：确认补丁没有空白错误。

运行时检查覆盖：

- 1920×1080：布局和字号保持原样，画面清晰且无黑边。
- 2560×1440：布局保持 16:9，文字按目标分辨率渲染，不再呈现整帧插值放大的模糊。
- 非 16:9 窗口：完整显示 1920×1080 设计画面，比例不变，剩余区域显示黑边。

## 风险与处理

- PNG 界面纹理仍可能在非整数缩放下出现轻微插值，但动态字体不再经过固定 1080p 中间视口的整帧放大。这是本次修复的预期边界。
- 若某个控件依赖 `viewport` 模式下的最终像素取整，自动布局测试和运行时检查应暴露其位置变化；只修复该控件的局部布局，不回退全局字体清晰度方案。
- 若无头 MVP 测试因沙箱中的 `user://` 写入失败，应按仓库规则区分环境故障与逻辑失败，并使用可写日志路径重新运行；不得通过删除业务断言获得通过。

## 完成标准

- `project-rest-new` 使用 `canvas_items + keep`。
- 非 16:9 输出保持完整 16:9 画面并允许黑边。
- 自动验证通过，或明确记录与本改动无关的既有失败。
- 1920×1080 与 2560×1440 的运行时检查确认字体清晰度改善且布局没有裁切。
- `project-rest` 和无关的用户未提交改动保持不变。
