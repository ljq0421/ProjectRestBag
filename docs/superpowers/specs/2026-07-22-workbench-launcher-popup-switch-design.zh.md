# 右下功能按钮弹窗切换设计

## 背景

`WorkbenchLauncher` 提供 7 个右下功能按钮：星辉、任务、库存、图鉴、采购、产出和橱窗经营。当前按钮回调已经支持打开目标弹窗，也保留了再次点击当前按钮关闭弹窗的 toggle 语义；但弹窗打开后，`GlobalPopupBackdrop` 位于启动栏之上并拦截真实鼠标输入，所以玩家点击另一个功能按钮时只会触发遮罩关闭，无法直接切换。

## 交互契约

- 没有功能弹窗时，点击任一已解锁按钮打开对应弹窗。
- 当前弹窗为 A 时，再次点击 A，关闭弹窗。
- 当前弹窗为 A 时，点击另一个按钮 B，直接切换到 B。
- 点击启动栏之外的普通遮罩区域，仍然关闭当前弹窗。
- 功能锁定校验、各弹窗刷新逻辑和弹窗内部状态保持现有行为。

## 设计

弹窗打开期间将 `GlobalPopupBackdrop` 设为忽略 GUI 鼠标输入，并由 `main_view.gd` 的统一 `_input()` 入口管理弹窗外点击。点击位置位于 `WorkbenchLauncher` 时，由启动栏组件按各按钮的实时全局矩形识别目标并触发现有按钮信号；这也覆盖弹窗尺寸与启动栏局部重叠的情况，不依赖固定坐标。位于全局弹窗和允许交互的顶栏范围内时保留现有行为；其他弹窗外位置则关闭弹窗并将事件标记为已处理，避免穿透到底层页面。

继续复用现有按钮回调和 `_close_if_global_popup_mode()`：相同模式走关闭分支，不同模式则调用目标 `_show_*_global_popup()` 完成原位切换。

不缩小遮罩，也不复制按钮路由逻辑。启动栏只遍历自己的现有按钮映射并读取实时矩形，因此不会把窗口尺寸、按钮坐标或具体布局编码进遮罩处理器，并且普通遮罩区域仍保持原有关闭行为。

## 影响范围

- 场景层级：不改变 `WorkbenchLauncher` 的布局、尺寸或节点路径。
- 脚本：不修改按钮业务回调；统一弹窗输入入口负责区分启动栏、弹窗内部和其他弹窗外区域。
- 测试：扩展工作台弹窗状态自检，加入真实鼠标点击路径。

## 验证

聚焦回归应覆盖：

1. 真实点击按钮 A 后打开 A。
2. A 打开时真实点击按钮 B，`global_popup_mode` 直接变为 B，遮罩与全局弹窗保持可见，只显示 B 的内容。
3. 再次真实点击 B，弹窗关闭。
4. 重新打开弹窗后点击启动栏之外的遮罩区域，弹窗关闭。
5. 研究材料等底层页面状态在打开、切换和关闭期间保持不变。

## 非目标

- 不重新设计弹窗外观、尺寸或背景。
- 不修改功能解锁条件。
- 不改变弹窗内部按钮和二级对话框行为。
- 不将同按钮点击改成刷新或保持打开。
