# 新手引导切页与经营结算顺序修正规格

## 背景

当前 NPC 引导在进入“采购”和“产出”步骤时会立即切换背景页面，导致玩家还没点击对话中的行动按钮，就已经看见对应功能页。经营阶段还存在两个顺序问题：成功开始营业后，“橱窗经营”虽然已写入解锁状态，但底部按钮没有立即刷新；如果玩家先完成真实结算、之后才点击“橱窗经营”，结算事件会因为引导仍停留在“查看经营”步骤而丢失。

## 目标

1. “采购”步骤出现时保留原背景，点击“去买种子吧”后才打开采购页。
2. “产出”步骤出现时保留原背景，点击“去农场看看”后才打开产出页。
3. 成功开始营业后立即开放并刷新“橱窗经营”按钮。
4. “查看橱窗经营”和“完成有真实销量的结算”可以任意顺序发生；两个条件都满足后才进入外婆最终说明。

## 非目标

- 不改变其他引导步骤的页面路由和行动按钮行为。
- 不把营业自然结束视为结算完成。
- 不改变“至少售出 1 件商品”这一真实结算门槛。
- 不改变“我自己来”只隐藏提示、不推进、不解锁的语义。

## 交互设计

### 采购与产出

进入 `purchase` 或 `output` 步骤时，只展示 NPC 对话，不自动打开目标页。玩家点击对话按钮后：

- `purchase`：打开采购弹层，随后进入指向水稻种子购买操作的行动提示。
- `output`：打开产出弹层，随后进入指向农场空位或成熟水稻的行动提示。

点击按钮只负责打开页面和收起对话，不推进引导步骤；步骤仍由真实购买、种植和手动收获事件推进。

### 橱窗经营解锁

成功开始营业后，`TutorialProgress.on_business_round_started()` 继续负责开放 `storefront_manage`。调用完成后立即刷新底部工作台入口，使“橱窗经营”在“看看经营状态”对话出现时已经可点击。

### 查看与结算双条件

引导分别保存两个持久化事实：

- `storefront_viewed`：玩家真实点击并打开过“橱窗经营”。
- `first_sale_settlement_completed`：玩家确认过一次至少售出 1 件商品的真实结算。

事件处理规则：

1. 先查看、后结算：查看后进入等待结算状态；合法结算后进入 `complete`。
2. 先结算、后查看：结算证据先保存，但仍停留在“查看经营”；玩家打开“橱窗经营”后立即进入 `complete`。
3. 营业结束但未确认结算：不保存结算完成证据，不完成引导。
4. 已确认结算但销量为 0：不保存有效结算证据，不完成引导。
5. 重复点击或重复事件：保持幂等，不重复推进或发放内容。

双条件使用现有 `core_unlock_progress` 持久化，不新增仅存在于 UI 的临时状态。

## 实现边界

- `main_view.gd`：取消采购、产出步骤的进入即切页；在对话行动按钮确认回调中打开这两个目标页；营业开始后刷新核心入口；打开橱窗经营时触发双条件检查。
- `tutorial_progress.gd`：结算事件在 `storefront` 或 `settlement` 阶段均可记录有效证据；查看事件记录查看证据，并统一通过一个内部函数判断两个条件是否齐全。
- 不改变采购、产出、营业和结算业务服务本身。

## 验证

至少覆盖以下回归：

1. 初次出现采购对话时采购页未打开；点击“去买种子吧”后才打开。
2. 购买水稻种子进入产出对话时，背景仍为采购页；点击“去农场看看”后才打开产出页。
3. 成功开始营业后，“橱窗经营”入口立即处于已开放状态。
4. 先查看再完成有效结算，进入最终说明。
5. 先完成有效结算再查看，点击查看后进入最终说明。
6. 营业结束但未确认结算，不进入最终说明。
7. 零销量结算，不进入最终说明。
8. 存档往返后，已保存的单边条件仍能与另一条件正确汇合。
