# “研发”失败逐级线索设计

## 目标

降低研发的盲猜难度，同时保留从失败中逐步发现配方的探索感。

玩家针对同一个潜在配方反复尝试时，失败会积累为永久线索。第三级线索直接揭示目标配方、正确设备和完整材料清单，确保玩家不会长期卡住。

本功能只增强尚未解锁成品配方的研发提示，不改变配方匹配、材料消耗、加工配方、店铺等级或设备解锁规则。

## 当前问题

研发规则实际按照“设备 + 精确材料组合”确定性匹配，不存在随机成功率。当前页面显示的“研发成功率”会误导玩家，而设备错误、差一种材料等有效线索通常要在点击失败后才短暂显示于状态区。

现有失败记录以本次设备和材料组合为键。玩家只要更换一种材料，就难以感知此前尝试与新尝试是否指向同一个配方，也没有常驻区域回看已经发现的线索。

## 核心规则

### 候选配方范围

逐级线索只会从同时满足以下条件的配方中选择目标：

- 属于可出售的成品配方，不是中间材料加工配方；
- 尚未被玩家解锁；
- 配方解锁等级不高于当前店铺等级；
- 配方要求的设备已经解锁。

因此，线索不会提前泄露高等级内容，也不会把玩家引向当前无法完成的设备路线。

### 最接近目标

研发失败后，规则层对候选配方进行确定性比较。候选按以下元组从高到低排序：

1. 命中的材料数量；
2. 设备是否正确；
3. 多选错误材料数量的相反数；
4. 缺少材料数量的相反数；
5. 稳定的配方 ID 顺序。

只有至少命中一种正确材料时，才建立目标线索。仅仅选对一个被多种配方共用的设备，不足以锁定目标。完全无关的组合只返回通用提示“这个组合暂时没有研发线索”，不会随机绑定配方，也不会提升任何线索等级。

### 线索等级

线索进度按目标配方记录，而不是按完全相同的尝试组合记录。玩家替换材料继续试验时，只要最近目标仍是同一配方，线索会继续升级。

每次针对目标配方的失败最多提升一级，最高为三级：

1. **方向线索**：提示成品方向、所需材料总数，以及设备方向是否正确；不显示配方名和具体缺料。
2. **接近线索**：显示配方名、正确设备、已命中材料数量，以及缺少材料的类别；不显示具体缺料名称。
3. **完整线索**：显示配方名、正确设备和完整材料清单，并逐项标记“已有”“缺少”或“选错”。

达到三级后永久保留。继续失败不会重复升级或产生新的奖励，只会重新显示完整线索。

### 失败类型处理

- **设备错误**：一级仅提示烹饪方式方向；二级显示正确设备；三级在完整答案中继续标记设备错误。
- **差一个或多个材料**：一级显示材料数量方向；二级显示缺料类别；三级显示具体缺料。
- **包含多余材料**：二级开始显示有多少种材料不属于目标；三级列出具体选错材料。
- **等级不足**：直接显示目标等级，不进入逐级隐藏，避免玩家在当前不可完成的内容上继续尝试。
- **设备尚未解锁**：该配方不进入候选池；如果当前选择的设备无效，则直接显示设备不可用原因。
- **已经研发过的配方**：直接显示“已经研发过”，不升级线索。
- **完全无关的组合**：只给通用方向提示，不记录目标进度。

研发失败的材料消耗沿用现有规则：当前部分接近配方或设备错误路径会消耗所选材料。本功能不改变这些既有路径，也不会因为记录或升级线索而产生额外消耗。

## 数据与存档

在 `GameState` 中新增按配方 ID 保存的线索进度，例如：

```gdscript
research_hint_progress = {
    "cream_shortcake": 2
}
```

同时保存 `latest_research_hint_recipe_id`，用于重新进入研发页时恢复最近一条有效研发笔记。该字段只能指向已有线索进度的配方，否则加载时回退为空。

数值只允许 `1..3`。加载旧存档时缺省为空字典；加载新存档时过滤不存在的配方 ID，并将等级限制在合法范围内。

现有 `discovered_hints` 保留，用于兼容旧存档和既有失败日志。本功能不把新结构强行塞入旧字段，避免破坏原有字符串值格式。

线索内容在显示时根据当前 `Catalog` 配方数据动态生成，存档只保存各目标的等级和最近目标 ID，不复制配方名、材料名或设备名，避免目录内容变更后产生陈旧文本。

## 规则层接口

`RecipeBook.research()` 继续负责研发判定。失败结果在现有 `ok` 和 `message` 之外增加结构化线索数据，供界面显示：

```gdscript
{
    "ok": false,
    "message": "这次研发没有成功。",
    "hint": {
        "target_recipe_id": "cream_shortcake",
        "level": 2,
        "matched_count": 2,
        "required_count": 3,
        "wrong_device": false,
        "extra_material_ids": ["rice"],
        "missing_material_ids": ["cream"]
    }
}
```

规则层负责：

- 筛选当前可提示的候选配方；
- 选择稳定的最接近目标；
- 升级并保存该目标的线索等级；
- 返回结构化的匹配结果；
- 生成适合底部状态栏的单句提示。

界面不自行重新计算最接近配方，避免提示与实际研发规则产生分歧。

`RecipeBook` 同时提供只读的线索展示构造接口。页面刷新时把当前设备、当前材料和已保存的线索等级传入该接口，由规则层返回同样的结构化展示数据。这样玩家更换材料或重新进入页面后，页头与研发笔记可以更新“已有、缺少、选错”状态，而不会在界面脚本中复制配方比较规则。

## 界面设计

### 研发页摘要

移除“研发成功率”文案，改为真实状态：

- 未选择材料：`至少选择 2 个食材开始研发`
- 尚无线索：`当前线索：暂无｜选择设备和食材进行尝试`
- 一级线索：`当前线索：烘焙方向｜接近度 1/3｜线索等级 1`
- 二级线索：`当前线索：鲜奶油小蛋糕｜接近度 2/3｜线索等级 2`
- 已完整揭示：`完整线索：鲜奶油小蛋糕｜可按研发笔记准备材料`

“接近度”使用命中材料数与目标材料总数，不使用百分比，避免再次造成随机概率的误解。

### 研发笔记

在设备、材料选择区与已解锁配方列表之间增加常驻“研发笔记”区域。稳定结构优先声明在 `.tscn` 中，脚本只负责绑定状态和刷新文本。

默认展示最近一次获得或升级的目标线索：

```text
鲜奶油小蛋糕｜线索等级 2
正确设备：烤箱
已确认：2/3 种材料
新线索：还缺一种乳制品
再次接近失败将揭示完整材料
```

三级显示：

```text
鲜奶油小蛋糕｜完整线索
设备：烤箱（正确）
面粉：已有
鸡蛋：已有
鲜奶油：缺少
水稻：选错
```

第一版只展示最近目标，不增加笔记列表、筛选、分页或手动选目标，控制页面复杂度。以后若需要完整研发图鉴，可复用同一份存档进度扩展。

### 即时反馈

每次失败后：

1. 底部状态栏显示一句可立即行动的摘要；
2. 研发笔记刷新为本次目标的详细线索；
3. 新升级的线索等级以明确文案提示，例如“研发线索提升至 2 级”；
4. 保存游戏，确保退出后不会丢失已获得线索。

完全无关的组合仍在状态栏显示通用失败原因，但不会替换玩家最近一次有效研发笔记。

## 代码边界

- `scripts/recipe_book.gd`：候选筛选、接近度比较、线索升级和结构化失败结果。
- `scripts/game_state.gd`：线索进度、最近目标、存档导入导出和数据清洗。
- `scripts/catalog.gd`：继续作为配方、设备、材料与等级要求的唯一事实来源；不为提示复制一份配方表。
- 研发页对应 `.tscn`：声明研发笔记的稳定容器、标题与正文节点。
- `scripts/main_view.gd`：绑定结构化结果、刷新摘要和研发笔记、触发保存；不计算配方匹配规则。

本功能不修改现有配方数据，不增加新的随机成功机制，不改变已解锁配方的制作与补货流程。

## 异常与边界情况

- 目标配方在版本更新中被删除：加载时移除对应线索记录，最近目标回退为空。
- 玩家升级后候选池扩大：已有线索保持原等级；新配方只有在后续尝试接近它时才建立记录。
- 玩家后来解锁目标配方：研发笔记不再把它列为待研发目标；线索进度可保留在存档中，但不参与候选比较。
- 一次尝试同时接近多个配方：使用稳定评分与 ID 顺序选择一个目标，只升级一个目标，避免一次失败刷多条答案。
- 重复材料：按配方和选择中的实际数量进行多重集合比较，不能用简单去重集合误判接近度。
- 复合配方把已制作成品作为材料：名称、库存和匹配均沿用当前配方材料规则，三级线索照常标记。
- 保存失败：研发失败提示仍可显示，但状态栏追加“线索保存失败”，不得静默声称已经永久记录。

## 验证范围

先增加聚焦规则自检并观察其在实现前失败，再写最小实现使其通过。至少覆盖：

1. 第一次、第二次、第三次接近失败分别产生一级、二级、三级线索。
2. 更换材料但仍指向同一目标时，线索继续升级而不是重置。
3. 三级线索返回配方名、正确设备、完整材料及已有、缺少、选错状态。
4. 完全无关的组合不绑定目标、不升级进度，也不覆盖最近有效笔记。
5. 高于当前等级或设备未解锁的配方不进入候选池。
6. 已解锁配方不再作为逐级线索目标。
7. 多个候选同分时目标选择稳定。
8. 重复材料按数量正确计算命中、缺少和多余项。
9. 旧存档可加载；非法配方 ID 和非法等级会被清洗。
10. 保存并重新加载后，线索等级和最近目标保持一致。
11. 研发页不再显示“研发成功率”，并正确显示当前线索摘要。
12. 研发笔记在一至三级显示对应信息，完全无关失败不会覆盖已有笔记。
13. 现有研发成功、设备错误、等级不足、重复研发及材料不足行为不回归。

Godot 头部自检必须从 `project.godot` 所在目录运行，并通过 `--log-file` 指定可写的临时日志路径。

## 完成标准

- 玩家每次接近失败都能获得比上一次更具体、可执行的线索；
- 连续三次接近同一目标失败后，玩家能看到完成该研发所需的完整答案；
- 玩家调整组合不会丢失同一目标的线索进度；
- 页面不再暗示研发存在随机成功率；
- 线索可随存档持久化，且不会泄露当前无法完成的高等级配方；
- 研发规则仍由 `RecipeBook` 统一决定，界面展示与真实判定一致。
