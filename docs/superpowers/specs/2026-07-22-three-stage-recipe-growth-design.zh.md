# ProjectRest New 三档配方成长设计

**日期：** 2026-07-22  
**项目：** `D:\Project\ProjectRest\project-rest-new`  
**状态：** 已批准，待实施计划

## 1. 目标

将配方成长从“试作品、稳定款、人气款、招牌款”四档精简为“试作品、人气款、招牌款”三档，彻底删除稳定款的运行时语义、界面入口、展示配置和专用图标。

本次不保留旧四档存档兼容。新档位编号连续定义为：

- `0`：试作品
- `1`：人气款
- `2`：招牌款

## 2. 成长规则

### 2.1 试作品到人气款

玩家必须同时满足：

- 制作 30 个真实批次；
- 完成 10 次有真实售卖的有效营业；
- 完成 3 次触发正向协同的营业；
- 对应设备达到 L3。

这些门槛合并了原“试作品到稳定款”和“稳定款到人气款”的培养节奏。阶段内计数仍在晋级后清零，不结转溢出。

### 2.2 人气款到招牌款

保持现有门槛：

- 制作 40 个真实批次；
- 完成 14 次有真实售卖的有效营业；
- 完成 8 次触发正向协同的营业；
- 对应设备达到 L5。

阶段内计数在晋级后清零，不结转溢出。

### 2.3 事件计数契约

现有事件语义保持不变：

- 制作进度按真实批次计数，不按产出件数计数；
- 有效营业必须是正常或挑战营业完成且发生真实售卖；
- 清仓、奖励等非真实营业事件不计入有效营业；
- 同一配方每轮最多计一次正向协同；
- 单次事件最多晋升一个阶段；
- 招牌款不再累计普通阶段进度。

## 3. 设备成长上限

设备等级继续作为配方成长上限：

| 设备等级 | 配方成长上限 |
| --- | --- |
| L1 | 试作品 |
| L2 | 试作品 |
| L3 | 人气款 |
| L4 | 人气款 |
| L5 | 招牌款 |

设备等级的使用次数、金币消耗、研发线索增量和 L4/L5 名作制作经验加成保持不变。设备效果文案同步改成三档语义。

当配方已经完成全部非设备条件但设备等级不足时，仍只发送一次等待设备升级通知。设备升级后立即逐道检查关联配方；每道已满足条件的配方最多晋升一个阶段，并在升级摘要中报告立即晋级数量。

## 4. 特性与名作

- 人气款开放原有第一次成长特性选择，并获得现有人气款基础售价加成。
- 招牌款开放原有第二次成长特性选择，并获得现有招牌款额外售价和售速加成。
- 招牌款完成两次特性选择后开启名作系统。
- 名作等级、经验阈值、里程碑外观和最高 Lv.10 称号不变。

删除稳定款不改变成长特性的候选规则、数值或名作经验来源。

成长阶段星光奖励按新档位重新编号，同时保持到达人气款和招牌款时的累计奖励不变：人气款一次领取原前两档合计 3 星光，招牌款再领取 3 星光。

## 5. 数据与素材

### 5.1 展示配置

`doc/recipe_display_config.json` 的 `growth_variants` 只保留：

- `popular`
- `signature`

生成器和 Python 契约测试同步删除 `stable`。人气款继续继承试作品的基础布局；招牌款继续只覆写配置中明确声明的字段。

### 5.2 图标

删除所有受 Git 跟踪的：

- `resources/recipe_icons/*_stable.png`
- `resources/recipe_icons/*_stable.png.import`

当前统计为 132 张稳定款 PNG 和 132 个对应导入文件，共 264 个文件。试作品、人气款和招牌款图标保留。

运行时图标解析只接受三档编号，不保留稳定款回退分支。

### 5.3 文档

历史设计规格和实施计划保留，作为演进记录，不改写其历史结论。

仍可能被用于继续生成成长图标的提示词批次文档，应在开头明确标记稳定款已废弃，并将当前有效交付范围改为人气款和招牌款，避免继续生产稳定款素材。

## 6. 界面与玩家反馈

以下玩家可见位置统一显示三档语义：

- 配方成长详情面板的当前阶段、阶段轨道、下一阶段与完成提示；
- 设备成长抽屉的培养上限与等待配方统计；
- 配方卡片、产出、橱窗和自动化报告中的成长阶段；
- 晋级通知、设备等待通知与设备升级摘要；
- 橱窗规则说明中的配方成长路线；
- 与四阶段或稳定款相关的场景默认文案。

成长详情轨道固定为：

`试作品 → 人气款 → 招牌款`

完成提示改为“三阶段成长已完成”。

工作区中 `scenes/ui/overlays/recipe_growth_detail_panel.tscn` 已存在未提交的红色按钮主题改动。本次必须保留该改动，只修改三档成长所需的结构或默认文案，不覆盖其他现有工作。

## 7. 存档策略

本次明确不兼容旧四档存档：

- 不编写 `稳定款 -> 试作品/人气款` 的迁移规则；

## 8. 实施边界

本次只删除稳定款并同步三档成长契约，不调整：

- 人气款、招牌款和名作的既有数值加成；
- 设备升级所需使用次数与金币；
- 橱窗相邻、套装、冲突和区域规则；
- 配方目录、研究解锁和生产配方；
- 非成长语义中的“稳定”普通中文描述。

搜索和清理必须基于稳定款阶段常量、档位文案、`growth_variants.stable` 与 `_stable.png` 文件名，不能误删 Godot 可执行文件名、测试描述中的英文普通词或其他非成长含义。

## 9. 验证标准

至少覆盖以下验证：

1. 新配方默认是试作品，合法档位只有 `0..2`。
2. 试作品必须满足 `30 批次 + 10 有效营业 + 3 协同营业 + 设备 L3` 才能成为人气款。
3. 人气款必须满足 `40 + 14 + 8 + 设备 L5` 才能成为招牌款。
4. L1/L2、L3/L4、L5 的配方上限分别为试作品、人气款、招牌款。
5. 每次事件最多晋升一档，晋级后阶段计数清零且生涯统计保留。
6. 人气款和招牌款分别触发第一次、第二次特性选择；完成两次选择后名作正常开启。
7. 所有当前界面轨道、通知和规则文案不再出现稳定款或四阶段表述。
8. 展示配置及生成器不再生成 `stable` 键，Python 配置测试通过。
9. Git 跟踪文件中不再存在 `*_stable.png` 或其 `.import` 文件。
10. 聚焦成长、设备、界面与名作自检通过。
11. Godot 项目能够无解析错误启动或退出。
12. `git diff --check` 通过，且不覆盖工作区既有的无关改动。

Godot 无头测试必须从项目根目录运行，并为每次命令传入写入工作区或临时目录的显式 `--log-file`，避免沙箱访问默认 `user://logs` 时崩溃。
