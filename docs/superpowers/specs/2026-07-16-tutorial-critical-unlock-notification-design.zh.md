# 新手教学关键解锁提示设计

## 背景

任务系统已经将 Lv.0 教学收敛为三张带子目标的任务卡。当前“完成第一份商品”中的“采集教学材料”子目标只匹配大米，因此收获大米后就会立即解锁蒸煮一体的圆锅。这个时机早于玩家收获泉水，玩家尚未备齐首轮研发需要的两种自产基础材料，设备解锁与下一步行动之间缺少清晰因果。

本次调整只补回完成下一步所必需的关键反馈，不恢复被合并的独立教学任务，也不增加普通进度弹窗。

## 目标

- 关键教学子目标首次解锁设备、功能或页面入口时，立即给出明确提示。
- 圆锅只在玩家真实收获过大米和泉水后解锁，两种材料的收获顺序不限。
- 提示同时说明“解锁了什么”和“下一步去哪里做什么”。
- 重复事件、重复应用进度或重复读取状态不会再次弹出同一提示。
- 普通计数、金币、口碑和非关键进度继续保持安静。

## 方案

采用子目标配置驱动的复合收获条件与可选通知，而不是检查当前库存，也不在 `GameState.unlock_device()` 中为所有设备统一弹窗。

“采集教学材料”声明 `item_ids: ["rice", "spring_water"]`，目标值为 `2`。任务服务按物品 ID 去重记录真实 `harvest` 事件；同一种材料重复收获只计一次。只有两个 ID 都已匹配，子目标才完成并应用圆锅解锁效果。

教学子目标可声明一个可选的 `notification` 字典：

```json
{
  "title": "新设备已解锁：蒸煮一体的圆锅",
  "body": "大米和泉水已经备齐。前往“研发制作”，使用圆锅尝试研发第一款商品。"
}
```

任务目录校验器只接受包含非空 `title` 和 `body` 的通知配置。没有该字段的子目标保持现有行为。

## 运行流程

1. 玩家收获大米或泉水，任务服务把对应物品 ID 记入该子目标的去重进度。
2. 只匹配一个所需物品时，子目标显示 `1/2`，不解锁圆锅，也不生成通知。
3. 玩家以任意顺序收获另一个所需物品，子目标首次达到 `2/2`。
4. 任务服务应用 `unlock_devices: ["round_pot"]` 即时效果。
5. 仅当即时效果确实让圆锅从未解锁变为已解锁时，加入配置的教学通知。
6. 现有收获交互在操作结束时调用通知展示入口，因此弹窗立即显示。
7. 玩家关闭弹窗后，任务仍停留在“制作 1 份商品”子目标；“前往”继续跳转到研发制作页面。

## 首个提示文案

- 标题：`新设备已解锁：蒸煮一体的圆锅`
- 正文：`大米和泉水已经备齐。前往“研发制作”，使用圆锅尝试研发第一款商品。`

## 幂等与边界

- 通知只在子目标由未完成变为完成的那次事件中生成。
- 大米与泉水可按任意顺序收获，同一物品重复收获不推进第二格进度。
- 判定依据是真实收获事件，而不是当前库存数量；之后的消耗不会倒退进度。
- 若圆锅在事件发生前已经解锁，则不生成“新设备已解锁”提示。
- 重复采集不会重复应用即时效果，也不会重复生成通知。
- 白糖不纳入圆锅解锁门槛；玩家研发米浆饮时若缺少白糖，继续使用现有研发失败提示引导采购。
- 整张教学卡完成时仍使用现有任务完成通知；两类通知表达不同节点，不互相替代。
- 本项目仍处于开发阶段，不增加旧存档或旧任务进度迁移。

## 验证

- 目录校验接受合法通知并拒绝缺标题或正文的配置。
- 只收获大米或只收获泉水时，圆锅保持未解锁且没有通知。
- 大米与泉水以任意顺序全部收获后，圆锅立即解锁，通知队列新增且文案正确。
- 重复收获同一种材料不会把复合目标错误推进到 `2/2`。
- 重复采集不增加通知数量。
- 圆锅预先解锁时，完成采集子目标不产生虚假的“新设备”通知。
- 完成后运行任务目标、Lv.0 路线、任务面板与 MVP 聚焦回归。
