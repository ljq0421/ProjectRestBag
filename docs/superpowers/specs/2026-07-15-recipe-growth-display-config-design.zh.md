# 166 个配方进阶展示配置设计

## 背景与目标

`doc/recipe_display_config.json` 当前包含 166 个基础配方，现有顶层几何字段描述试作品图标。需要为每个配方补充稳定款、人气款、招牌款三档展示配置，同时保持现有代码和审计工具对顶层配方字段的兼容。

本次只扩充展示配置，不修改配方成长阈值、图标资源、运行时选图逻辑或存档结构。

## 数据结构

每个配方现有顶层字段继续作为试作品配置，不迁移、不重命名。新增 `growth_variants`，包含三个英文阶段键。各阶段只保存相对试作品发生变化的字段；解析时先复制试作品配置，再用阶段配置进行浅层覆盖：

```json
{
  "recipe_name": "米浆饮",
  "cell_count": 2,
  "shape_category": "竖杯款",
  "default_shape": "2x1",
  "rotatable": true,
  "remark": "",
  "growth_variants": {
    "stable": {},
    "popular": {},
    "signature": {}
  }
}
```

例如试作品为 `2x2`、招牌款升级为 `2x3` 时，只写发生变化的字段：

```json
"signature": {
  "cell_count": 6,
  "shape_category": "大块款",
  "default_shape": "2x3"
}
```

父级 `recipe_name` 和 `remark` 不在各阶段中重复，避免文案漂移。`shape_cells` 遵循特殊的清除语义：

- 进阶款沿用试作品异形时省略 `shape_cells`。
- 进阶款使用另一种异形时写入新的 `shape_cells`。
- 试作品是异形、进阶款改为完整矩形时，必须写 `"shape_cells": []`，表示清除试作品占格，而不是继续继承。

### 形状分类

`shape_category` 只描述图标的几何尺度或主体构图，不描述成长阶段。允许值为：

| 分类 | 几何定位 |
|---|---|
| `迷你款` | 单格小件 |
| `竖杯款` | 纵向杯装、瓶装或窄高主体 |
| `横盘款` | 横向盘装、条状或宽扁主体 |
| `中块款` | 2–4 格的方块、紧凑组合或异形主体 |
| `大块款` | 5–9 格的大份、礼盒、拼盘或宴席型主体 |

`试作品`、`稳定款`、`人气款`、`招牌款` 均不得作为 `shape_category`。当前 `meta.shape_types` 中未被 166 个试作品实际使用的 `招牌款` 应替换为 `大块款`。

## 生成规则

### 试作品

- 保留现有顶层配置，字段和值均不修改。
- 顶层 `shape_cells` 继续作为试作品异形占格的唯一来源。
- 现有 `remark` 原样保留，仍用于记录明确的进阶形态提示。

### 稳定款

- 大小、横竖方向和异形轮廓均与试作品相同。
- 因为没有字段变化，配置固定写为 `"stable": {}`，解析结果复用试作品全部几何字段。

### 人气款

- 与稳定款采用同样的严格继承规则。
- 不因为装饰更丰富而增加占格，也不把异形改成矩形。
- 配置固定写为 `"popular": {}`。

### 招牌款

- 允许修改 `cell_count`、`shape_category`、`default_shape`、`rotatable` 和 `shape_cells`，但不是所有配方都必须放大。
- 只写相对试作品发生变化的字段；没有变化时写 `"signature": {}`。
- 优先服从现有 `remark` 中明确写出的升级形态，例如“可升级为 2x3 大份招牌款”。
- 没有明确备注时，按配方主体判断：杯装、瓶装、单块点心等依赖固定容器或单体轮廓的配方默认保持原形；拼盘、礼盒、组合装、大份主食和宴席型配方可以扩大或改形。
- 形状变化必须仍能从试作品辨认出同一配方，不能只为了填满格子而机械放大。
- 招牌款最大边界为 `3x3`，最多 9 格；可以使用该边界内的完整矩形或异形，异形必须提供无重复、连续的 `shape_cells`。

## 一致性约束

1. 顶层仍恰好有 166 个配方 ID，不新增 `_stable`、`_popular`、`_signature` 顶层伪配方。
2. 每个配方都必须有且只有 `stable`、`popular`、`signature` 三个进阶配置，共 498 份；允许阶段配置是空对象。
3. 阶段解析结果由“试作品浅拷贝 + 阶段字段覆盖”得到；`shape_cells: []` 的解析结果是不含 `shape_cells`。
4. 每个阶段解析后的 `cell_count` 必须等于实际占格数：完整矩形取行数乘列数，异形取 `shape_cells` 数量。
5. `default_shape` 使用 `行x列`；所有非空 `shape_cells` 必须落在该边界内。
6. 稳定款、人气款的解析后几何字段必须与试作品完全一致，且配置对象本身必须为空。
7. 招牌款解析后的行数和列数均不得超过 3，`cell_count` 不得超过 9。
8. 所有解析后的 `shape_category` 必须属于纯形状分类，禁止使用四个成长阶段名称。
9. 试作品的所有原字段、原值和配方顺序保持不变。
10. JSON 使用 UTF-8、两空格缩进，并保留中文内容。

## 验证方式

- 解析 JSON，确认 `meta.total_recipes == 166` 且实际配方数为 166。
- 检查 166 个 `growth_variants` 均齐全，阶段总数为 498。
- 逐配方检查稳定款、人气款均为空对象，并比较解析结果与试作品几何签名。
- 按覆盖与清除语义解析每个招牌款，再校验所有矩形、异形的边界、重复格、连续性和 `cell_count`。
- 检查各阶段没有写入与试作品相同的冗余字段。
- 检查所有 `shape_category` 均属于 `meta.shape_types`，且该列表不包含成长阶段名称。
- 检查所有招牌款均处于 3×3、9 格上限内。
- 确认修改前后试作品字段值及配方顺序完全一致。
- 运行仓库现有配方数据审计与配方图标提示词测试，确保新增嵌套字段不破坏既有读取流程。

## 非目标

- 不生成或修改 PNG 图标。
- 不修改 `scripts/catalog.gd` 的配方、标签或名称。
- 不接入成长阶段对应的运行时图标切换。
- 不改变成长数值、售卖加成或招牌配方选择规则。
