# 配方标签统一设计

## 目标

把当前分散在配方目录、展示配置、陈列规则、顾客偏好、任务与成长系统中的标签收敛为一套受控词表，消除同义标签、无消费者标签和重复数据源。

统一后，配方标签必须具有明确的玩法含义。纯粹用于描述口感或文案气氛、但不参与任何玩法判断的词，移入配方描述或展示备注，不再占用 `tags` 字段。

本次设计覆盖149个成品配方的标签迁移、展示规则引用、顾客偏好条件、稽核工具和聚焦验证。它不新增陈列规则类型，不重新设计顾客系统，也不改变配方材料、价格、产量、解锁等级或展示形状。

## 当前问题

配方目录与 `recipe_display_config.json` 各自保存一份标签，造成同一语义重复维护。现有数据包含约59种标签，而陈列规则只识别其中少量标签；`清甜`、`香甜`、`甜`以及`酥脆`、`焦脆`、`香脆`等同义词并存。

当前稽核只把 `display_rules_full.json` 视为标签消费者，因此会把顾客偏好已经使用的`招牌`误判为孤岛。另一方面，顾客的`低价`和`稀有`又被放入 `preference_tags`，但它们并不都是配方标签：`低价`实际由价格判断，`稀有`当前没有对应的配方字段或有效匹配路径。

规则数据也存在双份来源：`doc/display_rules_full.json`与`scripts/catalog.gd`内置的`DISPLAY_RULES`同时存在，加载失败时回退到内置副本。这种回退会隐藏配置缺失，并允许两份规则发生漂移。

此外，当前 `tools/audit_recipe_data.py` 导入了本检出中不存在的 `tools/generate_recipe_icon_prompts.py`，导致稽核脚本不能独立运行。标签统一后的质量门禁必须是自包含的，不能依赖图标提示词生成工具。

## 标签迁移规则

每个普通配方最终配置1至2个标准标签。只有确实属于特色商品的配方可以增加第3个`招牌`标签。迁移结果直接写入配方目录，运行时不保留旧标签别名层。

可确定的同义词按固定规则迁移：

| 旧标签 | 标准标签 |
| --- | --- |
| `清甜`、`香甜` | `甜` |
| `咸鲜` | `咸香` |
| `酥脆`、`焦脆` | `香脆` |
| `粉糯`、`Q弹` | `软糯` |
| `醇厚`、`浓醇`、`香浓` | `浓郁` |
| `清新`、`清润`、`清冽`、`解腻`、`清淡` | `清爽` |
| `微苦` | `苦甜` |
| `养生` | `低负担` |
| `暖胃`、`扎实`、`管饱` | `饱腹` |

组合词或依赖原料语义的标签不能机械地全局替换，必须按配方明确落表：

- `咸甜`通常拆成`咸香 + 甜`；如果配方实际没有明显甜味，则只保留`咸香`。
- `酸甜`的水果配方优先映射为`果香 + 清爽`，非水果配方根据实际风味映射为`甜 + 清爽`。
- `香气`、`复合香`根据主材料映射为`果香`、`茶香`、`奶香`或`浓郁`。
- `回甘`在茶类配方中映射为`茶香`，在咖啡或可可类配方中映射为`苦甜`。
- `米香`根据产品形态映射为`经典`或`软糯`；`栗香`映射为`浓郁`。
- `丝滑`、`嫩滑`、`绵密`、`流心`、`拉丝`、`湿润`、`滋润`、`润喉`等没有独立机制含义的词移入配方描述或展示 `remark`，不强行映射成不准确的玩法标签。

迁移必须形成149个配方的显式最终结果。材料或名称推断只能帮助生成候选，不允许在运行时动态推导标签。

## 文件职责与数据流

### `doc/recipe_tag_taxonomy.json`

新增受控词表，记录标签 ID、类别、中文说明和允许的消费者类别。稽核工具通过该文件判断合法标签和真正的标签孤岛。

### `scripts/catalog.gd`

保留配方最终标签分配。顾客的 `preference_tags` 只能引用标准标签；`低价`改为明确的价格偏好字段或条件，`稀有`在正式稀有度字段存在前移除。

移除旧标签兼容判断，例如甜点筛选不再同时判断`甜/清甜/香甜`，饱腹冲突不再兼容`管饱`。

### `doc/recipe_display_config.json`

删除每个配方重复保存的 `tags`。该文件继续只负责配方图标形状、占格数量、旋转、变体和展示备注。

### `doc/display_rules_full.json`

所有规则只能引用标准词表。`香浓`统一改为`浓郁`。基础相邻规则增加显式优先级；同一相邻配方对如果符合多条基础规则，只应用优先级最高的一条。

### 规则加载

`doc/display_rules_full.json`作为陈列规则唯一来源，移除 `scripts/catalog.gd`中的完整内置副本。JSON 缺失或格式错误时，加载层输出明确错误并返回结构完整但无加成的安全空规则，使存档和主循环可以继续运行，同时让测试与稽核失败。

数据流如下：

```text
recipe_tag_taxonomy.json
          ↓ 合法性校验
catalog.gd 的配方标签
          ↓
陈列规则 / 顾客偏好 / 任务 / 配方成长
```

## 加成与平衡控制

标签统一会让原本无效果的`清甜`、`酥脆`、`醇厚`等语义进入玩法，因此这是受控的平衡调整，不是纯文本替换。

为避免命中率上升造成加成膨胀：

- 普通配方最多两个机制标签，`招牌`只能作为可选第3标签。
- 每一对相邻配方最多触发一条基础标签加成。
- 多条基础规则同时命中时按显式优先级选择；优先级相同则按稳定规则 ID 排序，保证结果可复现。
- 套装加成与基础相邻加成可以同时存在，现有冲突减损继续独立计算。
- 迁移前后生成全部配方两两组合的规则命中矩阵，记录命中配方对数量、各规则覆盖量和单对最高加成。
- 若某条规则覆盖量明显集中，优先调整配方标签分配或规则数值，不通过恢复同义词来稀释覆盖率。

## 稽核规则

`tools/audit_recipe_data.py`改为自包含解析，不再导入图标提示词生成器。出现以下任意问题时返回非零退出码：

- 配方使用词表之外的标签；
- 配方没有标签，不含`招牌`的配方超过两个标签，或含`招牌`的配方超过三个标签；
- `recipe_display_config.json`仍保存配方标签；
- 展示规则、顾客偏好、任务或成长系统引用非法标签；
- 某个标准标签没有被任何声明的玩法系统消费；
- 旧同义词重新进入运行时代码或数据；
- 同一相邻配方对能够应用多条基础规则；
- 配方目录、展示形状、材料或设备引用存在原有阻断问题。

报告继续写入 `doc/recipe_data_audit.md`，并新增标准标签覆盖、消费者覆盖、旧词残留和规则命中矩阵摘要。成功状态下“标签孤岛”必须为零。

## 错误处理

- 词表或规则 JSON 解析失败：输出包含文件路径和失败原因的错误；运行时使用无加成安全结构，测试失败。
- 配方包含非法标签：开发期稽核直接失败，不在运行时静默归一化。
- 迁移后配方标签不足或超限：稽核列出配方 ID 和当前标签，不自动猜测修复。
- 多规则优先级相同：以稳定规则 ID 决胜，并在稽核报告中列为需要策划确认的警告。
- 顾客偏好引用非标准标签：稽核失败；价格、稀有度等非标签条件必须使用独立字段表达。

## 验证方案

新增聚焦测试并保留现有广泛自检：

1. Python 单元测试验证词表结构、旧词映射、消费者覆盖和稽核退出码。
2. 全量数据测试验证149个配方均只使用标准标签，并满足数量约束。
3. 展示配置测试验证配方数与目录一致，且不再包含重复 `tags`。
4. 规则引用测试验证基础规则、七套套装和三类冲突规则只引用标准标签。
5. 两两组合测试遍历全部配方对，验证每对最多应用一条基础规则，并输出规则覆盖统计。
6. 聚焦 Godot 自检验证基础相邻加成优先级、套装触发、冲突减损、顾客偏好、任务标签条件和配方成长。
7. 重新运行 `mvp_self_check.gd`，确认配方合同和核心流程没有回归。
8. 重新生成 `doc/recipe_data_audit.md`，确认阻断项、旧词残留和标签孤岛均为零。

所有 Godot headless 命令必须从包含 `project.godot` 的目录运行，并通过 `--log-file` 指向可写临时路径。

## 实施顺序

1. 建立标准词表及其测试。
2. 让稽核脚本自包含，并补齐新失败条件。
3. 生成149个配方的候选迁移表，逐项确认含义不稳定的标签。
4. 更新 `catalog.gd`中的配方标签和顾客条件。
5. 删除展示配置中的重复标签。
6. 更新展示规则词汇、优先级和单对单规则选择逻辑。
7. 清理各运行时系统中的旧词兼容和伪标签。
8. 运行全量数据、规则矩阵和 Godot 自检。
9. 重新生成数据稽核报告。

## 非目标

- 不新增第16个以上的标准标签。
- 不为每个口感形容词新增独立加成规则。
- 不在运行时保留旧标签别名或自动修复非法数据。
- 不调整配方材料、价格、产量、解锁等级或展示形状。
- 不在本次工作中设计新的稀有度系统。
- 不改造与标签统一无关的页面布局或视觉表现。

## 完成标准

- 149个配方全部完成显式标签迁移。
- 运行时、规则、顾客、任务和成长系统只引用15个标准标签。
- 展示配置不再重复保存配方标签。
- 陈列规则只有一个数据来源。
- 任意相邻配方对最多应用一条基础规则。
- 稽核脚本可独立运行并返回正确退出码。
- `doc/recipe_data_audit.md`中的标签孤岛、旧词残留和阻断项均为零。
- 聚焦测试与 `mvp_self_check.gd`通过。
