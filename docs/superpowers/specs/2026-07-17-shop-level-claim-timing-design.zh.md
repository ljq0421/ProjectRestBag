# 店铺等级领取时机修复设计

## 背景与目标

Lv.0 教学任务 `tutorial_l0_first_business` 的奖励同时包含 `set_level: 1` 和金币。当前任务系统在任务达成时立即应用 `set_level`，但金币要等玩家点击“领取奖励”后才发放。因此任务仍处于待领取状态时，页面顶部已经显示“店铺等级: 1”。

本次修复统一这段交互语义：店铺等级属于该任务的可领取奖励，必须和金币在同一次领取操作中生效。任务达成但未领取时，玩家仍是 Lv.0；领取成功后才进入 Lv.1。

## 状态契约

1. 新游戏开始时，`state.level == 0`。
2. 完成 `tutorial_l0_first_business` 的全部目标后：
   - 任务进入已完成、可领取状态；
   - `state.level` 仍为 `0`；
   - 顶部继续显示“店铺等级: 0”；
   - Lv.1 内容不应因任务达成而提前开放。
3. 玩家领取 `tutorial_l0_first_business` 奖励后：
   - 金币奖励与 `set_level: 1` 在同一次领取中应用；
   - `state.level == 1`；
   - 顶部资源栏刷新为“店铺等级: 1”；
   - 后续 Lv.1 成长任务按既有规则开放。
4. 奖励不可重复领取，重复调用不得再次改变等级或发放金币。

## 实现边界

- 保留 `game_data.json` 中现有任务奖励结构，不引入第二套“显示等级”或“已领取等级”。
- `TaskService._complete_task()` 仍负责记录任务完成，并继续立即应用既有的教学解锁效果。
- `set_level` 不再属于完成阶段的即时进度效果，改由领取阶段与金币、口碑、道具等奖励一起应用。
- 其他任务完成时立即解锁设备、工具、自动化或功能的现有语义不变。
- 页面顶部继续读取唯一来源 `state.level`，无需增加 UI 特判。
- 不增加存档迁移：项目仍在开发阶段，本次只修正新产生状态的行为。

## 测试设计

在现有任务主线或任务可见性自检中增加一条聚焦回归路径：

1. 创建 Lv.0 新游戏状态。
2. 触发前三个教学任务所需事件，完成 `tutorial_l0_first_business`。
3. 断言该任务可领取，同时等级仍为 0。
4. 调用 `claim_task_reward("tutorial_l0_first_business")`。
5. 断言等级变为 1，金币只增加一次，任务被标记为已领取。
6. 再次领取应失败，等级与金币保持不变。

验证顺序为：先运行新增断言并确认它在现有实现上因“未领取时等级已为 1”而失败；完成最小代码修改后再次运行该聚焦自检，再执行 Godot `--headless --quit` 做解析与加载校验。所有无头命令必须按仓库规范传入可写的 `--log-file`。

## 非目标

- 不改变 Lv.1 以后使用金币和累计口碑主动升级的流程。
- 不改变普通任务、每日任务和功能任务的领取规则。
- 不重构顶部资源栏或新增等级缓存。
- 不处理已经保存为 Lv.1、但旧版本中尚未领取该任务奖励的历史存档。
