# 采购页交互性能修复设计

日期：2026-07-25  
目标项目：`project-rest-new`

## 背景与已确认问题

当前采购页同时展示 6 个采购分区、36 行商品。一次 `+/-` 操作会刷新全部商品行；每行在判断是否还能增加数量时，又会重新遍历整辆购物车。热路径中的 `Catalog.get_ingredients()` 和 `Catalog.get_tools()` 返回深拷贝，因此一次点击会重复创建大量目录副本。

当前运行时基线：

- 点击一次 `+`：约 235 ms。
- 刷新全部商品行：约 234 ms。
- 重建全部采购分区：约 271 ms。
- 刷新整个采购页：约 287 ms。
- 小票控件自身生成并显示：约 1.3 ms。

购买流程还会在显示小票前重建一次采购分区，并在购买处理函数返回后再次刷新整个采购页。虽然小票已经调用 `show()`，但要等当前主线程事件结束后才能绘制，因此玩家会感受到约半秒的购买和弹票延迟。

## 目标

- 将一次 `+/-` 的同步处理耗时降至不超过 16 ms，争取达到个位数毫秒。
- 购买成功后立即显示小票，不在小票首次绘制前全量重建采购页。
- 小票关闭后只重建一次采购页，使库存、数量和按钮状态与购买结果一致。
- 保持跨分区重复商品数量同步、金币预算限制、购买持久化、教程进度和通知恢复行为。

## 非目标

- 不重构整个 `main_view.gd`。
- 不把采购系统迁移为新的独立服务。
- 不改变目录公开 API 的深拷贝语义，避免影响其他调用方。
- 不改变采购页面布局、小票视觉和小票拖拽/关闭输入行为。

## 设计

### 1. 单次刷新快照

采购刷新入口创建一个只在本次同步调用中使用的快照，至少包含：

- 一份原料目录深拷贝。
- 一份工具目录深拷贝。
- 当前购物车总件数。
- 当前购物车总价。

商品可用性、单价、名称和分区判断优先使用传入的目录快照，不在循环内重复调用目录 getter。购物车总价在一次刷新中只计算一次。

### 2. `+/-` 更新路径

数量变化后：

1. 更新 `purchase_cart_quantities` 中的目标商品数量。
2. 创建一次采购快照。
3. 遍历现有商品行，同步库存、数量和 `+/-` 禁用状态。
4. 使用同一快照更新购物车摘要和购买按钮状态。
5. 保持教程提示的延后刷新。

跨分区出现同一商品时，两行仍从同一购物车数量读取，因此继续同步更新。

### 3. 购买与小票时序

购买成功后：

1. 完成库存、金币、日志和教程状态变更。
2. 清空已购买条目的购物车数量。
3. 立即更新购物车摘要为 0，并设置“采购页待刷新”标记。
4. 显示小票。
5. 保存游戏并刷新顶部资源栏。
6. 不在当前按钮事件中再次调用 `_refresh_purchase_page()`。

小票关闭时：

1. 若存在“采购页待刷新”标记且当前仍处于采购弹层，则全量刷新采购页一次。
2. 清除待刷新标记。
3. 按现有规则恢复被小票暂停的任务通知，或继续展示下一条通知。

如果购买失败，不设置待刷新标记，也不显示小票；界面只执行维持一致性所需的轻量状态刷新。

### 4. 生命周期兜底

如果小票显示期间采购弹层被其他路径关闭，待刷新标记仍应清除；下次进入采购页时原有 `_refresh_purchase_page()` 会根据真实游戏状态重建页面。不得因为延后刷新而保留跨页面的陈旧标记。

## 测试与验收

### 自动化回归

扩展 `tests/purchase_cart_self_check.gd`，验证：

- `+/-` 后跨分区重复商品数量继续同步。
- 达到金币预算后所有相关 `+` 按钮正确禁用。
- 购买成功后购物车摘要立即归零，小票立即可见。
- 小票显示期间采购行允许保持购买前的可见库存，关闭小票后库存和数量刷新为购买后状态。
- 小票关闭后原有通知恢复行为不变。
- 背景点击关闭小票不会触发底层控件。

### 运行时计时

在真实运行场景中复测：

- `_on_purchase_cart_quantity_pressed()`。
- `_refresh_purchase_region_item_states()`。
- `_refresh_purchase_page()`。
- `PurchaseReceiptDialog.show_receipt()`。

验收标准：

- `+/-` 单次处理不超过 16 ms。
- 小票显示前不再发生采购分区全量重建。
- 关闭小票后采购页只发生一次全量刷新。
- `purchase_cart_self_check.gd` 通过。
- 相关脚本无解析错误，`git diff --check` 通过。

## 风险与控制

- 快照中的目录数据只在单次同步调用内使用，不缓存到长期状态，避免目录或解锁状态变化后数据陈旧。
- 不直接返回或修改 `Catalog` 常量字典，保持现有防御性复制边界。
- 延后刷新只适用于成功购买且小票可见的路径；失败路径和重新打开采购页仍从真实状态刷新。
