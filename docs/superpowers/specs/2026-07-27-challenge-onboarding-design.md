# 挑战模式新手引导设计规格

日期：2026-07-27
项目：`project-rest-two`
目标分支：`feature/challenge-onboarding`

## 1. 背景

当前 Stage 1 已具备完整的单 Boss 纵切：

```text
阅读 Boss
-> 选择独立挑战备货
-> 摆放与旋转
-> 阅读覆盖风险
-> 全自动战斗
-> 阅读战报
-> 失败后重排重试
```

现有界面通过按钮文案、tooltip、风险摘要和战报解释规则，但没有持久化的新手引导状态，也没有将玩家注意力依次引向 Boss 时间轴、可旋转配方、双向压力条和失败缺口。

本功能为新挑战核心增加首局引导。引导教会真实操作，但不提供必胜摆法，不保证首战胜利，也不创造教学专用 Boss。

## 2. 已确认的产品决策

- 首战允许失败；失败和重排本身属于教学内容。
- 正常情况下，引导覆盖首次战报，并在失败时覆盖一次真实返回重排。
- 首战胜利时，阅读并关闭战报后即可完成引导，不为了教学改变胜利结束流程。
- 首战失败且仍可重试时，必须返回战前并完成一次真实有效的布局变化后完成。
- 首战失败但已经没有信心时，阅读并关闭战报后完成，不能产生无法满足的重排步骤。
- 玩家可以随时关闭整个引导。
- 顶栏长期保留 `？` 引导入口。
- 缺少引导字段的既有 `project-rest-two` 存档自动进入一次引导。
- 引导使用聚光目标、箭头和贴近目标的小提示卡。
- 首次自动引导由真实成功事件推进；完成后的重播模式允许使用“下一步”浏览。
- 引导不赠送资源、不修改布局、不补充信心、不模拟结算，也不解锁内容。

## 3. 目标

引导完成后，玩家应理解：

1. Boss 在 8、16、24、30 秒分别检查什么；
2. 配方从挑战备货区拖入展示柜；
3. 牛奶布丁和蓝莓松饼可以通过右键旋转；
4. 预算、联动和覆盖风险会随布局实时变化；
5. 开战后完全自动，战前快照会被锁定；
6. 口碑防线和 Boss 挑剔值是两条不同压力；
7. 战报中的窗口缺口和配方贡献可以指导下一次重排；
8. 首战失败不是流程中断，而是分析与重排的入口。

## 4. 非目标

本轮不包含：

- 必胜构筑或固定摆法；
- 教学专用 Boss、特殊数值或强制失败；
- 五场短链、局内强化、局外研究树或无尽模式引导；
- 旧采购、产地、制作、研发或库存流程；
- 对旧 `project-rest-new` 教程状态的复用或迁移；
- 用引导步骤作为功能权限或内容解锁条件；
- 为完成引导而清空、重置或重写玩家当前挑战草稿。

## 5. 体验原则

### 5.1 真实事件推进

首次自动引导只接受业务层已经判定成功的事件。鼠标按下、弹窗可见、按钮收到点击或拖拽开始都不是成功证据。

例如：

- 配方必须真实加入合法草稿；
- 旋转必须由右键触发并真实改变可旋转配方的占格；
- 开战必须成功生成合法战斗快照；
- 结算必须来自真实战斗结果；
- 重排必须使当前合法草稿与首战快照产生实际差异。

### 5.2 不给答案

引导可以指出哪些配方能够旋转、哪里显示关系和风险，但不指定完整配方组合、数量、坐标或关系答案。玩家可以使用任意合法构筑进入首战。

### 5.3 不阻断游戏

视觉遮罩不拦截棋盘、备货卡、开战按钮和战斗控件的输入。只有提示卡自身的按钮接收鼠标。

### 5.4 上下文一致

引导只展示当前界面能够执行或理解的步骤。结算弹窗打开时暂停主界面提示，战斗开始后不再提示战前操作。

## 6. 首次自动引导状态机

### 6.1 步骤表

| 步骤 ID | 玩家看到的重点 | 首次自动引导的推进条件 |
|---|---|---|
| `boss_brief` | Boss 名称、三段需求和 30 秒终点 | 点击提示卡“开始备货” |
| `place_recipe` | 备货卡与展示柜 | 任意配方成功加入合法草稿 |
| `rotate_recipe` | 可旋转配方或其实际占格 | 牛奶布丁或蓝莓松饼被右键成功旋转 |
| `read_risk` | 预算、风险和联动摘要 | 当前草稿合法，玩家点击“看懂风险了” |
| `start_battle` | 开战按钮 | `start_battle()` 成功生成快照并切入战斗 |
| `observe_battle` | 双向压力条和需求时间轴 | 提示展示至少一次；状态等待真实结算 |
| `read_report` | 需求窗口、贡献、主要缺口和建议 | 玩家执行结算弹窗中的有效离开操作 |
| `rearrange` | 返回后的展示柜 | 当前合法草稿指纹不同于首战快照 |
| `complete` | 完成说明与 `？` 重播入口 | 玩家点击“完成引导” |

`boss_brief`、`read_risk` 和 `complete` 是解释性确认。其余业务步骤不能通过提示卡中的“下一步”越过。

### 6.2 旋转目标解析

进入 `rotate_recipe` 后按以下顺序解析目标：

1. 如果草稿中已有牛奶布丁或蓝莓松饼，聚光该实例的实际占格；
2. 如果两个都存在，优先聚光最早成功放入的实例；
3. 如果都不存在，同时聚光两张可旋转备货卡并提示先放入其中一个；
4. 单格黄油曲奇、草莓果冻以及旋转后外形不变的方形蛋糕不能满足该步骤。

旋转教学会要求玩家至少使用一个可旋转配方，但不规定该配方的最终位置，也不要求保留到开战。

### 6.3 胜负分支

#### 首战胜利

```text
observe_battle
-> read_report
-> complete
```

胜利后不创建额外练习轮，不返回已经完成的挑战。

#### 首战失败且信心大于 0

```text
observe_battle
-> read_report
-> rearrange
-> complete
```

玩家必须通过现有“调整备货，再战同一 Boss”返回战前。引导不自动点击该按钮。

#### 首战失败且信心等于 0

```text
observe_battle
-> read_report
-> complete
```

该分支主要覆盖升级前已剩 1 点信心的既有存档，避免引导等待不可能发生的重排。

## 7. 重排判定

开战成功时保存一份规范化草稿指纹。指纹只包含影响构筑的字段：

```text
instance_id
recipe_id
origin
rotation mod 360
```

生成指纹前按 `instance_id` 稳定排序。以下任一合法变化均可完成重排：

- 移动已有实例；
- 旋转可旋转实例；
- 新增配方；
- 移除配方。

以下情况不算：

- 原地释放；
- 旋转不可旋转配方；
- 因越界、重叠、预算或复制上限被拒绝的候选；
- 仅改变临时选中态、hover、拖拽预览或提示文本；
- 指纹变化后又恢复为开战时的原始指纹。

## 8. 显示设计

### 8.1 视觉方向

采用已确认的“聚光箭头”方案：

- 非目标区域使用夜莓色半透明压暗；
- 当前目标使用奶油金描边与柔和外发光；
- 箭头使用奶油金；
- 提示卡使用浅奶油底、深莓色正文和覆盆子色步骤标签；
- 视觉语言延续当前“夜莓色甜品展示柜”主题。

提示卡包含：

- 步骤编号，例如 `2 / 9`；
- 一句主操作提示；
- 最多一句机制解释；
- “关闭引导”；
- 仅解释性步骤出现确认按钮。

### 8.2 输入层级

稳定视觉结构放在场景文件中：

```text
ChallengeMain
  TutorialCanvasLayer
    TutorialVisualOverlay
    TutorialHintHost
      TutorialHintPanel
```

- `TutorialVisualOverlay` 使用 `mouse_filter = IGNORE`，只负责绘制遮罩、目标描边和箭头；
- `TutorialHintPanel` 是独立交互节点，只接收自身按钮；
- 不使用覆盖整个视口的透明 Button；
- 主界面真实控件继续接收拖放、右键和点击；
- 引导节点不动态拼装在 `challenge_main_view.gd` 中。

### 8.3 结算弹窗

`PopupPanel` 拥有独立的稳定引导承载节点：

```text
ChallengeSettlementDialog
  TutorialReportOverlay
```

主界面引导层在结算弹窗可见时暂停。`TutorialReportOverlay` 使用相同视觉组件和同一进度状态，但目标坐标只在结算弹窗内部解析。

失败战报优先聚光：

1. `PrimaryFailure`；
2. `SuggestionList`；
3. 可重试按钮。

胜利战报优先聚光：

1. `WindowRows`；
2. `ContributionRows`；
3. 离开按钮。

### 8.4 动态目标

目标通过语义接口解析，不把动态棋盘格的内部节点路径写进进度服务：

- `ChallengeBoard.get_tutorial_target_rect(kind, instance_id)`；
- `ChallengeMainView.resolve_tutorial_target(step_id)`；
- `ChallengeSettlementDialog.resolve_tutorial_target(step_id, outcome)`。

一个步骤可以返回多个 `Rect2`，用于同时强调备货卡与棋盘、双条与时间轴、预算与风险摘要。

## 9. 关闭、继续与重播

### 9.1 关闭

任意首次引导步骤都可点击“关闭引导”：

- 保存 `status = dismissed`；
- 保留 `step_id` 和已经完成的步骤；
- 立即隐藏覆盖层；
- 后续启动不再自动弹出；
- 不修改任何挑战业务数据。

### 9.2 顶栏入口

`TopBar` 增加纯图标 `？` 按钮：

- tooltip 为“新手引导”；
- 不与保存状态文案争夺空间；
- 战前、战斗和结算时均可访问；
- 若结算弹窗拥有输入焦点，入口在弹窗内提供等价按钮或由弹窗转发请求。

### 9.3 未完成时继续

`active` 或 `dismissed` 状态点击 `？`：

- 将状态恢复为 `active`；
- 从保存步骤继续；
- 仍按真实成功事件推进；
- 如果保存步骤与当前界面不兼容，选择当前界面可执行的最早合法步骤，不伪造此前业务事件。

### 9.4 完成后重播

`completed` 状态点击 `？` 进入仅限当前会话的 `replay_mode`：

- 从 `boss_brief` 开始；
- 每一步都允许“下一步”；
- 不清除永久完成记录；
- 不修改草稿、战斗、信心或结算；
- 退出游戏会结束本次重播，下次启动仍保持 `completed`；
- 当前界面不可展示的步骤显示说明文字，不强制切换或重置游戏状态。

## 10. 存档模型

在 `project_rest_two_save_v1.json` 顶层新增：

```json
{
  "onboarding": {
    "version": 1,
    "status": "active",
    "step_id": "boss_brief",
    "completed_step_ids": [],
    "pre_battle_draft_fingerprint": ""
  }
}
```

### 10.1 字段约束

- `version`：当前引导协议版本；
- `status`：仅允许 `active`、`dismissed`、`completed`；
- `step_id`：仅允许本规格定义的步骤；
- `completed_step_ids`：去重后的合法步骤 ID；
- `pre_battle_draft_fingerprint`：只有成功开战后写入。

`replay_mode` 不写入永久存档。

### 10.2 缺失字段迁移

缺少 `onboarding` 的存档初始化为 `version = 1`、`status = active`。

- 当前处于战前准备：从 `boss_brief` 开始完整引导；
- 当前处于已恢复战斗：不显示战前步骤，从 `observe_battle` 开始上下文引导；
- 当前正在显示结算：从 `read_report` 开始；
- 当前局已完成且没有可见结算：保持 `active`，点击顶栏 `？` 可从说明模式开始；不重置已完成挑战。

这是既有活动战斗的兼容例外。它保证升级后不强行退回战前或丢失战斗，同时承认该玩家不会被要求重新完成已经越过的操作步骤。

### 10.3 写盘时点

以下事件立即调用现有 `ChallengeSaveService`：

- 初始化缺失引导字段；
- 合法步骤推进；
- 成功开战并保存草稿指纹；
- 关闭引导；
- 从 `？` 恢复未完成引导；
- 首次引导完成。

引导写入继续使用现有原子保存路径，不创建第二份配置文件。

## 11. 组件与职责

### 11.1 `ChallengeTutorialProgress`

纯状态服务，职责：

- 创建、清洗和迁移引导数据；
- 验证合法状态迁移；
- 接收已经成功的语义事件；
- 计算胜负后的下一步骤；
- 管理首次引导和会话级重播的差异；
- 不访问场景树；
- 不修改挑战草稿、运行状态或战斗状态。

### 11.2 `ChallengeTutorialOverlay`

场景与展示脚本，职责：

- 绘制一个或多个聚光区域；
- 跟踪目标矩形和视口变化；
- 计算箭头方向和提示卡安全位置；
- 发出确认、关闭和重播导航信号；
- 目标缺失时显示安全回退；
- 不决定业务步骤是否完成。

### 11.3 `ChallengeBoard`

保留现有校验为唯一成功判据，并在 `_commit_candidate()` 成功后发出语义信号：

- `recipe_placed(instance_id, recipe_id)`；
- `instance_moved(instance_id)`；
- `instance_rotated(instance_id, recipe_id, rotation)`；
- `instance_removed(instance_id)`。

失败候选继续只发 `placement_rejected`，不能推进引导。

### 11.4 `ChallengeMainView`

负责协调：

- 创建进度服务；
- 将成功业务信号转发为教程事件；
- 解析当前页面语义目标；
- 控制主引导层和结算引导层互斥；
- 在步骤变化后刷新展示并写盘；
- 不实现步骤规则内部判断。

### 11.5 `ChallengeSettlementDialog`

新增：

- 战报已读和离开动作的明确语义信号；
- 内部教程目标解析；
- 结算引导层承载节点；
- 不直接写引导存档或修改教程状态。

## 12. 错误与恢复

- 目标节点缺失、隐藏或尺寸为零：隐藏箭头和描边，将提示卡放入视口安全区；步骤不推进。
- 动态目标被场景刷新替换：下一帧重新解析语义目标。
- 引导步骤未知：清洗到当前界面可执行的最早合法步骤，并记录开发期警告。
- `completed_step_ids` 含未知或重复值：过滤并去重。
- 引导版本高于当前客户端：保留挑战业务数据，隐藏自动引导并显示可诊断警告，不能覆盖未知新版数据。
- 引导存档写入失败：显示现有保存失败反馈；当前会话可继续，但不能声称进度已经持久化。
- 结算弹窗关闭或重建：主界面覆盖层只在弹窗完全不可见后恢复。
- 任意引导错误不得阻止开战、暂停、继续、结算或重试。

## 13. 测试设计

### 13.1 状态服务自检

新增 `challenge_tutorial_progress_self_check.gd`，覆盖：

- 空数据和缺失字段初始化；
- 合法步骤顺序；
- 未知字段清洗；
- 关闭与恢复；
- 完成状态；
- 会话重播不覆盖永久完成；
- 胜利、可重试失败、信心耗尽失败三条分支；
- 高版本数据安全回退；
- 序列化往返。

### 13.2 真实事件路由自检

新增 `challenge_tutorial_route_self_check.gd`，覆盖：

- 拖拽开始不推进，合法放置才推进；
- 非法放置不推进；
- 单格或方形不可旋转配方不推进；
- 牛奶布丁或蓝莓松饼真实右键旋转推进；
- 非法开战不推进；
- 成功生成快照后推进；
- 结算弹窗可见不等于战报已读；
- 胜利关闭战报进入完成；
- 可重试失败返回后等待真实草稿变化；
- 原地移动、失败变更和恢复原指纹不完成；
- 信心耗尽失败不会卡在重排。

### 13.3 覆盖层自检

新增 `challenge_tutorial_overlay_self_check.gd`，覆盖：

- 稳定场景节点和主题；
- 视觉层 `mouse_filter = IGNORE`；
- 提示按钮可接收输入；
- 单目标和多目标矩形；
- 箭头方向；
- 提示卡在 1920×1080 安全区内；
- 目标缺失回退；
- 视口变化后重排；
- 主界面与结算覆盖层互斥。

### 13.4 存档与迁移自检

扩展挑战存档测试：

- 新存档默认激活；
- 旧存档缺失字段迁移；
- 活动战斗上下文迁移；
- 关闭和完成即时保存；
- 损坏引导字段不破坏 `meta`、`active_run`、`active_draft` 或 `active_battle`。

### 13.5 真实输入与视觉验收

真实输入路径必须完成：

```text
启动缺失引导字段的存档
-> 确认 Boss 说明
-> 拖入配方
-> 拖入并右键旋转牛奶布丁或蓝莓松饼
-> 阅读风险
-> 开战
-> 观察双条
-> 阅读战报
-> 若失败则返回并重排
-> 完成引导
-> 点击 ? 重播
```

分别截取：

- Boss 说明；
- 拖放目标；
- 旋转目标；
- 战斗双条；
- 失败战报；
- 胜利战报；
- 完成提示。
