# 红色普通操作按钮全局替换设计

## 目标

将 `resources/ui/skin_v1/` 下的五张红色按钮素材接入 `project-rest-new` 的普通文字操作按钮。替换后保留现有按钮节点、文字、尺寸、布局、信号和业务逻辑；不同状态的外轮廓、圆角和边框粗细保持一致，按钮横向变化时不拉伸圆角与边框。

五张素材的状态语义固定为：

- `button_red_normal_v1.png`：正常。
- `button_red_hover_v1.png`：悬停。
- `button_red_pressed_v1.png`：按下过程。
- `button_red_disabled_v1.png`：禁用。
- `button_red_selected_v1.png`：文字选择按钮的持续选中状态。

## 纳入范围

本次替换以下带文字的普通操作按钮：

- 默认文字操作按钮。
- `DessertPrimaryButton`、`DessertSecondaryButton`、`DessertFlatButton` 和 `DessertDangerButton` 等现有文字按钮语义族。
- 单行文字选择按钮，例如任务筛选、主题选择和扩建模式选择。此类按钮使用独立的选择按钮主题，以区分“鼠标按下”和“持续选中”。
- 运行时动态创建、但语义仍属于普通文字操作的按钮；其创建路径需要显式绑定对应的红色文字按钮主题。

替换只改变按钮背景与为可读性所需的文字颜色，不改变按钮尺寸、内容、禁用条件、快捷操作、信号连接或点击结果。

## 明确排除

以下控件保持现状：

- 图鉴与库存顶部的 `TabBar` 分类页签，以及预留的 `DessertTopTabButton`。
- 关闭按钮、数量加减按钮、上一页/下一页按钮及其他方形小按钮。
- 仅显示图标的工作台入口或其他纯图标按钮，包括 `DessertIconButton` 与 `DessertLauncherIconButton`。
- 商品卡片、配方卡片、任务列表条目、库存格、研发材料格、生产格、展示槽等以 `Button` 承载的内容控件。
- 透明弹窗遮罩，以及仅为捕获点击、拖拽或关闭事件而存在的无视觉按钮。
- `OptionButton`、`CheckButton`、开关及其他非普通文字操作按钮控件。

上述小型或纯图标按钮等待后续单独生成的专用素材，不复用本次横向红色按钮图。

## 素材预处理

五张原始 PNG 均保持不动。构建脚本从源文件生成主题使用的运行时副本：

1. 对四张已有透明背景的状态图，按各自可见按钮轮廓裁切，再归一化到同一外框尺寸。
2. `button_red_normal_v1.png` 在部分预览器中会显示白底和右下角水印，但像素审计确认这些内容位于 alpha=0 的完全透明区域，Godot 实际不会绘制。预处理会把完全透明像素的隐藏 RGB 清零，避免外部工具错误显示，同时保留按钮内部的浅色高光。
3. 五态使用同一目标画布、同一轮廓基准和同一缩放比例，避免状态切换时发生跳动或边框忽粗忽细。
4. 生成结果采用 RGBA，透明区不得残留白底、水印或不透明矩形。

预处理规则进入 `tools/build_neighborhood_dessert_skin.py`，运行时输出继续写入 `resources/ui/skin/neighborhood_dessert/runtime/`。运行时文件是构建产物，不手工修图。

## 主题与状态设计

采用 `StyleBoxTexture` 九宫格。左右圆角端帽、上下边框和角部高光位于固定切片区，仅允许中间平坦区域横向伸缩；不得将整张素材按按钮尺寸直接缩放。

主题分为两种行为：

- 普通操作按钮：`normal`、`hover`、`pressed`、`hover_pressed`、`disabled` 分别使用正常、悬停、按下、按下、禁用素材。
- 文字选择按钮：未选中时使用正常与悬停素材，持续选中时将 `pressed` 和 `hover_pressed` 映射到选中素材。这样不会把一次点击过程误显示成持续选中，也不会浪费独立的 `selected` 素材。

现有主要、次要、弱化和危险文字按钮可继续保留语义名称，底层统一引用红色状态样式。默认文字操作按钮使用显式主题变体，不能全局覆盖基础 `Button`，否则会误伤被排除的卡片、格子和透明遮罩。

所有纳入按钮在正常、悬停、按下和选中的红色背景上使用统一浅色文字；禁用素材是浅桃色，因此禁用文字使用深棕色以保持足够对比度。焦点样式复用正常背景或仅增加不会改变外框尺寸的焦点反馈。

## 尺寸与不失真约束

- 保留各场景现有的按钮宽高与最小尺寸，本次不进行全局布局重排。
- 五种状态的运行时纹理尺寸、透明边界和九宫格切片边距必须完全一致。
- 九宫格固定区必须覆盖完整圆角与描边，伸缩区不得包含圆角、高光端点或边框转角。
- 宽按钮只拉伸中部；较窄的文字按钮必须至少容纳左右固定端帽与内容边距。
- 状态切换不得造成按钮外框位移、文字跳动、圆角变化或描边厚度变化。

## 实施边界

优先修改主题生成器与主题资源，再只为未使用语义主题的普通文字操作按钮补充显式主题变体。不得为了消耗素材而新增节点，不得修改脚本业务逻辑，也不得把排除项改成红色按钮。

当前工作树已有其他 UI 改动。实施时只修改与红色文字按钮主题、必要场景绑定和对应自检直接相关的文件；不得覆盖、回退或顺带整理用户的现有修改。

## 验证

- 增加或更新生成器单元测试，验证五态源映射、完全透明像素的隐藏 RGB 清理、RGBA 输出、统一尺寸与统一透明边界。
- 执行 `python -m unittest tests/test_build_neighborhood_dessert_skin.py`。
- 执行 `python tools/build_neighborhood_dessert_skin.py --check`。
- 更新主题自检，确认普通、悬停、按下、选中和禁用映射正确，文字选择按钮单独使用选中素材。
- 静态审计场景与动态创建路径，确认普通文字操作按钮全部纳入，页签、卡片/格子、透明遮罩和方形/纯图标按钮均未被替换。
- 使用带可写 `--log-file` 的 Godot headless 运行相关 UI 自检。
- 对代表性的宽按钮、窄文字按钮和文字选择按钮进行运行时截图或像素检查，确认无白底、水印、拉伸失真、状态跳动或描边粗细变化。
- 执行 `git diff --check`，并确认未触碰无关工作区改动。
