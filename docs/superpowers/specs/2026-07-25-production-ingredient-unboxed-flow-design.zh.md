# 制作队列食材无框三列布局设计

日期：2026-07-25  
范围：`project-rest-new` 制作队列右侧配方条目的食材区域

## 目标

去掉每项食材的独立底色、边框和圆角，让配方信息更紧凑、更接近一行摘要；同时提高食材文字可读性，并通过固定三列控制最多六项材料的换行节奏。

## 已确认的界面规格

- 配方条目总高度保持 `68px`。
- 食材区域宽度保持 `300px`，不挤占名称、耗时、售价和操作按钮的既有列宽。
- 每项食材不显示背景、边框、圆角或分隔线。
- 每项内容采用单行结构：`18px 食材图标 + 食材名称 + 数量`。
- 食材名称与数量的最终字号为 `13px`；初次实现的 `11px` 不再使用。
- 食材区域固定为三列，每列宽度为 `(300px - 2 × 4px 间距) ÷ 3`，约 `97.3px`。
- 每行最多三项：一至三项只显示一行；四至六项显示两行；六项固定为 `3 + 3`。
- 第二行只能由材料数量超过三项触发，不能因为名称较长提前换行。
- 食材区域最多使用两行，垂直内容必须完整位于 `68px` 配方条目内。
- 长名称可以在单列限定宽度内显示省略号，但数量必须完整显示。
- 食材项之间保留轻量水平、垂直间距，不能通过重新增加卡片底框区分项目。
- 缺料与材料充足使用同一中性文字颜色，不标红；缺料数量继续显示 `已有数量/需要数量`，材料充足继续显示需要数量。
- 现有材料悬停提示保留。

## 方案选择

### 采用：固定三列、按数量换行

食材项仍由流式容器排列，但每项固定占三列中的一列。这样换行只取决于材料数量：第四项稳定进入第二行，六项始终为 `3 + 3`；13px 字体不会把某个长名称挤到额外行，密集配方的视觉节奏也保持一致。

### 未采用：继续六等分，仅移除可见边框

改动较小，但每项仍只有约 `46–47px`，提高到 `13px` 后名称会更频繁截断，且“可以换行”的要求无法实现。

### 未采用：按内容宽度自动换行

短名称可以节省横向空间，但同样数量的配方可能因为名称长度不同产生不同换行位置，六项也不一定稳定为 `3 + 3`。

## 组件调整

- 保留 `ProductionQueueRecipeRow` 的 `HFlowContainer`，但让每项使用固定三列宽度。
- 将食材项从有皮肤的面板组件改为无皮肤的普通控件，保留鼠标提示和内容裁切。
- 食材项内部保持单行横排；数量先占用完整宽度，名称使用剩余宽度并在必要时省略。
- 不改配方排序、库存判断、缺料判断、制作行为、进度表现或左右两列结构。

## 边界处理

- 材料为零项时，食材区域保持空白，不显示占位框。
- 一至三项保持第一行，四至六项使用第二行。
- 超过三项时按输入顺序换行；六项固定前三项在第一行、后三项在第二行。
- 极长材料名称使用省略号并通过现有悬停提示显示完整信息；不得挤出数量或覆盖后续项目。

## 验证

- 自动检查食材项不存在面板背景、边框和圆角。
- 自动检查名称与数量字体均为 `13px`，图标为 `18px`。
- 自动检查每项宽度约 `97.3px`，三项保持一行，四项变为 `3 + 1`，六项固定为 `3 + 3`。
- 自动检查长名称只影响名称省略，不改变三列换行位置，数量保持完整。
- 自动检查所有食材项的边界均位于 `300×68px` 食材区域内。
- 运行制作队列场景、配方制作交互和按钮皮肤相关自检，确认本次样式调整没有改变制作逻辑。
- 运行实际制作队列页面并截图，核对无框视觉、文字清晰度、换行和整条 `68px` 高度。

## 非目标

- 不调整制作队列总宽度或左右栏宽度。
- 不增加配方标签 Tab。
- 不修改完成库存、可制作、缺材料三组的归属与排序。
- 不处理未跟踪的 `resources/ui/icons_v1` 资产。
