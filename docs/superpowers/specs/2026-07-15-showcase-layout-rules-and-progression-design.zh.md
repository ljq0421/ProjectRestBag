# 橱窗动态区域、规则显性化与构筑扩展设计

日期：2026-07-15  
状态：待用户评审  
适用项目：`D:\Project\ProjectRest\project-rest-new`

## 1. 背景与结论

`project-rest-new` 已经具备区域、四方向相邻标签、连通套装、冲突减损、上架变体、配方成长、商品角色、热度连锁、陈列道具和橱窗主题等计算能力，但玩家看到规则的时点主要集中在拖拽预览、商品悬停和营业结算之后。

仓库中的 `doc/橱窗配方布局设计.md` 明确写有四方向相邻、套装和冲突规则，但该文档仍保留旧 `5 x 10` 橱窗、旧标签名和旧固定区域坐标，不能继续作为当前运行时或玩家说明的唯一真相。当前运行时数值来自 `doc/display_rules_full.json`、`doc/showcase_round_rules.json` 和多个服务常量，玩家无法在营业前完整查看。

本设计解决四类问题：

1. 初始已解锁区由中心 `6 x 6` 缩小为第 `5-8` 行、第 `6-9` 列，共 `4 x 4 = 16` 格。
2. 引流前排位、黄金 C 位、宝藏深处位不再绑定完整 `12 x 14` 棋盘的固定绝对范围，而是根据当前已解锁矩形动态计算。
3. 相邻、套装、减损、变体、成长、角色、道具和主题在营业前拥有统一、显著、可主动查看的规则入口。
4. 在现有系统修正后，分阶段加入留白与拥挤、方向连锁、陈列容量和动态热点，强化橱窗布局的长期构筑深度。

## 2. 设计目标

1. 玩家不摆放商品也能查看全部已开放规则，不需要先触发后反推。
2. 玩家拖拽商品时能立即看见将触发、将失去和仍缺少的规则。
3. 区域随橱窗扩张自动重算，区域定义不再因棋盘尺寸或已解锁范围变化而失真。
4. 所有加成和减损必须进入同一收益归因链，结算可以解释每一笔基础、市场、布局、连锁和清仓收入。
5. 新机制必须改变空间决策、库存决策或连锁路径，不继续堆叠缺少空间含义的全局百分比。
6. 保持标准营业轮固定 30 秒、每件商品独立销售周期、轮内补货和明确余货结算边界。

## 3. 非目标

- 本设计不改任务系统正在进行的“当前目标 / 支线任务”重构。
- 本设计不修改 `2026-07-15-recipe-growth-display-config-design.zh.md` 规定的 166 配方成长展示配置生成结果。
- 本设计不一次性开放完整 `12 x 14` 棋盘，也不在第一阶段确定所有扩张价格。
- 本设计不增加指定配方才能完成的主线目标。
- 本设计不保留旧 `6 x 6` 初始区域的存档迁移分支；项目处于开发阶段，验证使用新档。

## 4. 初始解锁区与动态区域

### 4.1 初始矩形

新档初始已解锁区域固定为：

- 行：第 `5-8` 行；
- 列：第 `6-9` 列；
- 尺寸：`4 x 4`；
- 总格数：`16`。

外围其余 152 格继续显示锁定状态并拒绝商品、道具、移动、旋转和替换落点。

### 4.2 已解锁区域的数据合同

`GameState` 不再只暴露四个编译期常量，而是保存并提供统一的已解锁矩形：

```gdscript
showcase_unlocked_bounds = {
    "row_min": 5,
    "row_max": 8,
    "column_min": 6,
    "column_max": 9
}
```

所有放置校验、利用率、区域计算、扩张显示和挑战快照都读取这一个边界。后续扩张只能生成仍位于 `12 x 14` 内的矩形；第一阶段只建立数据合同和初始值，扩张价格与按钮在后续阶段接入。

### 4.3 百分比区域算法

对当前已解锁矩形中的每个格子，使用格子中心点在已解锁范围中的归一化位置计算区域：

```text
row_ratio = (local_row_index + 0.5) / unlocked_row_count
column_ratio = (local_column_index + 0.5) / unlocked_column_count
```

区域判定：

- `row_ratio < 0.30`：引流前排位；
- `row_ratio > 0.70`：宝藏深处位；
- 其余行为中间行；
- 中间行且 `0.30 <= column_ratio <= 0.70`：黄金 C 位。

离散格数导致某个区域为空时，使用以下保底规则：

- 引流区至少取已解锁第一行；
- 宝藏区至少取已解锁最后一行；
- 中间行至少取最接近垂直中心的一行；
- 黄金列至少取最接近水平中心的一列；
- 三类行区域不得重叠，优先顺序为“首行引流、末行宝藏、其余中间”。

初始 `4 x 4` 区域的实际结果为：

```text
      第6列  第7列  第8列  第9列
第5行  引流   引流   引流   引流
第6行  中间   黄金   黄金   中间
第7行  中间   黄金   黄金   中间
第8行  宝藏   宝藏   宝藏   宝藏
```

### 4.4 区域数值

第一阶段保持现有数值，先改变范围来源和可见性：

| 区域 | 售价 | 售速 | 额外规则 |
| --- | ---: | ---: | --- |
| 引流前排位 | -3% | +8% | 无 |
| 黄金 C 位 | +5% | 0 | 相邻、套装与冲突幅度 ×1.2 |
| 宝藏深处位 | +8% | -4% | 无 |

商品只有全部占格落在同一功能区域内才获得该区域效果。跨区域商品不获得区域固定效果，拖拽预览必须明确显示“跨区：无区域效果”。

### 4.5 区域服务

新增纯服务 `ShowcaseRegionService`：

- 输入：已解锁矩形、区域策略配置、商品占格；
- 输出：每个格子的区域 ID、每个区域的实际行列范围、商品完整所属区域；
- 不读取场景节点，不修改金币、库存或存档；
- `ShopSimulation`、`main_view.gd`、报告服务和测试共同消费服务输出。

`doc/display_rules_full.json` 中的固定 `row_range` / `col_range` 改为百分比策略和区域效果，避免配置与运行算法重复维护。

## 5. 规则真相与游戏内说明

### 5.1 当前明确程度审计

| 规则 | 仓库文档 | 当前游戏内表现 | 结论 |
| --- | --- | --- | --- |
| 四方向相邻标签 | `doc/橱窗配方布局设计.md` 与 `display_rules_full.json` | 拖拽和悬停在触发后显示原因 | 没有营业前总览 |
| 连通套装 | 同上 | 触发后进入 tooltip / 结算原因 | 玩家无法主动查完整套装表 |
| 冲突减损 | 同上 | 红色预览或触发后原因 | 缺少触发条件总览和规避提示 |
| 上架变体 | 右键菜单 | 菜单和商品 tooltip | 入口隐蔽，格子本体缺少稳定标识 |
| 配方成长 | 成长服务与商品 tooltip | 显示阶段和已选特性 | 阈值、候选与实际收益不集中 |
| 角色与连锁 | `showcase_round_rules.json` | 热度和结算角色 | 营业前难以理解定位关系 |
| 道具与主题 | 运行时服务 | 没有正常玩家入口 | 代码存在但玩法未开放 |

### 5.2 构筑规则入口

在橱窗左侧棋盘的营业控制条增加常驻 `构筑规则` 按钮，与当前环境和“开始营业”同一决策区域。按钮在调整、营业和结算阶段都可查看，但规则编辑操作只在调整阶段开放。

点击后打开真实居中对话框 `ShowcaseRulebookDialog`，不用临时状态栏或只读 tooltip 代替。对话框使用场景文件维护稳定结构，包含九个分类：

1. 区域；
2. 四方向相邻；
3. 连通套装；
4. 冲突减损；
5. 上架变体；
6. 配方成长；
7. 商品角色与热度连锁；
8. 陈列道具；
9. 橱窗主题。

每条规则至少显示：名称、触发条件、影响对象、售价变化、售速变化、占格或热度成本、当前开放状态。区域页必须显示当前已解锁区域推导出的实际行列，而不是固定历史坐标。

### 5.3 橱窗经营页的当前构筑摘要

右侧 `橱窗经营` 页在经营概览之后增加固定的“当前构筑”卡，不把核心规则藏在页面底部：

- 当前区域分布与已开放 `16/168`；
- 正向规则数量、冲突数量、连通套装数量；
- 当前主题和已放置道具数量；
- 当前最强的三条增益或减损；
- `查看全部规则` 按钮。

现有“最近营业报告”和“橱窗扩张”底部双卡保持；扩张卡的“中心 6x6”文案改为当前动态矩形和 `16/168`。

### 5.4 棋盘视觉

已解锁空格使用低强度底色或角标区分三个区域：

- 引流：浅青色；
- 黄金：浅金色；
- 宝藏：浅紫棕色；
- 普通中间区：维持基础色。

区域视觉不得盖住配方图标、库存徽标、待售进度和拖拽预览。锁定格继续优先显示锁定皮肤。

拖拽预览除“预计售价/售速”外，固定拆成三行：

- `新增：` 本次摆放新增的区域、相邻、套装或留白规则；
- `失去：` 移动后失去的规则；
- `风险：` 新增冲突、跨区、拥挤、断链或未解锁格原因。

## 6. 修正现有规则合同

### 6.1 四方向相邻

- 只认上下左右接触，斜角不算；
- 一对商品可以匹配多条不同标签规则并叠加，不再只取优先级最高的一条；
- 同一规则对同一商品对只结算一次，避免多格接触重复计数；
- 规则图鉴显示双方都获得效果。

### 6.2 连通套装

- 候选连通块必须覆盖规则声明的全部 `required_tags`；
- 每个参与商品至少与套装中的另一个商品四方向相邻；
- 套装只作用于实际满足条件的最小连通成员组，不把同一连通块内仅命中任意标签的所有商品都自动纳入；
- 同一商品可以参与不同套装；同一套装 ID 对同一商品只生效一次；
- 报告保存稳定的套装 ID、名称和参与配方 ID。

### 6.3 同类扎堆

- 按“相同标签的四方向连通分量”分别判断，不再按全橱窗同标签总数判断；
- 每个连通分量前两件不受罚，第 3 件及以后分别承受售价 -5%、售速 -3%；
- 被惩罚的成员按锚点行列稳定排序，保证相同布局结果确定；
- 把同类商品拆成两个不连通组可以消除扎堆减损。

### 6.4 试吃口碑

- `sample` 变体明确获得每次真实成交 `+1` 额外口碑；
- 该固定变体口碑与售价倍率推导的口碑分开计算；
- 清仓和纯连锁金币奖励不产生试吃口碑；
- UI 明确显示“售价 -35%、售速 +40%、真实成交额外口碑 +1”。

- 基础道具随 Lv.2 构筑课程开放；
- 专项道具随 Lv.3-Lv.5 成长或阶段奖励开放；
- Lv.6+ 合同只提供外观变体或更高阶横向选择，不提供不可替代的唯一数值道具；
- 已解锁道具永久保留，可在调整阶段从右侧“道具与主题”卡拖到橱窗；
- 道具占用真实格子，不可与商品或其他道具重叠；
- 营业中不可移动、放置或移除，道具操作失败必须显示原因。

### 8.1 第一批主题

| 主题 | 匹配标签 | 效果 |
| --- | --- | --- |
| 夏日 | 清爽、果香、清凉 | 售速 +8% |

| 茶会 | 茶香、苦甜、甜 | 售价 +4%、售速 +4% |

### 8.2 主题规则

- 同一轮只能启用一个主题，也可以选择“无主题”；
- 调整阶段选择，开始营业后锁定；
- 主题不占格，但只强化匹配标签商品；
- 主题选择区同时显示当前橱窗内的匹配商品数量和预计收益变化；
- 主题通过店铺阶段、构筑任务或门店评级开放，不要求解锁指定配方；
- 营业环境与橱窗主题是两层独立来源，结算分别归因。

## 9. 配方成长显性化

当前正在生成的 `growth_variants` 只描述各成长阶段的展示几何，不在本设计中重复修改。运行时接入分为两个步骤：

1. 规则图鉴和商品详情显示试作品、稳定款、人气款、招牌款的阈值、基础收益、可选特性和进阶形状预览；
2. `pending_trait_choice` 为真时打开真实成长选择对话框，展示每个候选对 30 秒预计成交次数、金币、占格、角色和热度连锁的影响，确认后调用现有 `select_recipe_trait()`。

商品格本体保留简短成长角标，不把完整成长说明塞进格子文字。

## 10. 后续构筑机制

### 10.1 留白与拥挤

在初始规则和扩张稳定后加入：

- 中块、大块或收获型商品，四方向外沿至少存在 2 个已解锁空格时，获得“精品留白”：售价 +6%；
- 商品四方向外沿没有任何已解锁空格时，获得“陈列拥挤”：售速 -6%；
- 锁定格、棋盘外和道具占格不计为空格；
- 初始 `4 x 4` 阶段只显示规则预告，达到至少 36 个已解锁格后正式生效，避免前期空间过小形成强制惩罚。

### 10.2 方向连锁

当前推进角色会选择全橱窗距离最近的目标，空间关系不够显著。后续改为：

- 推进角色优先推动与自身四方向直接相邻的可售商品；
- 没有相邻目标时不发动推进，并显示“连锁断开”；
- 多个相邻目标按锚点距离、行、列、配方 ID 稳定选择；
- 预览用箭头显示 `引流 -> 推进 -> 放大 -> 收获` 的实际目标；
- 单次连锁仍最多 4 个不同商品，保持现有热度成本和真实库存扣除规则。

### 10.3 陈列容量

让占格不只影响拼图，还影响补货压力：

```text
最大陈列库存 = 2 + ceil(商品占格数 / 2)
```

- 1-2 格商品最多 3 份；
- 3-4 格商品最多 4 份；
- 5-6 格商品最多 5 份；
- 7-8 格商品最多 6 份；
- 9 格商品最多 7 份；
- 超出容量的补货留在库存，不扣除、不丢失，并显示“陈列容量已满”；
- 小份/试吃侧重节省空间但需要频繁补货，大份/礼盒侧重容量和单次收益。

该机制会改变轮内补货与“一键上架全部”合同，必须单独成阶段实施和回归。

### 10.4 动态热点

在环境确定后，从当前已解锁区域生成一条营业前可见的临时热点：

- 客流热点：一行或一列售速 +10%；
- 品质展位：中心小区域售价 +8%；
- 拥堵带：一行售速 -6%、售价 +3%；
- 热点只持续本轮，开始营业前显示，营业中不变化；
- 热点与永久区域、主题分别归因，避免把环境变化误显示为布局固定效果。

- 推进连锁改为相邻方向目标；
- 增加有效连锁箭头；没有相邻目标时静默终止，不显示断链标记。

### 阶段 E：库存与轮次变化

- 加入陈列容量；
- 加入动态热点；
- 接入真实橱窗扩张价格、永久解锁和新合同条件。

每个阶段独立使用红绿测试、真实交互验证和宽回归；不得把 A-E 合并为一次不可归因的大改。

## 12. 组件职责

- `display_rules_full.json`：区域策略、相邻、套装、冲突、变体、道具和主题的数值真相。
- `showcase_round_rules.json`：角色、热度、连锁、环境和动态热点模板。
- `ShowcaseRegionService`：已解锁矩形到动态区域的纯计算。
- `ShowcaseRuleService`：聚合区域、相邻、套装、冲突、成长、变体、主题和道具结果。
- `ShowcaseRoleService` / `ShowcaseChainService`：角色与确定性连锁。
- `GameState`：保存已解锁矩形、已解锁道具、当前主题、摆放道具和成长选择。
- `main_view.gd`：协调刷新、预览、营业锁定和对话框，不新增规则计算。
- `.tscn` 场景：维护规则按钮、当前构筑卡、规则图鉴、道具主题面板和成长选择对话框的稳定结构。

## 13. 验证标准

### 13.1 区域

- 新档恰好解锁第 5-8 行、第 6-9 列，共 16 格；
- 初始区域得到第 5 行引流、第 6-7 行中部、第 8 行宝藏和中心 `2 x 2` 黄金 C 位；
- 不同矩形尺寸均满足引流、宝藏、中间行和黄金列至少 1；
- 商品跨区域时不获得区域固定效果；
- 放置、移动、旋转、替换、道具和轮内上新都拒绝未解锁格。

### 13.2 规则计算

- 一对商品可以触发多条不同相邻规则，但同一规则不因多格接触重复；
- 套装缺少任一必需标签时不触发；
- 三个同标签但互不连通的商品不受扎堆惩罚；
- 试吃真实成交得到额外口碑，清仓与纯金币连锁不产生；
- 规则叠加后的售价和售速仍遵守统一上限与稳定归因。

### 13.3 玩家说明

- 未摆放商品时可打开规则图鉴查看全部已开放规则；
- 区域页显示当前动态行列范围；
- 变体、成长、道具和主题均显示入口、开放状态和准确效果；
- 拖拽预览同时显示新增、失去和风险；
- 结算说明与营业前规则名称和数值一致。

### 13.4 新机制

- 留白和拥挤只在规定开放阶段生效；
- 推进只选择相邻可售目标，顺序确定且不越过 4 层；
- 容量不足不丢库存、不误扣库存；
- 动态热点在营业前锁定，并与永久区域分别归因。

### 13.5 回归

- 标准营业仍为 30 秒；
- 轮内补货、上新、售完替换、余货八折、五折清仓和一折强制清仓保持正确；
- 当前任务系统重构与 166 配方成长展示配置继续通过各自测试；
- Godot headless 使用可写 `--log-file`，以退出码和显式 PASS 为准；
- `git diff --check` 无格式错误。

## 14. 待用户确认

1. 后续真实扩张是否统一保持“居中矩形逐级扩大”。本设计推荐保持矩形，这样动态 30% / 40% / 30% 区域稳定且易理解；如果允许不规则模块，必须另行定义洞和突出格如何参与百分比区域。
2. 陈列道具采用“阶段奖励后永久拥有”的推荐方案，而不是每轮购买或一次性消耗品。
3. 新增机制按 A-E 五个独立阶段实施，不一次性全部上线。
