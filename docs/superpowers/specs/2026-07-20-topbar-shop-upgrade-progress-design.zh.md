# 顶部栏店铺升级进度设计

## 目标

在主界面顶部栏常驻展示店铺升至下一等级所需的金币和累计口碑进度，让玩家不必打开成长任务详情也能判断升级距离。

本改动只增强现有升级条件的可见性，不修改升级公式、资源消耗规则、成长任务结构或等级推进时机。

## 已确认方案

采用顶部栏方案 A：保留“店名、金币、口碑、店铺等级”的现有阅读顺序，将金币与口碑分别改为纵向资源模块。

每个资源模块包含：

1. 上方数值标签，例如 `金币 899 / 900`、`口碑 29 / 30`。
2. 下方一条细横向进度条。

金币和口碑使用不同但符合现有甜品店主题的填充色。两条进度互相独立，不合并成一个综合等级百分比。

### 紧凑几何修订

顶部栏必须保持原有 `44px` 高度，不能为了容纳进度条增加最小高度，否则会把下方主体整体向下挤压。

- 金币与口碑资源模块高度均为 `44px`。
- 进度条高度为 `8px`，顶部位于模块局部坐标约 `24px`，让文字与进度条之间只保留约 `2–3px` 视觉间距。
- 进度条下方保留空白，不与顶部栏边缘贴合。
- 金币与口碑模块宽度保持 `180px`，不改变店名、等级和主体页面的纵向位置。

## 数据来源与显示规则

顶部栏刷新时调用 `GameState.upgrade_eligibility()`，以其返回值作为下一等级条件的唯一数据源：

- `cost` 是下一等级所需金币。
- `required_reputation` 是下一等级所需累计口碑。
- 当前值分别使用 `state.coins` 与 `state.reputation`。

标签保留真实当前资源量，不把超过门槛的数值截断。例如当前持有 1200 金币、门槛为 900 时显示 `金币 1200 / 900`；进度条的视觉填充封顶为 100%。

金币模块的提示文本说明“店铺升级会扣除所需金币”。口碑模块的提示文本说明“只检查累计口碑，升级不会扣除口碑”。

## 边界状态

- Lv.0 的首次升级由教学任务领取推进，不使用金币和口碑门槛。Lv.0 继续显示金币与口碑当前值，但隐藏两条升级进度条，避免出现 `0 / 0`。
- 当 `upgrade_eligibility()` 返回 `definition_missing` 时，继续显示金币与口碑当前值，但隐藏两条升级进度条。这一状态不得显示虚构的下一等级条件。
- 当金币或口碑达到门槛时，对应进度条填满；数值标签仍显示真实当前值。
- 完成升级后，现有资源栏刷新流程立即重新读取下一等级条件，分母切换为新目标。

## 场景与代码边界

稳定布局结构写入 `scenes/Main.tscn`：

- 保留 `Root/TopBar/CoinsLabel` 与 `Root/TopBar/ReputationLabel` 的既有节点路径，避免破坏金币飞行动画锚点和现有测试。
- 在两个资源标签节点下各放置一个 `ProgressBar` 子节点，组合成紧凑的纵向资源模块。
- 店名与等级模块维持原有顺序和职责。

`scripts/main_view.gd` 只负责绑定节点，并在 `_refresh_resource_bar()` 中把当前状态及 `upgrade_eligibility()` 结果写入标签、进度条、可见性和提示文本。

不得在 UI 脚本中重新计算等级公式，也不得修改 `Catalog`、`TaskService` 或 `GameState.upgrade()` 的业务规则。

## 验证

增加聚焦顶部栏的 Godot 自检，至少覆盖：

1. Lv.1 未达门槛时，金币与口碑标签和进度值分别正确。
2. 当前资源超过门槛时，标签保留真实值，进度条填充封顶。
3. 达成一次升级并刷新后，顶部栏切换到下一等级分母。
4. Lv.0 隐藏升级进度条且不显示 `0 / 0`。
5. 缺少下一等级定义时隐藏升级进度条。
6. 金币和口碑提示文本准确说明是否扣除资源。
7. `TopBar` 保持 `44px`，进度条高度为 `8px`，主体页面不因新增进度而下移。

运行自检时遵守仓库约定，为 Godot 4.6.1 headless 命令传入位于可写临时目录的 `--log-file`。

## 非目标

- 不在成长任务详情中新增第二套进度条。
- 不增加升级按钮、升级提醒动画或可领取红点。
- 不改变 Lv.0 教学升级、金币扣除、累计口碑不扣除或无限等级生成规则。
- 不调整顶部栏以外的页面布局。
