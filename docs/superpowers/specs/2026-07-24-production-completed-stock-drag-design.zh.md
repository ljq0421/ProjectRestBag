# 制作队列完成库存保留与拖拽上架设计

日期：2026-07-24
目标项目：`project-rest-new`
基于：`feature/production-queue-picker`

## 1. 目标

配方制作完成后，配方行不再因运行任务从队列移除而立即消失。只要该配方仍有成品库存，或仍有批次正在制作，它就继续显示在右侧制作队列中。

玩家可以直接从配方行的完成库存区域拖拽到橱窗上架。拖拽沿用现有橱窗布局、变体、占格、营业阶段和库存扣减规则，每次成功拖拽上架 1 件成品。

## 2. 明确边界

- 三个纵向槽位只表示最多三批并发制作，不把完成库存计入并发容量。
- 完成时仍立即结算产物、成长和任务事件，成品继续进入 `product_inventory`。
- 不把已完成任务继续留在 `recipe_production_queue`，避免重复结算。
- 不新增“待领取产物”或逐批领取系统。
- 同配方有完成库存并开始新批次时，完成库存与三个制作槽可以同时显示。
- 成品库存为 0 且没有正在制作的批次后，该配方行自动消失。
- 本次不改变仓库拖拽、橱窗变体选择、橱窗形状或营业阶段规则。

## 3. 状态模型

在 `GameState` 中增加轻量的已完成配方记录，按 `recipe_id` 保存：

```gdscript
production_ready_recipe_records = {
    "rice_milk_drink": {
        "display_sequence": 12,
        "last_completed_at_unix": 1784887200
    }
}
```

记录只负责说明“该配方应继续出现在制作队列”以及稳定排序，不保存独立产物数量。可拖拽数量始终以 `product_inventory[recipe_id]` 为唯一事实来源。

### 写入

- 手动制作完成且产物成功入仓后写入或刷新记录。
- 自动制作完成且产物成功入仓后使用相同路径写入或刷新记录。
- `display_sequence` 首次使用完成任务的 `queue_sequence`；同一记录存在期间不因后续完成而跳动。

### 清理

当下列条件同时成立时移除记录：

- `get_product_count(recipe_id) == 0`
- `active_recipe_production_batch_count(recipe_id) == 0`

清理必须覆盖：

- 成品成功拖拽上架并扣减仓库库存；
- 成品作为其他配方材料被消耗；
- 读取存档时发现零库存的陈旧记录。

记录需要进入正常存档和读取流程。读取时只接受有效配方 ID、正整数顺序和非负完成时间。

## 4. 队列合并与排序

`main_view.gd` 构造队列条目时合并两个来源：

1. `recipe_production_queue_summary()` 中的进行中配方；
2. `production_ready_recipe_records` 中仍有成品库存的配方。

每个配方只生成一行。排序使用以下稳定规则：

- 同时有进行中批次和完成记录时，取两者最小的有效顺序；
- 只有完成库存时，使用记录的 `display_sequence`；
- 记录被清理后，该配方将来重新制作完成会取得新的顺序。

此前约 1 秒的绿色完成闪现可以保留，作为刚完成的瞬时反馈；它不再负责维持配方行的生命周期。

## 5. 配方行布局与交互

`ProductionQueueRecipeRow` 保留右侧三个纵向制作槽。左侧配方摘要增加一个稳定的 `CompletedStockDragArea`：

- 无成品库存：隐藏；
- 有成品库存：显示绿色完成状态、`库存 ×N` 和“拖拽上架”提示；
- 上架功能未解锁：区域可见但不可拖拽，并显示明确的解锁原因；
- 当前橱窗无法接收：仍允许开始拖拽，由现有橱窗落点校验展示失败原因。

拖拽数据复用现有库存成品协议：

```gdscript
{
    "kind": "inventory_product",
    "recipe_id": recipe_id,
    "variant_id": selected_variant_id,
    "shape_rows": ...,
    "shape_cols": ...,
    "cell_count": ...,
    "shape_cells": ...
}
```

因此橱窗不需要识别新的拖拽种类。成功落点继续调用现有上架路径并扣减 1 件仓库库存。

拖拽预览显示配方名、当前变体和占格形状。配方行不弹出仓库覆盖层，也不在拖拽期间隐藏制作队列。

## 6. 刷新流程

制作完成：

1. 结算产物进入仓库；
2. 写入完成配方记录；
3. 刷新制作队列；
4. 配方行显示完成库存拖拽区。

拖拽上架成功：

1. 现有橱窗路径扣减 1 件仓库库存；
2. 刷新橱窗和制作队列；
3. 库存仍大于 0 时更新 `库存 ×N`；
4. 库存为 0 且没有进行中批次时清理记录并移除配方行。

拖拽失败：

- 不扣库存；
- 不清理记录；
- 配方行和完成库存数量保持不变；
- 使用现有橱窗失败状态说明原因。

## 7. 测试要求

### 领域层

- 手动和自动制作完成都会写入完成配方记录。
- 完成任务不再留在运行队列，也不会重复发放产物。
- 记录可存档、恢复和清理。
- 库存耗尽但仍有活动批次时记录保留。
- 库存耗尽且无活动批次时记录移除。

### UI

- 只有完成库存时配方行仍显示。
- 完成库存与一至三批活动槽可以同时显示。
- 三批容量统计不包含完成库存。
- 完成区域显示正确库存和锁定说明。

### 真实交互

- 从完成库存区域发起真实鼠标拖拽并成功落到橱窗。
- 每次成功拖拽只扣减并上架 1 件。
- 失败落点不扣库存、不移除配方行。
- 最后一件成功上架且无活动批次后，配方行消失。
- 如果最后一件上架时仍有活动批次，配方行继续存在。

## 8. 非目标

- 批量拖拽或一次上架整批；
- 独立的完成产物领取按钮；
- 完成历史页；
- 为制作队列单独实现一套橱窗变体选择器；
- 修改橱窗占格、补货、售罄替换或营业阶段行为。
