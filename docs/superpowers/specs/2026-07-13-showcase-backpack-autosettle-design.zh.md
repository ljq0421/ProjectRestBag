# 橱窗独立售卖与跳金币反馈设计

**日期：** 2026-07-13
**状态：** 已确认
**目标分支：** `feature/showcase-backpack-autosettle`
**基线：** `e884429d4beae991d52d3fa58a300e2cf455cd24`，并已移植库存名称与采购小票相关提交

## 1. 背景

当前橱窗已经具备多格商品、自由摆放、旋转、独立库存、售卖时间、布局加成、自动入账和基础金币飞行动画，但运行与反馈仍有以下问题：

- `_process_showcase_sales()` 每次只处理第一件到期商品，同一时刻的其他成交会被推迟。
- 售卖计时、经济结算、任务事件和表现逻辑集中在 `main_view.gd`，难以独立验证。
- 商品售罄后会退出当前售卖循环，橱窗 build 不能稳定保留为长期经营布局。
- “集中收银”与即时入账同时存在，容易让玩家误解金币是否需要手动领取。
- 现有金币飞行只是单个符号直线移动，缺少商品弹跳、连续金币和余额回弹组成的收获高潮。
- 基于时间戳的计时尚未形成清晰的离线批量结算契约。

本方案参考《背包乱斗》的核心感受：玩家先通过多格商品的形状、位置与组合完成 build，随后看着每件商品在棋盘上独立运转并持续产生结果。参考的是“摆放构筑 + 盘面自动运转”的概念，不复制战斗、回合或商店刷新系统。

## 2. 设计目标

### 2.1 核心目标

- 每件已摆放商品拥有独立、持续、可读的售卖循环。
- 商品到点后自动售出一份并立即入账，不设置领取门槛。
- 用商品弹跳、金额浮字、多枚金币弧线和顶部余额回弹建立清晰的收益因果。
- 商品售罄后保留形状与位置，让玩家的橱窗 build 不因库存暂时归零而消失。
- 移动或旋转商品时保留当前进度比例，并立即应用新布局的售速与售价。
- 游戏离线期间按时间和库存补算，返回游戏时合并成一次可读的金币爆发。
- 将结算计算从 `main_view.gd` 抽离为可独立测试的领域服务。

### 2.2 非目标

- 不引入顾客排队、顾客寻路、点单或取货动画。
- 不引入全局营业回合或统一结算节拍。
- 不保留“集中收银”领取或回放按钮。
- 不自动从成品库存补充橱窗；补货仍由玩家拖入同款商品完成。
- 不自动采购、自动制作或自动上架新商品。
- 不修改当前 `12 × 14` 橱窗棋盘、中心初始开放区或扩张规则。
- 不修改现有橱窗售价、售速、相邻、套装、冲突和成长数值。
- 不为本功能新增音效资源；声音可在后续独立迭代。
- 项目仍处于开发阶段，本方案不做旧存档字段迁移、旧结构兼容或历史存档补偿。

## 3. 已确认的产品决策

1. 采用“独立售卖器”路线：每件商品独立计时、独立成交、独立开始下一轮。
2. 每次到期只售出该商品的一份库存，金币立即写入真实账户。
3. 库存归零后保留商品形状，进入“缺货”状态；玩家拖入同款后原位恢复售卖。
4. 移动、旋转和补货不重置当前进度比例。
5. 布局变化后立即按新布局重算售价与剩余售速。
6. 移除“集中收银”，右侧只保留实时效率、缺货提醒、最近成交和收益来源。
7. 离线期间按经过时间与库存补算；返回游戏时合并播放一次离线收益反馈。
8. 同一时刻多件成交全部真实结算，表现层只负责错峰和降噪。

## 4. 核心售卖循环

每件商品按以下状态循环：

`售卖中 → 到期成交 → 有库存则开始下一轮 / 无库存则进入缺货 → 玩家补货 → 恢复售卖`

### 4.1 正常成交

商品到达 `sale_ready_at_unix` 时：

1. 从 `ShowcaseRuleService` 的当前布局结果中读取该商品的售价与售速。
2. 生成该商品本次成交计划。
3. 扣除一份橱窗库存。
4. 将金币、口碑、任务进度和配方成长写入真实状态。
5. 写入一条结构化最近成交记录。
6. 向 `ShowcaseFeedbackDirector` 投递表现事件。
7. 若仍有库存，以成交时刻为起点开始下一轮；否则保持摆放并进入缺货状态。

经济更新必须先于动画。动画节点缺失、动画被跳过或玩家切换页面都不能撤销或重复发放收益。

### 4.2 同一帧多件到期

- 一次 tick 必须扫描全部已摆放商品，不能在第一笔成交后提前返回。
- 结算顺序按商品锚点格索引升序，保证测试、记录和表现可重复。
- 每件商品独立扣库存、独立计算价格并独立推进任务与成长。
- 结算完成后统一刷新状态并保存一次，避免每笔成交都重建橱窗或写盘。

### 4.3 缺货与补货

- `stock == 0` 不删除 `display_items` 中的商品，也不释放其占用格。
- 缺货商品不推进新的售卖周期，不产生金币或口碑。
- 玩家把同款成品拖到该商品任意占格时，交互解释为“原位补货”，不执行移动或新建。
- 补货只增加该商品的橱窗库存，不从仓库自动抽取后续库存。
- 正常售出最后一份库存时，下一轮进度先归为 `0%` 再暂停；补货后从该暂停点开始。若其他开发期操作在周期中途把库存改为零，则保留当时的暂停比例。
- 拖入不同商品时仍使用现有占格冲突和放置规则，不能覆盖缺货商品。

## 5. 计时与进度

### 5.1 开发期数据结构

不迁移旧存档，直接以新结构作为开发期真相。每个 `display_items[recipe_id]` 至少包含：

```gdscript
{
    "cells": Array[Vector2i],
    "stock": int,
    "variant_id": String,
    "cycle_started_at_unix": int,
    "cycle_duration_seconds": int,
    "sale_ready_at_unix": int
}
```

- `cycle_started_at_unix`：当前周期按现有售速开始或重映射后的起点。
- `cycle_duration_seconds`：当前布局下本轮完整周期时长。
- `sale_ready_at_unix`：本轮到期时间。
- 缺货时仍保留周期字段，但不继续推进；补货时按保存的进度比例恢复。

### 5.2 移动与旋转时保留进度

移动或旋转前先处理已经到期的成交，再重算布局。未到期商品按以下规则换算：

```text
旧完成比例 = clamp((当前时间 - 旧周期起点) / 旧周期时长, 0, 1)
新剩余时间 = ceil(新周期时长 × (1 - 旧完成比例))
新周期起点 = 当前时间 - floor(新周期时长 × 旧完成比例)
新到期时间 = 当前时间 + 新剩余时间
```

因此，移动不会凭空增加或清空进度；新的位置、相邻、套装和冲突售速会立即影响剩余时间。成交价格始终以真正成交时的布局结果为准。

### 5.3 系统时间异常

- 当前时间早于周期起点时，完成比例按 `0` 处理，不产生负剩余时间。
- 当前时间大幅前进时可以触发离线补算，但销量始终受橱窗库存约束。
- 周期时长至少为 `1` 秒，防止除零和无限成交。

## 6. 离线批量结算

离线补算在载入当前开发期存档后执行一次。离线期间布局不发生变化，因此使用载入时的布局规则结果。

对每件有库存的商品：

```text
若 now < first_ready：可售数量 = 0
若 now >= first_ready：理论数量 = 1 + floor((now - first_ready) / duration)
实际数量 = min(理论数量, 当前橱窗库存)
```

结算要求：

- 按商品聚合数量计算，不能为几百次离线成交创建几百个动画或逐次保存。
- 金币、口碑、任务计数、配方成长和库存变化与逐笔结算的合计一致。
- 仍有库存时，将下一次到期时间推进到当前时间之后的第一个合法周期点。
- 库存耗尽时保留商品位置并进入缺货状态。
- 所有商品计算完成后统一写入状态并保存一次。
- 返回游戏时只生成一个离线汇总表现，包含售出件数、总金币和贡献最高的商品。

## 7. 视觉与交互设计

### 7.1 常态进度

- 每件多格商品只显示一条整体进度，不在每个格子重复绘制进度条。
- `showcase_board.tscn` 增加专用商品状态覆盖层；覆盖层按商品占格包围区域沿整体底边绘制连续进度。
- 正常售卖使用明亮金绿色；出现售速减损或冲突时使用橙红色。
- tooltip 显示预计售价、完整周期、剩余时间和主要增益/减损来源。
- 缺货商品整体降低饱和度，进度停止，并显示“缺货｜拖入同款补货”。

### 7.2 单次成交反馈

一次完整成交按以下顺序播放：

1. 商品整个占格区域短暂下压后弹起，图标同步加亮。
2. 商品原位浮出 `+金币数`。
3. 根据收益档位生成 `3–6` 枚金币；金币数量只表达收益档位，不与真实金额逐枚对应。
4. 金币以略有随机差异的抛物线和弹跳弧线飞向顶部 `CoinsLabel`。
5. 顶部金币数字滚动到真实余额，并做一次短促回弹。
6. 商品有库存时进度条立即进入下一轮；售罄时切换为缺货状态。

金币反馈层必须使用 `MOUSE_FILTER_IGNORE`，不能抢夺橱窗拖拽、旋转或补货输入。

### 7.3 同时成交降噪

- 同一秒内的完整反馈按约 `0.12` 秒间隔依次播放，形成连续节奏。
- 同屏最多播放 `4` 组完整商品弹跳和金币轨迹。
- 超出上限的成交显示为 `另外 N 件｜+X`，但每笔经济和最近成交记录仍保持独立。
- 表现队列只压缩动画，不得修改、合并或延迟真实金币入账。

### 7.4 离线收益反馈

- 返回游戏后在橱窗上方显示“离线售出 N 件｜金币 +X”。
- 橱窗整体做一次柔和回弹，随后生成一组较密集但受上限控制的金币爆发。
- 贡献最高的商品短暂金色描边，其余商品不逐笔回放。
- 离线汇总关闭或动画中断不影响已经完成的结算。

## 8. 右侧橱窗经营页

移除“集中收银”按钮及其消费汇总语义，不再出现“金币已入账但仍需点击查看”的双重心智。

保留并重组以下信息：

- 实时效率：当前上架商品数、缺货数、预计每分钟收入和主要售速来源。
- 缺货提醒：列出需要补货的商品，点击后高亮对应橱窗形状。
- 最近成交：按时间倒序显示商品、数量、单价、金币和主要原因。
- 收益来源：继续展示位置、相邻、套装、成长和冲突的解释。

删除旧的 `cashier_summary`、`consume_cashier_summary()`、`last_cashier_summary` 和集中收银回放路径。用有明确语义的 `recent_showcase_sales` 有界列表承载最近成交，默认最多保留 `30` 条结构化记录。

## 9. 代码与组件边界

### 9.1 `ShowcaseAutoSaleService`

新增 `scripts/showcase_auto_sale_service.gd`，职责包括：

- 扫描全部商品并生成确定性的在线到期结算计划。
- 按离线时间和库存生成按商品聚合的补算计划。
- 计算移动、旋转和售速变化后的进度比例映射。
- 输出商品数量、单价、总价、口碑、下一周期和缺货状态。

服务不创建 UI 节点，不播放动画，不自行保存文件。

### 9.2 `ShowcaseRuleService`

继续作为售价、售速、位置、相邻、套装、成长和冲突原因的唯一来源。自动售卖服务只消费规则结果，不复制规则计算。

### 9.3 `GameState`

- 持有新的商品周期字段、橱窗库存和 `recent_showcase_sales`。
- 提供一次性应用结算批次的状态入口，确保库存、金币和口碑同步更新。
- `display_items` 是商品摆放、库存与售卖周期的唯一业务真相；若实施期仍保留 `display_slots`，它只能作为根据 `display_items` 重建的格子命中投影，不能保存第二套经济或计时状态。
- 项目处于开发期，不保留旧 `display_slots`/`cashier_summary` 的迁移分支来服务历史存档。

### 9.4 `ShowcaseFeedbackDirector`

- 接收已经完成真实入账的成交事件。
- 按锚点顺序错峰播放。
- 限制同屏完整反馈数量。
- 生成溢出摘要和离线汇总表现数据。

### 9.5 场景与 UI 脚本

- `showcase_board.tscn`：稳定声明商品状态层、金币反馈层和离线汇总层。
- `showcase_slot.tscn/.gd`：处理格子图标、缺货蒙层、选中/冲突状态与弹跳视觉状态。
- `storefront_manage_page.tscn/.gd`：声明实时效率、缺货提醒、最近成交和收益来源分区。
- `main_view.gd`：协调服务、应用结算、任务/成长事件、刷新与保存，不继续拥有逐商品结算算法。

## 10. 异常与降级

- 商品配方缺失：跳过该商品结算并输出明确开发期警告，不扣库存、不发金币。
- 规则结果缺失：使用配方基础售价和基础售速，同时输出开发期警告。
- 动画节点缺失：跳过对应动画，真实结算保持成功。
- 商品节点在动画前被刷新：改从商品原锚点或橱窗中心播放金额与金币。
- 玩家正在拖拽：不抢焦点；允许将表现缩短或延后，但不延后经济入账。
- 同一商品重复进入结算计划：按 `recipe_id + cycle_ready_at` 去重，防止重复入账。
- 库存不足：实际销量取计划数量与当前库存的较小值，禁止负库存。

## 11. 测试与验收

实施必须使用测试先行的红—绿—重构流程。

### 11.1 新增自检

`tests/showcase_auto_sale_service_self_check.gd`：

- 两件商品拥有不同售速时独立成交。
- 同一帧多件到期时全部进入计划且顺序稳定。
- 单次到期只扣一份库存并只发一次收益。
- 售罄后商品形状保留并进入缺货状态。
- 同款补货恢复原位循环，不重建摆放。
- 移动、旋转后完成比例保持一致。
- 新售速正确换算剩余时间。
- 离线销量受库存约束。
- 离线聚合收益与逐笔计算合计一致。
- 系统时间倒退和零周期得到安全结果。

`tests/showcase_coin_feedback_self_check.gd`：

### 11.3 验收标准

- 任意两件商品能在同一橱窗中以不同节奏独立售卖。
- 每次成交都能明确看出“哪件商品赚了多少钱，金币去了哪里”。
- 同一帧多笔成交不会丢单、重复入账或形成负库存。
- 缺货不会破坏玩家已构筑的橱窗布局。
- 移动与旋转不会惩罚性清空售卖进度。
- 离线收益严格受时间、售速和橱窗库存约束。
- 删除集中收银后，玩家无需额外点击即可获得全部收益。
- 满橱窗连续成交时仍可拖拽、旋转、补货和切换右侧页面。
- 库存名称与采购小票功能保持可用。
