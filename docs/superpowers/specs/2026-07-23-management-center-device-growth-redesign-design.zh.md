# 经营中心与设备培养页面重构设计

## 1. 背景

`project-rest-new` 当前通过右下工作台启动栏的“橱窗经营”入口打开全局弹窗。弹窗在同一屏同时展示当前构筑、组合加成、本轮预估、产品收益率、道具、主题、特殊挑战、最近营业报告和橱窗扩建，信息数量仍然过多，阅读顺序和操作主次不清晰。

设备培养目前又以 `DeviceGrowthBar` 的形式固定在研发页输入区下方。设备成长会由研发、手动制作和自动化制作共同推进，却只在研发页提供总览入口，容易被理解为研发附属功能。

本设计把右下入口升级为面向全店的“经营中心”，以三个顶层页签重新划分现有经营内容，并将设备培养迁入独立页签。迁移不是把设备铭牌追加到现有长页面，而是同时删除研发页常驻铭牌和橱窗经营的一屏堆叠结构。

## 2. 已确认方向

1. 玩家可见名称从“橱窗经营”改为“经营中心”。
2. 经营中心使用三个顶层页签：
   - 经营总览；
   - 橱窗策略；
   - 设备培养。
3. 经营总览不展示设备摘要、设备进度或设备升级提醒。
4. 有设备满足全部升级条件时，设备培养页签显示动态提示“`x 可升级`”；数量为零时隐藏提示。
5. 设备详情、升级条件和升级操作直接在设备培养页签内完成，不在经营中心弹窗上继续叠加原右侧培养抽屉。
6. 三个页签切换时，经营中心弹窗的尺寸和位置保持不变。

## 3. 设计目标

1. 把设备培养从研发语境中分离出来，明确为全局经营成长系统。
2. 让经营中心每个页签只承担一种清晰职责，消除跨模块信息混排。
3. 保留当前构筑判断、本轮预测、橱窗策略、挑战、报告、扩建和设备升级能力，不改变业务结果。
4. 在 1920×1080 基准画面内完成一屏布局，避免页面级长滚动和页签切换导致的外框拉伸。
5. 保留现有教程、任务、功能解锁和弹窗路由的内部契约，降低与本次视觉重构无关的改动范围。
6. 对锁定、条件不足、可升级、满级和升级成功提供明确可见反馈。

## 4. 非目标

本次不包含以下内容：

- 不修改设备五级规则、使用次数、金币费用、配方培养上限或名作经验加成。
- 不修改橱窗组合加成、道具、主题、挑战、扩建、经营预测或营业结算规则。
- 不增加新的设备类型，不让研磨机参与成品设备培养。
- 不增加新的存档字段，不编写存档迁移。
- 不改变左侧橱窗场景、构筑拖放、营业按钮、构筑规则按钮或轮次环境栏。
- 不把经营中心扩展为采购、产出、库存、任务或图鉴的总入口。
- 不在经营总览恢复已经删除的本轮成交、当前加成、最近成交信息或补货提示面板。

## 5. 名称与路由边界

### 5.1 玩家可见名称

- 右下工作台启动栏按钮：`橱窗经营` → `经营中心`。
- 全局弹窗标题：`橱窗经营` → `经营中心`。
- 教程、任务和提示文字中面向玩家的“橱窗经营”按新语义改为“经营中心”；若句子明确描述橱窗操作，则继续使用“橱窗”。

### 5.2 内部标识保持不变

现有内部页面和功能标识继续使用 `storefront_manage`，包括但不限于：

- `global_popup_mode == "storefront_manage"`；
- `_show_page("storefront_manage")`；
- 核心功能解锁 ID；
- 教程和任务目的地；
- 现有自检中的路由断言。

本次只改变玩家可见名称和页面承载结构，不进行无收益的全局内部重命名。

## 6. 经营中心共用外框

### 6.1 外框结构

经营中心继续使用现有全局弹窗系统和统一外框：

```text
经营中心标题栏                           关闭
经营总览 | 橱窗策略 | 设备培养 [x 可升级]
------------------------------------------------
当前页签内容区
```

- 标题栏、关闭按钮、遮罩和底部工作台启动栏的切换规则沿用现有全局弹窗契约。
- 页签栏固定在标题栏下方，三个页签等宽。
- 内容区使用统一可用高度，任何页签都不得通过最小尺寸改变外框大小。
- 默认打开“经营总览”。
- 同一次弹窗打开期间切换到其他全局工作台模式，再切回经营中心时重新进入“经营总览”；不增加跨弹窗会话持久化。

### 6.2 滚动规则

- 经营中心内容区整体不使用长滚动。
- 经营总览和设备培养不出现滚动条。
- 橱窗策略只有道具、主题等天然长列表允许局部滚动。
- 局部滚动不得带动页签栏、标题栏或其他模块移动。

### 6.3 操作归属

删除当前页面底部的三枚跨模块大按钮。入口按职责就地放置：

| 入口 | 新位置 |
|---|---|
| 最近营业报告 | 经营总览“当前构筑”标题右侧 |
| 查看全部规则 | 橱窗策略“组合加成”标题右侧 |
| 特殊挑战 | 橱窗策略左下行动卡 |
| 橱窗扩建 | 橱窗策略左下行动卡 |
| 查看关联配方 | 设备培养所选设备标题右侧 |

这些入口继续打开现有目标弹窗或页面，不复制业务逻辑。

## 7. 页签一：经营总览

### 7.1 职责

经营总览回答“当前橱窗是什么状态，以及下一轮大致会发生什么”。它只展示读数和报告入口，不承载构筑规则、策略配置或设备成长。

### 7.2 垂直布局

内容区从上到下分为三块：

1. 当前构筑；
2. 本轮预估；
3. 产品收益率 Top 4。

三块均使用固定高度，保持一屏可读。

### 7.3 当前构筑

使用一行三列紧凑指标：

| 指标 | 内容 |
|---|---|
| 开放格位 | 已开放格位 / 总格位 |
| 已摆放 | 当前橱窗已摆放商品件数 |
| 可售库存 | 当前已摆放商品的可售库存总量 |

“最近营业报告”作为标题行右侧次级文字按钮，不再占据底部整行。

### 7.4 本轮预估

使用一行四列指标：

| 指标 | 内容 |
|---|---|
| 预计收益 | 当前构筑的预计金币 |
| 预计口碑 | 当前构筑的预计口碑 |
| 预计售出 | 当前构筑的预计售出件数 |
| 低库存 | 低库存商品数量；存在时使用警示色 |

低库存指标只负责概括数量和进入详情，不恢复独立“补货提示”面板。

### 7.5 产品收益率 Top 4

使用全宽紧凑表格，列出：

- 商品名称；
- 当前可售库存；
- 预计金币/秒。

表格固定四行。没有有效商品的行显示空状态，不生成额外高度。

### 7.6 明确不显示

经营总览不显示：

- 设备名称、等级、进度或升级提醒；
- 区域、口味、连通、冲突、道具或主题加成；
- 道具与主题按钮；
- 特殊挑战和扩建入口；
- 已删除的本轮成交、当前加成、最近成交或补货提示面板。

## 8. 页签二：橱窗策略

### 8.1 职责

橱窗策略回答“当前构筑为什么产生这些加成，以及玩家可以如何调整橱窗”。它集中承载规则结果、道具、主题、挑战和扩建。

### 8.2 左右布局

内容区使用左右两列：

- 左列约占 55%，展示组合加成及两项行动卡；
- 右列约占 45%，展示道具与主题选择。

### 8.3 左列

#### 组合加成

使用 `3×2` 紧凑网格展示六项现有结果：

1. 区域加成；
2. 口味组合；
3. 连通套装；
4. 冲突减损；
5. 陈列道具；
6. 橱窗主题。

正向值使用正向色，负向值使用警示色，零值保持中性。“查看全部规则”位于标题右侧。

#### 行动卡

组合加成下方使用两张等宽行动卡：

- 特殊挑战：显示当前挑战状态或“选择挑战”，点击打开现有挑战弹窗；
- 橱窗扩建：显示下一格价格或当前状态，点击进入现有扩建模式。

### 8.4 右列

右列标题为“道具与主题”，内部再分两列：

- 左列：道具列表；
- 右列：主题列表。

每个选项继续显示现有名称、效果摘要、可用状态和选择状态。道具与主题数量超出高度时，仅该列内部滚动。

### 8.5 明确不显示

橱窗策略不显示：

- 当前构筑三项摘要；
- 本轮收益、口碑、销量和低库存预测；
- 产品收益率 Top 4；
- 设备等级、进度、效果或升级入口。

## 9. 页签三：设备培养

### 9.1 职责

设备培养回答“每台成品设备成长到什么程度、下一等级提供什么效果、还缺什么条件”。设备状态总览、详情和升级在同一页完成。

### 9.2 页签升级提示

页签文字基础形式为“设备培养”。当存在满足全部升级条件的设备时显示：

```text
设备培养  [x 可升级]
```

`x` 的统计规则：

1. 设备显式支持成品设备成长；
2. 设备已经解锁；
3. 设备未满级；
4. 当前有效使用次数达到下一级要求；
5. 当前金币达到升级费用；
6. `device_growth_quote()` 的 `can_upgrade` 为真。

数量为零时完全隐藏提示，不显示“0 可升级”。升级成功、金币变化、设备使用次数变化或设备解锁后立即刷新计数。

### 9.3 设备选择区

内容区顶部横向展示五台成品设备：

- 蒸煮一体圆锅；
- 烤箱；
- 冷藏柜；
- 煎烤盘；
- 搅拌机。

每张设备卡显示：

- 设备图标和名称；
- 当前等级；
- 当前有效使用次数 / 下一级要求；
- 进度条；
- 单台“可升级”标记；
- 满级徽章或锁定状态。

五个位置固定。未解锁设备保持可见但不可操作，显示解锁条件，不创建可升级状态。研磨机不出现在设备培养列表中；本页不需要用一张禁用卡重复说明其不参与培养。

默认选择第一台已解锁设备；若没有已解锁成品设备，详情区显示统一空状态。

### 9.4 设备详情区

设备选择区下方使用左右布局：

- 左侧约占 65%，展示设备效果与关联状态；
- 右侧约占 35%，展示升级事务。

#### 左侧内容

1. 所选设备名称与当前等级；
2. 当前效果；
3. 下一等级效果；
4. 关联配方阶段统计：试作、人气、招牌；
5. 等待设备条件的配方数量；
6. 成功研发次数和累计制作批次；
7. “查看关联配方”次级入口。

“查看关联配方”沿用现有按设备筛选图鉴的行为。进入图鉴前关闭经营中心；返回后不要求恢复原页签状态。

#### 右侧内容

1. 下一等级；
2. 当前有效使用次数 / 要求次数；
3. 缺少的使用次数；
4. 升级费用；
5. 缺少的金币；
6. 升级按钮。

按钮状态必须可解释：

- 条件满足：显示“升级到 Lx”并可按；
- 使用次数不足：禁用并显示仍需次数；
- 金币不足：禁用并显示仍需金币；
- 两项均不足：同时列出两项缺口；
- 已满级：显示“设备已满级”，不再提供升级操作；
- 设备锁定：显示解锁条件。

升级成功后就地刷新：

- 所选设备等级与进度；
- 当前和下一等级效果；
- 关联配方等待数量；
- 单台“可升级”标记；
- 页签“x 可升级”计数；
- 顶部金币；
- 现有结构化通知和状态反馈。

### 9.5 取消嵌套抽屉

经营中心内不再调用 `DeviceGrowthDrawer.open_for_device()`。原抽屉展示的状态迁入设备培养页签详情区，避免全局弹窗上再叠加右侧抽屉。

实现阶段可以删除抽屉实例和相关连接，也可以在确认没有其他入口依赖后移除其场景与脚本；不得保留两个并行的设备升级入口。

## 10. 研发页调整

从研发工作台移除：

```text
Root/Body/MainArea/WorkbenchPanel/ResearchWorkbench/ListRow/PrimaryList/DeviceGrowthBar
```

移除后：

- 研发输入条直接衔接研发配方列表区域；
- 研发页不再显示六设备横向铭牌；
- 选择研发工具仍然使用现有设备选择控件；
- 研发成功、研发失败线索和设备有效使用次数仍按原业务规则更新；
- 研发页可以在与当前操作直接相关的反馈中提及设备效果，但不恢复全局设备总览。

## 11. 场景与脚本职责

### 11.1 场景优先

稳定页面结构放在 `.tscn`：

- 经营中心标题与页签栏；
- 三个页签内容容器；
- 经营总览各指标和 Top 4 表格；
- 橱窗策略左右列、加成网格和行动卡；
- 设备选择区、设备详情区和升级区；
- 局部滚动容器。

脚本只负责数据绑定、状态刷新、信号连接和页面切换，不在运行时拼装整个稳定页面。

### 11.2 推荐组件边界

经营中心继续挂载在现有：

```text
GlobalOverlayLayer/OverlayFrame/OverlayModeStack/StorefrontManageOverlay
```

可将 `StorefrontManagePanel` 重构为以下语义结构：

```text
StorefrontManagePanel
├── ManagementCenterTabs
├── ManagementCenterPages
│   ├── OverviewPage
│   ├── ShowcaseStrategyPage
│   └── DeviceGrowthPage
```

设备培养页可以复用 `DeviceGrowthService`、`GameState.get_device_growth()` 和 `GameState.device_growth_quote()`，但不复制等级表或升级条件。

### 11.3 主协调脚本

`scripts/main_view.gd` 继续负责：

- 打开和关闭 `storefront_manage` 全局模式；
- 切换三个经营中心页签；
- 刷新经营总览和橱窗策略现有数据；
- 统计可升级设备数量；
- 接收设备选择、升级和查看关联配方信号；
- 升级成功后的全局刷新与通知；
- 保持教程和任务路由契约。

具体页签脚本只接收状态和目录数据，不拥有存档或业务规则。

## 12. 状态与数据

本次不增加存档字段。所有展示值继续来自现有来源：

| 页面 | 数据来源 |
|---|---|
| 经营总览 | 当前橱窗布局、库存、经营预测和营业报告服务 |
| 橱窗策略 | 组合加成、道具、主题、挑战和扩建现有状态 |
| 设备培养 | `DeviceGrowthService`、`GameState.device_growth`、配方成长状态和目录 |

当前页签和当前选中设备只作为运行时 UI 状态，不写入存档。

## 13. 可见反馈与交互规则

1. 页签按钮必须支持鼠标和键盘焦点。
2. 页签的选中状态不能只依赖颜色，应同时使用边框、底色或下划线差异。
3. “x 可升级”使用独立徽标，不把数字拼进难以解析的长标题。
4. 所有禁用升级按钮都必须同时显示禁用原因。
5. 锁定设备必须显示解锁原因，不能只变灰。
6. 低库存、负向加成和金币不足使用警示色，但不把正常零值误判为错误。
7. 经营中心内打开现有二级弹窗时，关闭二级弹窗后回到原页签；进入图鉴等其他全局模式时按现有模式切换规则关闭经营中心。
8. 点击遮罩和关闭按钮沿用统一全局弹窗关闭规则，不新增页面私有例外。

## 14. 布局稳定性

1. 继续使用项目既定的 1920×1080 基准和 `canvas_items + keep` 展示策略。
2. 非 16:9 窗口保持完整画面并留黑边，不通过经营中心改动引入拉伸或裁切。
3. 三个页签的根容器使用相同最小尺寸和伸展策略。
4. 指标卡使用紧凑样式，不能复用会增加内容边距并撑大页面的主面板样式。
5. 页签切换前后必须测量并确认：
   - `OverlayFrame` 尺寸不变；
   - 经营中心外框尺寸不变；
   - 左侧橱窗与右侧工作台的基础分区不变；
   - 底部启动栏位置不变。

## 15. 兼容性与迁移

- 不修改存档结构，现有 `device_growth` 数据直接使用。
- 不修改设备和配方 ID。
- 不修改 `storefront_manage` 内部路由 ID。
- 不改变教程要求玩家真实点击经营中心入口的判定方式，只更新目标按钮的玩家可见文字。
- 不改变任务跳转到 `storefront_manage` 的目的地。

## 16. 验证方案

### 16.1 场景结构

### 16.2 内容边界

验证：

- 经营总览只包含当前构筑、本轮预估、Top 4 和最近报告入口；
- 橱窗策略只包含组合加成、规则、道具、主题、挑战和扩建；

- 当前底部三枚跨模块大按钮已经移除。

### 16.3 设备升级提示

至少覆盖：

1. 没有可升级设备：页签不显示徽标；
2. 一台可升级：显示“1 可升级”；
3. 多台可升级：显示正确数量；
4. 使用次数足够但金币不足：不计入；
5. 金币足够但使用次数不足：不计入；
6. 锁定设备：不计入；
7. 满级设备：不计入；
8. 研磨机：不计入；
9. 升级成功后数量立即减少或重新计算。

### 16.4 真实交互路径

验证真实鼠标按下、释放和页面层级：

- 点击右下“经营中心”打开弹窗；

- 点击设备卡刷新详情；
- 条件不足时升级按钮不可执行且原因可见；
- 条件满足时升级成功、扣除金币并刷新全部相关显示；

## 17. 验收标准

满足以下条件即视为设计实现完成：

1. 玩家通过“经营中心”全局入口打开固定尺寸弹窗。
2. 经营总览、橱窗策略和设备培养职责互不混排。
3. 经营总览完全不展示设备信息。
4. 设备培养页签只在存在可升级设备时显示正确的“x 可升级”徽标。
5. 五台成品设备可在同一页查看成长状态，锁定、条件不足、可升级和满级状态均有明确反馈。
6. 设备升级不需要打开嵌套培养抽屉。
7. 研发页不再常驻设备培养铭牌。
8. 报告、规则、挑战、扩建和关联配方入口均位于所属页签。
9. 页签切换不改变弹窗、橱窗、工作台或启动栏的几何尺寸。
10. 现有设备成长、经营、教程、任务、功能解锁和存档规则保持不变。
