# 任务解锁与奖励领取分离设计

## 1. 目标

所有任务采用统一规则：任务条件达成时立即完成并应用进度解锁；金币、口碑、食材和工具等奖励仍由玩家点击“领取奖励”获得。

玩家不领取奖励也能使用已经解锁的设备、进入已经开放的店铺等级，并看到后续任务。领取动作只影响经济资源，不扣留主线内容。

## 2. 奖励分类

现有 `reward` 字典按字段语义分为两组，不新增平行任务系统。

完成时自动生效的进度效果：

- `unlock_devices`：设备解锁。
- `unlock_tools`：工具类型解锁。
- `set_level`：店铺等级开放。
- 任务前置链：由 `completed_tasks` 直接开放。

点击领取时发放的经济奖励：

- `coins`：金币。
- `reputation`：口碑。
- `ingredients`：食材数量。
- `tools`：工具物品数量。
- 未来若增加 `experience`，默认归入领取奖励，不参与本次实现。

金币和口碑可能影响后续资源门槛。玩家不领取时可能更晚满足升级条件，但已经完成任务对应的功能、等级和后续任务不会被撤回或隐藏。

## 3. 状态流转

任务事件满足条件后按以下顺序执行：

1. 将任务加入 `completed_tasks`。
2. 应用 `unlock_devices`、`unlock_tools` 和 `set_level`。
3. 开放以该任务为前置条件且等级条件满足的后续任务。
4. 写入任务完成日志。
5. 将完成通知加入 `pending_notifications`，通知列出已经生效的解锁，并说明经济奖励可领取。
6. 若任务包含经济奖励，则保持未领取状态，并在任务按钮和任务页显示可领取提示。

如果某个未来任务没有任何经济奖励，完成后直接加入 `claimed_tasks` 并归档，不显示空的领取按钮。

玩家点击“领取奖励”后：

1. 校验任务已完成且尚未领取。
2. 发放 `coins`、`reputation`、`ingredients` 和 `tools`。
3. 将任务加入 `claimed_tasks`。
4. 刷新资源栏、任务按钮和任务页。
5. 展示奖励领取通知。

重复任务事件不得重复应用进度效果，重复点击领取不得重复发放经济奖励。

## 4. 每个任务的领取动作

每个正式主线任务都应具有至少一项可领取的经济奖励，避免出现只有按钮、没有实际收益的空领取。

现有只包含解锁或升级效果的任务补充以下金币奖励：

| 任务 | 自动生效 | 点击领取 |
| --- | --- | ---: |
| `main_l0_harvest_rice` | 解锁圆锅 | 金币 20 |
| `main_l0_first_product` | 解锁研磨机 | 金币 30 |
| `main_l0_list_product` | 开放 Lv.1 | 金币 50 |
| `main_l1_upgrade` | 开放 Lv.2 | 金币 60 |
| `main_l2_upgrade` | 开放 Lv.3 | 金币 80 |
| `main_l3_upgrade` | 开放 Lv.4 | 金币 100 |
| `main_l4_upgrade` | 开放 Lv.5 | 金币 150 |
| `main_l5_mvp_complete` | 完成 MVP 主线 | 金币 300 |

其他主线任务继续使用现有金币、口碑、食材或工具奖励，不调整数值。

## 5. 开发期存档策略

- 当前游戏仍处于开发阶段，本次不实现旧存档迁移、历史奖励补发或版本兼容分支。
- 规则变更后删除现有开发存档，以新游戏状态验证新的任务流程。
- 新规则产生的存档继续保存 `completed_tasks` 与 `claimed_tasks`，并保证重复事件和重复领取不会重复发奖。

## 6. 界面规则

任务页：

- 保留“可领取”筛选、数量和“领取奖励”按钮。
- 进行中任务分别展示“完成后解锁”和“可领取奖励”。
- 已完成未领取任务显示“解锁已生效”和可领取的经济奖励。
- 已领取任务显示“已完成 / 已领取”。
- 不把已经自动生效的设备或等级解锁再次描述为“点击领取后获得”。

顶部任务按钮：

- 有经济奖励待领取时继续显示数量标记。
- 任务完成但没有待领取奖励时不显示领取标记。

通知：

- 任务完成通知说明“已解锁：……”和“奖励待领取：……”。
- 领取通知只列出本次实际发放的金币、口碑、食材和工具。
- 店铺等级在任务完成时变化，等级提升通知也在完成时进入现有通知队列。

## 7. 服务边界

- `TaskService` 负责判断任务完成、拆分进度效果与经济奖励、保证两段流程幂等，并生成通知。
- `GameState` 保存 `completed_tasks` 与 `claimed_tasks`，不承担旧存档迁移。
- `main_view.gd` 继续负责领取按钮、资源栏刷新、任务按钮标记和任务页展示，不承载任务规则。
- Lv.1-Lv.5 的任务条件、前置链和现有奖励数值保持不变；只为没有经济奖励的正式主线任务补充表中金币奖励。

## 8. 验收标准

- 完成“收获第 1 批水稻”后，圆锅立即解锁，金币 20 保持待领取。
- 不领取金币 20 也能看到并完成下一项主线任务。
- 完成升级任务后，店铺等级立即变化，对应等级任务可正常出现，补充金币仍需领取。
- 领取奖励只改变金币、口碑、食材或工具数量，不再触发设备、工具类型或等级解锁。
- 每项正式主线任务完成后都有实际可领取内容。
- 顶部任务按钮准确标记待领取经济奖励数量。
- 新游戏保存并重新加载后，已完成、待领取和已领取状态保持一致。
- 任务主线自检、MVP 自检和组件契约自检全部通过。

## 9. 非目标

- 不新增店铺经验值或经验等级曲线。
- 不改变任务条件和前置链。
- 不新增奖励二选一或库存溢出处理。
