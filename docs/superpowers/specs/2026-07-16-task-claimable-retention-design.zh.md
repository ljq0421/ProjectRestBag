# 已完成任务领奖前保留设计

## 背景

任务服务已经在快照中提供完整的 `claimable` 任务数据，包括任务标题、类型、奖励和完成状态；但任务页的“当前目标”和“支线任务”列表只展示仍在进行的任务。任务完成后会立即从原列表消失，页面底部只显示“一键领取奖励（N 项）”。玩家因此知道有奖励待领取，却无法直接确认完成了哪些任务、每项奖励是什么。

本次调整不恢复“待领取”页签，也不增加已领取历史页。目标是让刚完成的任务继续留在玩家原本查看它的位置，直到奖励实际领取。

## 目标

- 已完成但奖励尚未领取的任务保留在原分类列表中。
- 玩家能在列表和详情中看到任务名称、完成状态与奖励内容。
- 单项领取或一键领取后，相应任务立即从列表消失。
- 完成任务不阻塞后续任务开放；待领取任务与下一项进行中任务可以同时出现。
- 保持“当前目标 / 支线任务”两个页签，不新增分类。

## 非目标

- 不展示已经领取过奖励的历史任务。
- 不增加任务完成时间、历史筛选或任务日志。
- 不修改任务奖励、完成条件、前置关系或存档结构。
- 不要求玩家领奖后才能继续主线或接受下一项经营合同。

## 分类规则

待领取任务沿用任务原类型，不创建新的展示分类：

- `tutorial`、`growth`、`contract`：保留在“当前目标”。
- `daily`、`feature`：保留在“支线任务”。

没有可领取奖励、已在完成时自动标记为已领取的任务不需要保留。

## 列表组成与顺序

任务快照继续分别提供当前目标和支线任务，但两个列表都由两部分组成：

1. 该分类中已完成且待领取的任务。
2. 该分类中仍在进行或可选择的任务。

待领取任务排在进行中任务之前，并按完成顺序倒序排列，让刚完成的任务位于最上方。进行中任务保持现有排序。

同一个任务不能在列表中重复出现。任务完成后，原来的进行中条目由“进行中”切换为“待领取”，而不是额外复制一条。

## 列表与详情表现

待领取条目继续使用现有任务条目和详情组件，但详情组件需要补上待领取状态的动作分支：

- 列表状态显示“待领取”。
- 进度显示“已完成”。
- 选中后，详情继续展示任务说明、全部完成标准和奖励内容。
- 主操作按钮在 `status == completed` 且 `claim_status == claimable` 时显示“领取奖励”，调用主视图现有的单项领取入口；该状态不再调用“前往”。
- 任务刚完成时保留原 `selected_task_id`，刷新后仍停留在该任务详情，方便立即核对和领取。

若玩家重新打开任务页且没有有效选择，默认选中该分类最上方的待领取任务；没有待领取任务时，维持现有默认选择。

## 后续任务开放

任务完成逻辑与前置关系保持不变。任务进入待领取状态后：

- 下一项主线或成长目标照常开放。
- 新目标显示在待领取任务下方。
- “当前目标”摘要只统计实际进行中的目标槽位，不把待领取任务算作第二个当前目标。
- “支线”摘要只统计仍在进行的支线；所有未领奖任务统一由“待领取 N”统计。

这样列表可以同时出现“待领取任务 + 下一项进行中任务”，但顶部摘要仍能区分工作量与领奖数量。

## 领取后的状态变化

### 单项领取

1. 玩家在待领取任务详情点击“领取奖励”。
2. 现有奖励结算逻辑执行。
3. 任务页重新生成快照。
4. 已领取任务从原分类列表消失。
5. 选择自动移动到该分类的下一条任务；若列表为空，则显示现有空状态。

### 一键领取

1. 玩家点击现有“一键领取奖励（N 项）”。
2. 所有待领取奖励按现有逻辑汇总发放。
3. 所有已领取任务同时从两个分类列表消失。
4. 页面刷新并显示现有汇总通知。

一键领取按钮继续作为快捷操作存在，但不再是玩家识别待领取任务的唯一入口。

## 边界情况

- 日常任务跨日重置时沿用现有清理规则；上一日未领取的日常奖励不会因为本次展示调整获得额外保留语义。
- 可重复经营合同在奖励未领取前继续保持当前的“不可重复接受”约束；领取后从列表消失并恢复后续可选状态。
- 若奖励配置为空，任务继续沿用现有自动领取处理，不生成永久停留的无奖励条目。
- 任务读取、页面刷新和重复打开不会改变领取状态，也不会重复发放奖励。

## 验证

- 完成一项主线任务后，它以“待领取”状态保留在“当前目标”，下一项任务同时显示在其下方。
- 完成一项日常任务后，它保留在“支线任务”，且不与进行中的支线重复。
- 待领取任务详情显示完成标准、奖励和单项领取按钮，不显示“前往”。
- 单项领取后，仅对应任务消失，其他待领取任务仍保留。
- 一键领取后，所有待领取任务消失，奖励只发放一次。
- 顶部“当前目标 / 支线 / 待领取”计数分别保持正确。
- 任务快照、任务面板、单项领取和批量领取的聚焦 Godot 自检通过。
