# 制作队列双列完成库存设计

日期：2026-07-25  
目标项目：`project-rest-new`

## 1. 目标

在制作工作台总宽保持 `820px` 的前提下，将完成且仍有库存的成品从制作配方列表中独立出来：

- 左侧窄列仅展示可拖拽上架的完成成品。
- 右侧继续展示可制作、制作中和缺材料的中间食材及成品配方。
- 完成库存清零后，配方离开左列，并根据当时材料状态重新进入右侧对应位置。
- 缺材料只通过数量表达，不使用红色背景或红色文字。
- 成品格使用 `128×128` 基础配方图标缩小至 `68×68px`，消除当前放大 `32×32` action 图标造成的模糊。
- 本轮不实现配方标签 Tab。

## 2. 已确认的状态边界

### 2.1 完成成品

一个配方同时满足以下条件时进入左列：

1. 存在该配方的制作完成记录；
2. 对应成品库存数量大于 `0`。

完成成品只在左列出现，不在右侧重复显示，也不参与“制作全部”。

当完成库存变为 `0` 时：

1. 清理既有完成记录；
2. 从左列移除该成品；
3. 重新计算材料状态；
4. 将配方放入右侧可制作或缺材料位置。

因此，完成库存未清空期间，玩家先处理该完成库存；该配方不会同时提供新的“制作”按钮。

### 2.2 制作中配方

制作中的配方继续显示在右侧上段，不新增第四个可见分区：

- 显示整行进度和剩余倒计时；
- 操作按钮处于制作中/禁用状态；
- 即使开始制作后材料已被扣除，也不把该行移动到缺材料段；
- 同一配方仍最多只有 `1` 批在制，不同配方继续并行。

### 2.3 中间食材

中间食材没有完成库存左列状态，始终留在右侧：

- 可制作或制作中的中间食材位于右侧上段；
- 缺材料的中间食材位于右侧下段；
- 上段内部按加工耗时升序、解锁顺序打破平局；
- 下段使用相同排序。

## 3. 布局

### 3.1 总体尺寸

工作台继续保持：

- 总宽：`820px`
- 总高：`858px`
- 顶部操作区：`820×54px`
- 顶部与内容区间距：`10px`
- 下方内容区：`820×794px`

顶部搜索、批量操作和自动排程仍横跨整个工作台。

下方内容区拆分为：

| 区域 | 宽度 | 说明 |
|---|---:|---|
| 完成成品栏 | `104px` | 单列 `68×68px` 成品格，水平居中 |
| 列间距 | `8px` | 固定留白 |
| 右侧制作列表 | `708px` | 可制作/制作中在上，缺材料在下 |

左右两列分别拥有自己的垂直滚动位置，互不影响。

### 3.2 左侧完成成品栏

- 不显示“制作完毕”“成品”等可见分类标题。
- 每格固定为 `68×68px`，单列排列，格间距 `6px`。
- 成品格在 `104px` 列中水平居中，左右各保留约 `18px`。
- 右上角库存角标只显示数字，例如 `3`，不显示 `×3`。
- 成品格保留既有 `inventory_product` 拖拽上架协议。
- 拖拽失败不扣库存、不删除完成记录。
- 成功上架最后一个库存后，完成记录清理并触发双列重新归类。
- 左列按照售价从高到低排序；售价相同时按配方配置/解锁顺序排序。

### 3.3 左侧悬停信息

悬停提示固定显示：

```text
焦糖布丁
库存：3
售价：20
标签：奶香、甜
```

约束：

- 不显示“拖拽到橱窗上架”等操作说明。
- 库存数字不带乘号。
- 标签取自 `Catalog.RECIPES[recipe_id].tags`，保持现有标签数据，不做合并或迁移。
- 无标签时显示 `标签：无`，不省略整行，保证提示结构稳定。

### 3.4 右侧制作列表

右侧仍使用 `68px` 横向整行进度条，信息顺序不变：

1. `68×68px` 产品图标；
2. 配方/加工品名称；
3. 材料格；
4. 闹钟图标和秒数；
5. 金币图标和售价；
6. 制作、补货或制作中操作。

为了在 `708px` 宽度内保留材料区域，不缩窄当前约 `300px` 的材料栏，而是压缩其他固定列：

| 信息 | 目标宽度 |
|---|---:|
| 产品图标 | `68px` |
| 名称 | `90px` |
| 材料区域 | `300px` |
| 倒计时 | `60px` |
| 售价 | `60px` |
| 操作按钮 | `76px` |
| 单项间距 | `4px` |

实际运行时还需计入右侧滚动条；允许在不减少材料区域的前提下微调名称、元信息和按钮各 `1–2px`，但产品图标必须保持 `68px`。

## 4. 右侧分组与排序

页面不显示“可制作”“缺材料”等分组文字，只通过连续顺序表达状态。

从上至下：

1. 可制作或制作中的中间食材；
2. 可制作或制作中的成品配方；
3. 缺材料的中间食材；
4. 缺材料的成品配方。

完成库存大于 `0` 的成品不参加上述排序。

排序规则：

- 中间食材：加工耗时升序，相同时按解锁/配置顺序；
- 成品配方：售价降序，相同时按解锁/配置顺序。

## 5. 缺材料样式

缺材料格保留材料图标、材料名称和数量，但取消警示红色：

- 使用与普通材料格一致的中性色背景、边框和文字颜色；
- 数字使用 `当前数量/需要数量`，例如 `芒果 0/1`；
- 不再依靠颜色表达缺少状态；
- 缺少原因仍保留在按钮禁用原因或补货逻辑中。

## 6. 图标清晰度修复

### 6.1 已确认原因

当前制作行通过 `RecipeIconService` 的 `action` surface 取得 `32×32` PNG，再在 `68px` 成品格中放大到最多 `62px`。导入配置使用无损纹理模式，因此模糊的主要原因是低分辨率图标被放大，而不是有损压缩。

### 6.2 新显示方式

- 制作队列的成品图标改用 `base` surface 的 `128×128` 基础图。
- 将基础图缩小到完整 `68×68px` 画布。
- 不使用 Button 自带图标布局，避免主题边框和内容边距继续缩小图像。
- 在拖拽按钮内部使用铺满格子的 `TextureRect`：
  - 尺寸 `68×68px`；
  - 保持长宽比；
  - 居中显示；
  - 鼠标事件穿透给外层拖拽按钮。
- 库存角标叠加在 TextureRect 上方。

如果源图自身包含透明留白，菜品主体可能小于 `68px`，但显示画布必须完整占据 `68×68px`，不得再次设置为 `62px`。

## 7. 搜索与批量操作

### 7.1 搜索

顶部搜索同时作用于左右两列：

- 左列按成品名称、配方 ID 和标签匹配；
- 右列继续按名称、材料名称、配方 ID 和标签匹配；
- 搜索不会改变完成库存归属，只控制当前可见性。

### 7.2 批量操作

- “制作全部”只处理右侧当前可制作且不在制作中的配方；
- 左侧完成成品不参与“制作全部”；
- “一键补货”只处理右侧缺材料配方；
- “上架全部”继续处理所有可上架完成库存，不受左右列滚动位置影响；
- 标签 Tab 本轮不实现，也不进入批量操作过滤条件。

## 8. 数据与刷新流程

结构快照应为每个配方计算唯一归属：

```text
完成记录存在且库存 > 0
    → 左侧完成成品
否则，制作中或材料充足
    → 右侧上段
否则
    → 右侧下段
```

以下事件触发结构刷新：

- 配方制作完成；
- 完成成品成功上架；
- 完成库存被其他系统消耗；
- 材料库存变化；
- 配方或设备解锁；
- 搜索文本变化。

每帧/每秒的轻量刷新只更新：

- 右侧在制行进度宽度；
- 剩余秒数；
- 操作状态。

完成、库存清零或归属变化必须触发结构刷新，不能只调用运行时刷新。

## 9. 场景与脚本边界

遵循 scene-first 结构：

- `production_workbench.tscn` 声明顶部、双列容器、两个滚动区和空状态。
- `production_queue_recipe_row.tscn` 声明右侧 `68px` 制作行。
- 新增独立的完成成品格场景，声明 `68×68px` 图标、库存角标和拖拽按钮。
- 脚本只负责数据绑定、排序、筛选、进度刷新、Tooltip 和信号转发。
- 不在脚本中临时搭建双列主结构。

## 10. 空状态

- 左列无完成库存时保持窄列空间，不折叠，不改变右侧宽度。
- 左列为空时不显示文字空状态，保持干净。
- 右侧无匹配项时，在右侧显示现有空状态提示。
- 搜索导致左右两列均为空时，只在右侧显示“没有匹配的配方”。

## 11. 验收标准

1. 工作台运行时总宽仍为 `820px`。
2. 左列 `104px`、间距 `8px`、右列 `708px`。
3. 左侧成品格和右侧制作行产品图标均为 `68×68px`。
4. 左列只包含完成记录存在且库存大于 `0` 的成品。
5. 左列库存角标只显示数字。
6. 左侧 Tooltip 只包含名称、库存、售价和标签。
7. 完成库存清零后，配方从左侧进入右侧正确分组。
8. 左侧配方不在右侧重复，也不参与“制作全部”。
9. 右侧材料区域保持约 `300px`。
10. 缺材料格不使用红色，仍显示材料名称、图标和 `当前/需要` 数量。
11. 制作队列成品图标来自 `128×128` base 图，不再放大 `32×32` action 图。
12. 完成库存拖拽上架、失败回滚和最后库存清理行为保持可用。
13. 本轮没有标签 Tab。
