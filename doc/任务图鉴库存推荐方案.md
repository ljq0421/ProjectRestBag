**推荐方案**
采用“统一全局覆盖层”重构，而不是继续让三类入口走三套 UI：

- 顶部按钮：`任务` / `库存` / `图鉴` 保持在 [Main.tscn](D:/Project/ProjectRest/project-rest/scenes/Main.tscn:57) 顶栏。
- 点击后：打开同一个 `GlobalOverlayLayer`，背景主界面压暗，主橱窗和右侧分页仍可见但不可交互。
- 三个场景分别是 `TaskOverlay`、`InventoryOverlay`、`CatalogOverlay`，由 `global_popup_mode` 控制互斥显示。
- 先把现有 `AcceptDialog` 式任务/图鉴弹窗迁走；库存已有独立 [InventoryOverlay](D:/Project/ProjectRest/project-rest/scenes/Main.tscn:374)，可以升级为统一覆盖层的一员。

**方案选型**
推荐：`PanelContainer` 覆盖层方案。

优点是和当前 `InventoryOverlay`、`GlobalPopupBackdrop` 基础最接近，适合直接编辑 `.tscn`，风险小。不要继续用 `AcceptDialog` 做任务/图鉴，因为 1920x1080 的信息密度、左中右区域、底部奖励条都不适合系统弹窗。

备选 1：三个完全独立场景文件 `TaskOverlay.tscn` / `InventoryOverlay.tscn` / `CatalogOverlay.tscn`。结构更干净，但当前项目主 UI 主要集中在 `Main.tscn + main_view.gd`，第一轮拆出去会增加绑定成本。

备选 2：继续复用 `GlobalPopup`。最快，但会卡在布局、拖拽、背景关闭、详情面板这些能力上，不建议。

`TaskOverlay`：

`InventoryOverlay`：
顶部容量、搜索/排序、分类 `全部 / 食材 / 成品 / 种子 / 工具 / 低库存`；中间 6x5 或 7x4 库存卡；右侧低库存、满仓、可补货摘要；底部 `一键补货 / 批量上架 / 出售多余 / 整理库存`。第一版按钮可以先只做可用动作和明确禁用提示，避免同时引入自动经济规则。
