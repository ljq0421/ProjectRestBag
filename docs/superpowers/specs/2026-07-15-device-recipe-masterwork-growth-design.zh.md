# 设备五级与配方名作成长设计

## 1. 背景

`project-rest-new` 当前拥有 166 道售卖配方，并已经实现以下配方成长基础：

- `试作品 → 稳定款 → 人气款 → 招牌款` 四阶段；
- 累计制作、真实售卖和正向橱窗邻接计数；
- 基于配方标签与展示形状生成候选特性；
- 人气款与招牌款的玩家手动特性选择；
- 166 道配方的稳定款、人气款、招牌款展示差量配置；
- 手动即时制作、批量制作和自动化生产入口。

本设计不替换上述系统，而是在其上增加两条互补成长线：

1. 五台成品设备各自拥有固定五级成长，用于开放配方阶段上限和降低培养成本；
2. 配方成为招牌款并完成两次特性选择后，开启名作 Lv.1—Lv.10 的长期荣誉成长。

设备等级回答“厨房对这一类制作有多熟练”，四阶段回答“单道配方成熟到什么程度”，标签/形状特性回答“配方在橱窗里如何发挥”，名作等级回答“玩家对这道招牌配方长期投入了多少”。四者必须保持职责分离。

## 2. 设计目标

1. 让五台成品设备拥有清晰、有限、可完成的成长路线。
2. 让设备升级能够影响配方成长，但不能替代单道配方自己的制作、售卖和邻接培养。
3. 保留 `project-rest-new` 已有的标签、形状、候选特性和正向邻接核心。
4. 让招牌款之后仍有可持续目标，但不再无限叠加经济数值。
5. 允许全部 166 道配方最终达到名作 Lv.10，不设置人工数量上限。
6. 保持成品即时制作，不为了设备成长引入新的加工倒计时。
7. 所有升级缺口、等待原因和成长结果必须在玩家操作位置可见。

## 3. 明确不采用的方向

### 3.1 不增加四类经营专精

不增加“走量、精品、常备、需求”四类专精。`project-rest-new` 已经使用标签、形状、候选特性和橱窗邻接定义配方用途，再增加第二套经营定位会造成语义与数值重复。

### 3.2 不把四阶段替换为无限等级

试作品、稳定款、人气款、招牌款继续承担功能解锁。名作等级只在招牌款之后出现，不从研发成功时就向玩家展示 166 条等级经验线。

### 3.3 不增加经济型设备奖励

设备升级不增加商品产量，不返还材料，不提高售价，不提高售速，也不降低采购成本。设备只改善研发线索、配方培养效率和阶段上限。

### 3.4 不增加成品加工时间

手动成品制作继续即时完成。现有自动化队列保持原有内部运行方式，本设计不增加面向玩家的成品制作倒计时，也不提供“制作时间 -5%”一类只有部分入口能感受到的效果。

## 4. 参与成长的设备

只有拥有直属售卖配方的五台设备参与五级成长：

| 设备 ID | 名称 | 是否参与 |
|---|---|---|
| `round_pot` | 蒸煮一体的圆锅 | 是 |
| `oven` | 烤箱 | 是 |
| `chiller` | 冷藏柜 | 是 |
| `griddle` | 煎烤盘 | 是 |
| `mixer` | 搅拌机 | 是 |
| `grinder` | 研磨机 | 否 |

研磨机目前只承担原料加工，没有 166 道售卖配方中的直属成品，因此不为形式统一而添加无意义的配方阶段、名作经验或经济奖励。研发制作页选择研磨机时，明确显示“加工设备，不参与成品设备成长”。未来只有在研磨机出现直属售卖配方时，才另行评估接入。

圆锅虽然可以加工酸奶，但酸奶加工不计入圆锅成长；圆锅只从直属售卖配方的成功研发和制作中获得有效使用次数。

## 5. 设备五级

五台成品设备共用一张固定等级表，每台独立保存、独立累计、独立支付金币。

| 等级 | 累计有效使用次数 | 本次升级金币 | 效果 |
|---:|---:|---:|---|
| L1 | 0 | 0 | 对应配方最高可达到稳定款 |
| L2 | 10 | 120 | 研发失败时线索一次提升 2 级而不是 1 级 |
| L3 | 30 | 360 | 对应配方最高可达到人气款 |
| L4 | 70 | 900 | 人气款晋升招牌款的制作培养贡献 +20%；名作制作经验 +20% |
| L5 | 150 | 2200 | 对应配方最高可达到招牌款；获得设备满级徽章 |

表中次数为累计门槛，升级不会消耗或清零 `use_count`。金币为每次升级单独支付的费用。

设备成长只在设备已经解锁后显示和生效。设备解锁时初始化为 L1、累计使用 0；未解锁设备不提前创建可操作的成长入口，也不向配方提供阶段上限。

- 单台设备从 L1 升至 L5 共支付 3,580 金币；
- 五台成品设备全部满级共需要累计 750 次有效使用；
- 五台成品设备全部满级共支付 17,900 金币；
- 每次操作只提升一级，即使玩家同时满足多个后续等级也要逐级确认。

设备 L5 后不再增加等级或永久数值，只显示满级徽章、累计成功研发数和累计制作批次作为荣誉记录。

## 6. 设备有效使用次数

设备成长按“成功批次”计数，不按商品产量计数。

### 6.1 增加次数

| 行为 | 设备有效使用 |
|---|---:|
| 成功研发一道该设备的直属售卖配方 | +1 |
| 手动成功制作 1 批 | +1 |
| 手动成功制作 5 批 | +5 |
| 自动化成功完成 N 批 | +N |
| `制作全部` 中实际成功完成 N 批 | +N |

成功研发只在配方首次解锁成功后计数。已解锁配方的重复研发不会成功，也不会计数。

### 6.2 不增加次数

- 研发失败；
- 未知材料、材料不足或设备不匹配；
- 商品单批产出数量；
- 商品售卖；
- 正向邻接触发；
- 研磨、发酵等原料加工；
- 未完成或失败的自动化任务。

例如某配方单批产出 5 份商品，制作 1 批仍只给设备增加 1 次有效使用；一次制作 5 批则增加 5 次，而不是按最终商品数量增加。

## 7. L2 研发线索效果

当前研发失败会消耗本次选中的材料，并把目标配方线索提高 1 级，线索最高为 3 级。使用 L2 及以上成品设备研发失败时：

```text
线索新等级 = min(3, 线索旧等级 + 2)
```

规则如下：

- 材料仍只按当前研发失败规则消耗一次；
- 研发失败仍不给设备增加有效使用；
- 线索最高仍为 3 级；
- 设备不匹配但能够生成有效目标线索时，也使用当前所选设备的线索增量；
- 研磨机不参与设备成长，因此始终使用当前基础线索增量。

L2 改善的是探索成本，不改变配方材料、解锁等级或研发成功条件。

## 8. 四阶段与设备上限

四阶段继续使用当前阈值：

| 晋升 | 实际制作数 | 实际售卖数 | 正向邻接触发数 |
|---|---:|---:|---:|
| 试作品 → 稳定款 | 5 | 3 | 0 |
| 稳定款 → 人气款 | 15 | 10 | 0 |
| 人气款 → 招牌款 | 40 | 25 | 10 |

设备等级只增加阶段上限：

| 设备等级 | 配方阶段上限 |
|---:|---|
| L1—L2 | 稳定款 |
| L3—L4 | 人气款 |
| L5 | 招牌款 |

配方的制作、售卖和正向邻接进度在达到设备上限后继续记录，不被截断。若成长条件已经满足但设备等级不足，图鉴显示：

> 成长条件已满足，等待烤箱升级至 L3。

设备升级不会批量修改关联配方的阶段。升级后只计算有多少配方已达到条件，并发送一条汇总通知。每道配方在下一次成功制作时重新评价成长，晋升到当前全部条件允许的最高阶段。自动化成功制作同样可以触发该配方重新评价。

已达到的配方阶段不会因为设备状态变化而降低。

## 9. L4 制作培养贡献

L4 不修改试作品到稳定款、稳定款到人气款的制作阈值。它只影响人气款晋升招牌款的制作条件，以及招牌后的名作制作经验。

### 9.1 招牌款制作条件

当对应设备达到 L4 时：

```text
有效招牌制作贡献 = floor(实际制作数 × 1.2)
```

招牌款仍要求有效贡献达到 40：

| 实际制作数 | 有效贡献 | 是否满足制作条件 |
|---:|---:|---|
| 33 | 39 | 否 |
| 34 | 40 | 是 |

售卖 25 份和正向邻接 10 次必须完整完成，不受设备加成影响。UI 同时显示实际制作数和设备加成后的有效贡献，不把有效贡献伪装成库存产量。

### 9.2 不改变经济结果

制作 1 批产生的商品数量、材料消耗、任务数量、售卖库存和金币收益全部保持不变。L4 只减少培养所需的实际制作投入。

## 10. 保留标签、形状和橱窗邻接成长

本设计继续使用现有候选特性生成逻辑：

- 人气款阶段基于配方标签和通用邻接方向提供候选特性，玩家选择第 1 个；
- 招牌款阶段增加基于展示形状和招牌方向的候选特性，玩家完成第 2 个选择；
- 只有已选择特性产生效果；
- `pending_trait_choice` 继续用于可关闭的待选择提示；
- 正向邻接继续是人气款晋升招牌款的必要条件；
- 166 道配方的 `growth_variants` 继续作为阶段展示来源。

设备等级不能替玩家选择特性，也不能绕过售卖或邻接要求。

## 11. 名作 Lv.1—Lv.10

### 11.1 开启条件

名作成长同时要求：

1. 配方已达到招牌款；
2. 配方已经完成两次特性选择。

达到招牌款但仍有待选特性时，配方可以正常制作、上架和售卖，但不累计名作经验。UI 显示：

> 完成特性选择后开启名作。

完成第 2 个特性选择后，名作从 Lv.1、经验 0 开始。此前的制作、售卖和邻接行为不追溯、不补发经验。

### 11.2 经验来源

| 行为 | 基础名作经验 | 对应设备 L4+ 后 |
|---|---:|---:|
| 手动成功制作 1 批 | +2 | +2.4 |
| 自动化成功制作 1 批 | +1 | +1.2 |
| 真实售卖 1 份 | +2 | +2 |
| 该份售卖享受正向邻接 | 额外 +1 | 额外 +1 |

设备加成只作用于制作来源。售卖和正向邻接经验不受设备等级影响。

内部使用 `masterwork_xp_tenths` 保存十分之一点：

- 手动基础制作写入 20；L4+ 写入 24；
- 自动化基础制作写入 10；L4+ 写入 12；
- 售卖写入 20；正向邻接额外写入 10；
- 所有等级阈值在内部乘以 10 比较，避免浮点误差。

不增加今日需求、每日主题、登录或现实时间经验来源，避免名作规则分散。

### 11.3 等级阈值

| 名作等级 | 累计经验 |
|---:|---:|
| Lv.1 | 0 |
| Lv.2 | 20 |
| Lv.3 | 50 |
| Lv.4 | 90 |
| Lv.5 | 140 |
| Lv.6 | 200 |
| Lv.7 | 275 |
| Lv.8 | 365 |
| Lv.9 | 470 |
| Lv.10 | 600 |

名作等级最高为 Lv.10。达到 Lv.10 后继续显示现有累计制作数和售卖数，但不再增加等级、经济倍率或无限经验奖励。

### 11.4 荣誉奖励

名作等级不提供售价、售速、产量、材料或经验倍率：

| 等级 | 可见奖励 |
|---:|---|
| Lv.1 | 开启名作经验条 |
| Lv.2 | 更新名作等级数字 |
| Lv.3 | 共享银色名作边框 |
| Lv.4—Lv.5 | 更新名作等级数字 |
| Lv.6 | 共享轻微光效 |
| Lv.7—Lv.9 | 更新名作等级数字 |
| Lv.10 | 金色完成边框、名作印章、自动生成配方称号 |

Lv.10 称号按配方显示名生成，例如“黄油曲奇名匠”。边框、光效和印章使用共享 UI 组件，不为 166 道配方分别制作特效资产。

全部 166 道配方都可以最终达到名作 Lv.10。不增加“最多 3 个本店招牌”或其他人工数量上限。

## 12. 数据模型

### 12.1 设备成长

`GameState` 新增：

```json
{
  "device_growth": {
    "oven": {
      "level": 3,
      "use_count": 46,
      "research_count": 6,
      "production_batch_count": 40
    }
  }
}
```

- `level`：1—5；
- `use_count`：终身累计有效使用次数，不随升级清零；
- `research_count`：成功研发直属售卖配方的荣誉统计；
- `production_batch_count`：手动和自动化成功制作批次的荣誉统计；
- 只保存五台成品设备的合法记录；
- 三个累计字段在同一次成功事件中原子更新，并始终满足 `use_count = research_count + production_batch_count`；
- `use_count` 是升级公式读取的累计值，两个明细字段只用于玩家查看，不参与额外经济计算。

设备是否参与成长由 `Catalog.DEVICES` 中的显式布尔字段声明，五级表和效果由 `DeviceGrowthService` 统一提供，不能在 UI、`RecipeBook` 和 `GameState` 分别复制。

### 12.2 配方成长

保留现有 `recipe_growth` 字段和 `mastery_level` 命名，不重命名四阶段字段。下面示例表示已经开启名作的配方：

```json
{
  "masterwork_level": 1,
  "masterwork_xp_tenths": 0
}
```

- `masterwork_level` 合法范围为 0—10；0 表示尚未开启名作，完成开启条件后设置为 1；
- `masterwork_xp_tenths` 在尚未开启时固定为 0，开启后按十分之一点累计；

名作是否已开启、是否等待设备、下一阶段要求、有效制作贡献和下一名作等级阈值均由当前状态动态计算，不重复保存派生布尔值。

读取缺失字段时使用新系统默认值。项目仍处于开发阶段，本设计不提供旧开发存档补偿、追认、返还或批量迁移流程；开发存档可以清空后重新创建。

## 13. 运行职责

### 13.1 `DeviceGrowthService`

纯规则服务，负责：

- 五级表；
- 合法设备判定；
- 默认状态和清洗；
- 当前阶段上限；
- 当前与下一等级效果；
- 累计使用和金币缺口；
- 单级升级资格与结果数据。

### 13.2 `RecipeGrowthService`

继续负责：

- 四阶段阈值和名称；
- 标签/形状候选特性；
- 已选特性清洗和效果；
- 正向邻接成长来源判定。

新增负责：

- 设备阶段上限；
- 等待设备状态和说明；
- L4 有效招牌制作贡献；
- 名作开启判定；
- 名作经验阈值、等级和荣誉里程碑。

### 13.3 `GameState`

负责持久化和事务：

- 设备成长状态；
- 设备升级扣金币；
- 成功事件的设备使用累计；
- 配方成长和名作经验累计；
- 设备升级、配方晋升和名作升级通知；
- 保存、读取和合法值清洗。

### 13.4 事件入口

- `RecipeBook.research()`：直属售卖配方成功解锁后记录设备研发使用；失败时按当前设备等级决定线索增量；
- `RecipeBook.make_product()`：传递 `recipe_id`、`device_id`、`batches`、`output_count` 和 `manual` 来源；
- 自动化完成入口：传递实际完成批次和 `automation` 来源；
- `GameState.record_recipe_sold()`：继续记录真实售卖和正向邻接，同时在名作已开启时增加相应经验；
- `RecipeBook.process_ingredient()`：不记录设备成长。

事件必须区分“批次数”和“商品产量”，不能继续仅用 `output_count` 推导设备使用。

## 14. 设备升级事务与反馈

升级到下一等级必须同时满足：

```text
use_count >= 下一等级累计次数
coins >= 下一等级金币费用
```

升级成功：

1. 扣除本级金币；
2. 设备等级增加 1；
3. 有效使用次数保持不变；
4. 统计已满足成长条件但此前被该设备上限阻挡的配方数量；
5. 发送一条设备升级汇总通知；
6. 不直接修改任何关联配方阶段。

升级失败返回全部缺口，不只返回第一个错误：

> 有效使用还差 24 次；金币还差 140。

L5 设备再次点击升级时显示“已满级”，不扣资源。

## 15. UI 与可见反馈

采用“紧凑设备栏＋详情抽屉”，不增加独立成长中心页面。

### 15.1 研发制作页

当前设备槽下方常驻一条紧凑成长栏，显示：

- 设备图标与名称；
- 当前等级；
- 当前有效使用次数与下一累计门槛；
- 紧凑进度条；
- “可升级”状态或主要缺口；
- 点击后打开设备详情抽屉。

选择研磨机时显示静态说明，不显示虚假的等级进度。

### 15.2 设备详情抽屉

抽屉显示：

- 当前等级效果；
- 下一等级效果；
- 使用次数和金币要求；
- 两项资源的准确缺口；
- 升级按钮及禁用原因；
- 关联配方的试作品、稳定款、人气款、招牌款数量；
- 等待该设备升级的配方数量；
- “查看关联配方”按钮。

点击“查看关联配方”跳转图鉴，并自动按设备筛选，不在抽屉内塞入可能很长的完整配方列表。

### 15.3 图鉴列表与详情

图鉴列表只显示紧凑状态：

> 黄油曲奇　人气款｜名作未开启 / 名作 Lv.4

图鉴详情显示：

1. 四阶段路径和当前阶段；
2. 实际制作、有效招牌制作贡献、售卖、正向邻接进度；
3. 当前设备等级、阶段上限和等待原因；
4. 已选特性、候选特性和待选择操作；
5. 名作开启条件、当前经验、下一等级和里程碑；
6. Lv.10 荣誉制作与售卖纪录。

达到招牌但尚未完成特性选择时，明确显示“完成特性选择后开启名作”，不显示正在增长的经验条。

### 15.4 通知策略

- 设备升级：一条汇总通知；
- 配方阶段晋升：由实际触发该配方的成功制作产生现有单配方通知；
- 名作等级提升：每次事件最多汇总为一条通知；
- 同一设备升级不为全部关联配方逐个弹窗；
- UI 刷新必须立即反映金币扣除、设备等级、配方等待状态和下一缺口。

稳定页面结构、抽屉结构和详情区块写入 `.tscn`；脚本只负责读取状态、刷新文案、绑定列表和转发信号。

## 16. 验证

### 16.1 设备成长

1. 五台成品设备解锁时初始化为 L1，未解锁设备没有可操作成长入口，研磨机不产生成长记录。
2. L2/L3/L4/L5 分别要求累计 `10/30/70/150` 次和 `120/360/900/2200` 金币。
3. 升级逐级执行、只扣金币、不消耗累计使用次数。
4. 金币或使用次数不足时状态不变，并返回全部准确缺口。
5. L5 后无法继续升级。

### 16.2 有效使用

1. 成功研发直属售卖配方增加 1 次。
2. 手动 1 批和 5 批分别增加 1 次和 5 次。
3. 自动化按实际完成批次累计。
4. 单批商品产量不影响设备次数。
5. 研发失败、材料不足、售卖、邻接和加工都不能增加设备次数。
6. 圆锅加工酸奶不增加圆锅设备次数。

### 16.3 四阶段

1. 当前 `5/3`、`15/10`、`40/25/10` 阈值保持不变。
2. L1/L3/L5 分别限制稳定款、人气款、招牌款。
3. 达到条件但设备不足时继续记录进度并返回等待设备状态。
4. 设备升级不批量晋升配方。
5. 下一次手动或自动化成功制作触发该配方重新评价。
6. L4 下实际制作 33 份有效贡献为 39，不满足；34 份有效贡献为 40，满足。
7. L4 不减少售卖或邻接条件。

### 16.4 特性与名作

1. 人气款和招牌款候选仍由现有标签、形状和通用规则生成。
2. 未选择的特性不产生效果。
3. 招牌款完成两次特性选择前不累计名作经验。
4. 第 2 次选择完成后从名作 Lv.1、经验 0 开始，不追溯旧行为。
5. 手动、自动化、售卖和正向邻接经验分别符合 `2/1/2/+1`。
6. L4+ 只把制作经验变为 `2.4/1.2`。
7. 十分之一内部计数和十级阈值准确。
8. Lv.10 在 600 经验封顶，不增加经济数值。
9. Lv.3/Lv.6/Lv.10 的共享外观里程碑正确。
10. 任意配方都能独立达到 Lv.10，不存在全局招牌数量上限。

### 16.5 UI 与回归

1. 研发制作页存在紧凑设备栏，研磨机显示排除说明。
2. 详情抽屉显示当前效果、下一效果、准确缺口和关联配方汇总。
3. 跳转图鉴后自动使用对应设备筛选。
4. 图鉴列表保持紧凑，完整成长信息只在详情中展开。
5. 设备升级只发一条汇总通知，不批量弹出配方通知。
6. 166 道配方的成长展示配置继续完整通过校验。
7. 现有标签/形状候选、橱窗邻接、真实售卖、自动化、任务、保存加载和图鉴测试无回归。
8. Godot 无头验证必须按项目约定使用可写的 `--log-file`，不得使用 `NUL`。

## 17. 不在本次范围

- 研磨机成长等级；
- 成品制作倒计时或手动生产队列重构；
- 产量、材料、售价、售速或采购优惠；
- 四类经营专精；
- 为 166 道配方手写独立名作奖励树；
- 无限设备等级或无限名作等级；
- 本店招牌槽位或最多 3 个招牌限制；
- 今日需求、登录、现实时间或限时活动名作经验；
- 旧开发存档补偿和批量迁移；
- 与本系统无关的任务、橱窗规则或配方数据重构。

## 18. 完成标准

功能完成时，玩家应能在研发制作页看到五台成品设备各自的五级进度，通过累计成功研发、制作批次和金币逐级升级；设备等级应限制对应配方的四阶段上限，并在不增加经济产出或制作时间的前提下降低研发与培养成本。

任意配方达到招牌款并完成两次特性选择后，应能通过手动制作、自动化制作、真实售卖和正向邻接成长到名作 Lv.10。名作成长必须提供清晰的荣誉反馈，但不得继续堆叠经济数值。整个系统必须保留现有 166 配方、标签/形状特性、橱窗邻接和展示配置的运行语义。
