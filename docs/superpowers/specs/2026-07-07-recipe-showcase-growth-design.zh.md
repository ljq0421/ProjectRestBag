# 配方与橱窗产品成长设计

## 背景

当前项目已经有 0-5 级店铺解锁路线、149 个配方、橱窗 5x10 格子、产品形状、四方向相邻加成、套装加成、冲突减损和区域加成。下一步需要让每个配方和每个橱窗产品也拥有自己的成长路线。

本设计采用双轨成长：

- 配方成长：由制作、售卖带来的长期熟练度，代表这道甜品在店内被打磨成熟。
- 橱窗成长：由相邻加成触发带来的陈列特性，代表这道甜品在橱窗 build 中形成了自己的摆放价值。

顾客和 NPC 偏好先保留为后续扩展，不进入 MVP 第一版的强依赖。

## 设计目标

1. 让玩家愿意长期经营同一批配方，而不是只追逐最新最高价配方。
2. 让橱窗摆放不只是全局规则，而是具体产品也有成长后的个性。
3. 保持 MVP 可实现：第一版只记录次数、等级和少量特性，不为 149 个配方手工写大量分支。
4. 与现有 `recipe_display_config.json` 和 `display_rules_full.json` 对齐，继续使用标签、形状和四方向相邻作为核心规则。

## 与现有橱窗规则的关系

本规格不替代 `doc/橱窗配方布局设计.md` 的相邻加成、减损体系和玩法流派，而是在其上增加“产品成长层”。现有橱窗规则仍是结算的基础，配方成长只负责记录玩家如何使用这些规则，并在后续给予轻量、可解释的强化。

现有橱窗体系遵循“搭配有增益、扎堆有内卷、冲突有惩罚”的原则。成长系统应保留这个判断顺序：

1. 先按格子、形状和四方向相邻关系确认商品是否有效摆放。
2. 再结算基础标签联动、套装组合、冲突减损和区域加成。
3. 然后根据本轮是否触发有效正向相邻，记录 `adjacency_trigger_count`。
4. 最后应用已解锁的配方成长和橱窗特性。

冲突减损不是成长来源。玩家把商品摆成同类扎堆、口感冲突或饱腹压制时，可以正常结算惩罚，但不应因此获得相邻成长进度。

## 核心模型

每个配方保存一份成长状态：

| 字段 | 类型 | 说明 |
|---|---|---|
| `mastery_level` | int | 配方熟练度等级，0-3 |
| `made_count` | int | 累计制作数量 |
| `sold_count` | int | 累计售卖数量 |
| `adjacency_trigger_count` | int | 橱窗中成功触发相邻加成的累计次数 |
| `display_traits` | Array[String] | 已解锁橱窗特性 |
| `selected_display_traits` | Array[String] | 当前启用的橱窗特性，第一版可默认自动启用 |

等级命名：

| 等级 | 名称 | 定位 |
|---|---|---|
| 0 | 试作品 | 刚研发成功，可制作、可上架 |
| 1 | 稳定款 | 通过制作和售卖证明稳定，获得基础经营收益 |
| 2 | 人气款 | 已经形成稳定销量，并开始从橱窗相邻中获得特性 |
| 3 | 招牌款 | 成为店内代表作，可解锁强化形态或核心相邻能力 |

## 成长来源

### 制作次数

制作成功时增加 `made_count`。它代表厨房熟练度，适合驱动成本、产量和制作效率。

第一版建议阈值：

| 阶段 | 条件 |
|---|---|
| 试作品 -> 稳定款 | 制作 5 份，且售卖 3 份 |
| 稳定款 -> 人气款 | 制作 15 份，售卖 10 份 |
| 人气款 -> 招牌款 | 制作 40 份，售卖 25 份，相邻加成触发 10 次 |

### 售卖次数

售卖成功时增加 `sold_count`。它代表市场验证，适合驱动售价、售速和顾客吸引力。

售卖统计应在商品真正卖出时记录，而不是上架时记录。这样玩家不能只靠反复上架刷成长。

### 相邻触发次数

一轮营业或单件售出结算时，如果该产品在橱窗中触发了基础标签联动、套装加成或位置强化后的相邻效果，则增加 `adjacency_trigger_count`。

第一版只需要记录“本轮是否触发过有效相邻”，不需要按每条边重复刷次数。这样可以避免玩家用一个高频售卖商品无限刷成长。

有效相邻来源按现有橱窗规则分为三类：

| 来源 | 计入成长 | 说明 |
|---|---|---|
| 基础标签联动 | 是 | 例如 `果香 + 清爽`、`苦甜 + 浓郁`、`甜 + 咸香`、`经典 + 经典` |
| 进阶套装组合 | 是 | 例如下午茶三件套、夏日清凉套、咸甜正餐套、巧克力狂热套 |
| 橱窗位置加成 | 条件计入 | 黄金 C 位的相邻加成倍率可计入；单纯前排或深处位的售价/售速变化不计入 |
| 同类扎堆惩罚 | 否 | 这是反制无脑堆叠的负反馈 |
| 口感冲突惩罚 | 否 | 例如清凉类与浓郁类相邻导致售价降低 |
| 饱腹压制惩罚 | 否 | 例如咸香主餐压低周边甜品售速 |

同一轮营业中，一个商品无论触发多少条正向边，最多增加 1 次 `adjacency_trigger_count`。如果它同时触发正向加成和冲突惩罚，仍可获得 1 次成长，但 UI 需要显示正负来源，避免玩家误以为惩罚本身也能刷成长。

## 配方熟练度效果

熟练度效果应轻量、稳定，不抢走橱窗 build 的主要策略空间。

| 等级 | 建议效果 |
|---|---|
| 试作品 | 使用基础售价、基础售速、基础产量 |
| 稳定款 | 制作成本 -5% 或制作产量 +1，二选一按配方类型自动给 |
| 人气款 | 售价 +5%，并解锁第 1 个橱窗特性 |
| 招牌款 | 售价 +8%，售速 +5%，并解锁第 2 个橱窗特性或强化形态 |

自动给效果的原则：

- 1 格和 2 格小件优先给售速或产量，强化走量定位。
- 2x2 中块优先给售价，强化组合核心定位。
- 2x3 招牌款优先给相邻加成或区域收益，避免单纯堆售价。

## 橱窗特性

橱窗特性只在商品被摆入橱窗后生效。每个配方最多解锁 2 个特性，MVP 第一版默认全部启用；后续如果特性数量增加，再做手动选择。

### 形态进化

形态进化改变产品占格、售价和售速，适合让同一配方在不同布局中有不同用途。

| 形态 | 适用对象 | 效果 |
|---|---|---|
| 小份 | 杯装、糕点、招牌款 | 占格减少或保持小形态，售速 +8%，售价 -5% |
| 标准 | 全部 | 使用 `recipe_display_config.json` 默认形状 |
| 礼盒 | 1 格或 2 格小件 | 升级为 1x2 或 2x2，售价 +12%，售速 -5% |
| 大份 | 中块和招牌款 | 占格增加，售价 +20%，售速 -10%，相邻加成倍率 +10% |

MVP 第一版不需要为所有配方开放所有形态。建议先按形状类别自动开放：

- 迷你款：标准、礼盒。
- 竖杯款：小份、标准。
- 横盘款：标准、礼盒。
- 中块款：标准、大份。
- 招牌款：小份、大份。

### 邻接强化

邻接强化让产品对特定方向或特定标签的邻居提供额外收益。

示例：

| 特性 | 触发条件 | 效果 |
|---|---|---|
| 茶点搭档 | 相邻产品含 `茶香` | 自身和茶香产品售速 +5% |
| 清爽侧摆 | 左右相邻产品含 `清爽` | 自身售价 +5% |
| 咸甜桥梁 | 一侧为 `咸香`，另一侧为 `甜` | 三件售速 +6% |
| 经典陈列 | 相邻产品含 `经典` | 自身相邻加成效果 +10% |
| 核心展位 | 位于黄金 C 位且至少 2 个邻居 | 自身售价 +6% |

第一版优先做不依赖方向的标签型邻接强化；方向型能力可作为第二批，因为它需要 UI 更明确地提示玩家方向。

邻接强化需要映射到现有基础标签联动，而不是新增一套不相干的标签体系。第一版推荐映射：

| 现有联动 | 可生成特性 | 成长定位 |
|---|---|---|
| `果香 + 清爽` | 清爽侧摆、夏日预备 | 支持走量流和夏日清凉套 |
| `苦甜 + 浓郁` | 醇厚搭档、巧克力预备 | 支持高客单价流 |
| `甜 + 咸香` | 咸甜桥梁 | 支持咸甜综合流 |
| `软糯 + 甜` | 软糯热卖 | 支持缝隙走量流 |
| `茶香 + 奶香/乳制` | 茶点搭档 | 支持经典下午茶流 |
| `香脆 + 浓郁` | 口感层次 | 支持曲奇、酥饼和浓郁蛋糕组合 |
| `经典 + 经典` | 经典陈列 | 支持低风险基础经营 |
| `低负担 + 清爽` | 轻食推荐 | 支持健身轻食路线 |

### 套装核心

套装核心让部分人气款或招牌款成为 build 中心，强化已有套装规则。

示例：

| 特性 | 适配路线 | 效果 |
|---|---|---|
| 下午茶核心 | 经典、茶香、香脆、浓郁 | 参与“经典下午茶三件套”时，套装售价额外 +5% |
| 夏日核心 | 果香、清爽、清凉 | 参与“夏日清凉套装”时，套装售速额外 +5% |
| 咸甜核心 | 咸香、甜、茶香 | 参与“咸甜正餐套装”时，自身售速 +8% |
| 巧克力核心 | 苦甜、浓郁、香脆 | 参与“巧克力狂热套装”时，自身售价 +8% |

MVP 第一版可以先不做套装核心，只把字段和规则预留出来。先上线“邻接强化 + 形态进化”，更容易验证玩家是否理解成长反馈。

套装核心应直接引用现有套装，而不是额外定义新套装。后续开启时，成长特性只做“该商品参与套装时的微强化”，不改变套装成立条件。

| 现有套装 | 可成长为核心的产品类型 | 成长强化方向 |
|---|---|---|
| 经典下午茶三件套 | 茶饮、曲奇/酥饼、蛋糕/派 | 稳定售价和售速，适合均衡利润 |
| 夏日清凉套 | 果香甜品、薄荷/清爽饮品 | 提高售速，适合走量 |
| 老街怀旧套 | 米食、传统糕点、甜汤糊类 | 提高售价，适合经典客群 |
| 健身轻食套 | 低负担食品、酸奶、燕麦碗 | 售价和售速小幅双加成 |
| 巧克力狂热套 | 可可/巧克力、坚果类 | 提高售价，适合高客单价 |
| 咸甜正餐套 | 咸口主餐、饮品、小甜品 | 提高售速，适合综合营收 |
| 全茶风味套 | 红茶、绿茶、抹茶相关甜品 | 提高主题溢价 |

## 配方特性生成规则

为了避免为 149 个配方手写成长路线，第一版使用自动生成规则，再允许少数招牌配方手工覆盖。

生成输入：

- 配方标签：来自 `recipe_display_config.json` 和配方表。
- 默认形状：来自 `recipe_display_config.json`。
- 解锁等级：来自配方数据。
- 售价、设备、材料数量：来自配方数据。

生成逻辑：

1. 根据默认形状决定可用形态进化。
2. 根据标签决定第 1 个邻接强化。
3. 根据是否拥有套装关键标签决定是否预留套装核心。
4. 对 Lv.5 招牌配方和 `community_parfait` 等代表性产品允许手工覆盖。

示例：

| 配方 | 默认定位 | 人气款特性 | 招牌款特性 |
|---|---|---|---|
| 米浆饮 | 竖杯、经典、清爽 | 经典陈列 | 小份走量 |
| 黄油曲奇 | 迷你、经典、香脆 | 茶点搭档 | 礼盒装 |
| 蓝莓慕斯杯 | 竖杯、果香、清爽 | 清爽侧摆 | 夏日核心 |
| 巧克力曲奇 | 迷你、苦甜、香脆 | 巧克力核心预备 | 礼盒装 |
| 海绵杯蛋糕 | 中块、经典、甜 | 核心展位 | 大份招牌 |

## 数值边界

成长不应让旧配方无限压过高等级内容，也不应让新配方完全替代旧配方。

建议限制：

- 单个配方熟练度总售价加成不超过 +15%。
- 单个配方熟练度总售速加成不超过 +15%。
- 单件商品来自橱窗成长特性的额外加成不超过 +20%。
- 相邻加成、区域加成、成长加成最终可叠加，但 UI 应显示拆分来源。
- 同类扎堆惩罚继续生效，不能被成长特性完全抵消。
- 口感冲突和饱腹压制属于最终惩罚层，成长加成不能把惩罚值直接清零。
- 大份、礼盒等形态进化必须承担售速下降或占格增加的代价，不能只给售价收益。
- 黄金 C 位可以强化相邻加成，但不能让单个大件在没有邻居时获得完整 build 收益。

## 玩法流派支持

成长系统需要服务现有四种主流玩法流派，让不同配方在不同橱窗 build 中有价值。

| 流派 | 原始思路 | 成长系统支持 | 平衡约束 |
|---|---|---|---|
| 缝隙走量流 | 用 1 格迷你款和小件填满橱窗，靠售速和数量获利 | 迷你款优先获得售速、产量、经典陈列、软糯热卖等成长 | 单品售价成长较低，且同类扎堆惩罚继续限制全堆同标签 |
| 招牌利润流 | C 位放大份招牌，周围摆辅助件叠加溢价 | 中块和招牌款可获得大份形态、核心展位、套装核心预备 | 大份必须增加占格或降低售速，避免纯数值碾压 |
| 主题套装流 | 围绕下午茶、夏日、巧克力等套装组织布局 | 人气款可解锁与套装标签对应的邻接强化，招牌款预留套装核心 | 套装仍要求连通相邻，成长不能绕过摆放条件 |
| 咸甜综合流 | 咸口主餐、饮品、小甜品穿插，提高客群覆盖和售速 | 咸甜桥梁、咸甜核心预备可鼓励玩家做跨品类组合 | 饱腹压制仍生效，主餐周围不能无脑堆太多甜品 |

第一版的成长奖励应优先强化流派识别，而不是直接给最高收益。例如黄油曲奇成长后更适合做下午茶搭档，蓝莓慕斯杯更适合清爽走量，海绵杯蛋糕更适合 C 位核心；它们不应该都成长成同一种“售价更高”的模板。

## UI 表达

配方图鉴和橱窗格子都需要展示成长状态。

配方图鉴：

- 显示成长阶段名：试作品、稳定款、人气款、招牌款。
- 显示制作进度、售卖进度、相邻触发进度。
- 显示已解锁橱窗特性和下一阶段条件。

橱窗格子：

- 商品名后显示阶段短标，例如“黄油曲奇 · 人气”。
- 鼠标悬停或详情面板展示当前生效加成。
- 如果相邻特性未触发，显示简短提示，例如“旁边放茶香商品可触发茶点搭档”。

## 数据与存档

建议新增存档字段：

```json
{
  "recipe_growth": {
    "butter_cookie": {
      "mastery_level": 2,
      "made_count": 18,
      "sold_count": 12,
      "adjacency_trigger_count": 5,
      "display_traits": ["tea_partner"],
      "selected_display_traits": ["tea_partner"]
    }
  }
}
```

旧存档迁移：

- 没有 `recipe_growth` 时默认为空字典。
- 已解锁但没有成长记录的配方，在首次查询时创建默认状态。
- 已售出历史不倒推，避免旧存档迁移复杂化。

## 事件接入点

第一版需要在三个事件上记录成长：

| 事件 | 记录内容 |
|---|---|
| 制作成功 | 增加 `made_count` |
| 售卖成功 | 增加 `sold_count` |
| 售卖结算中触发有效相邻 | 增加 `adjacency_trigger_count` |

升级检查可以在每次事件记录后执行。若达到新阶段，加入待弹窗通知，并在图鉴和橱窗刷新后展示。

## MVP 范围

第一版实现：

1. 配方成长状态存档。
2. 试作品、稳定款、人气款、招牌款四阶段。
3. 制作、售卖、相邻触发三类计数。
4. 成长阶段带来的轻量售价、售速或产量效果。
5. 人气款解锁 1 个邻接强化。
6. 招牌款解锁 1 个形态进化。
7. 配方图鉴和橱窗格子显示成长阶段与下一步条件。

第一版不实现：

- 顾客或 NPC 专属成长分支。
- 手动选择多个成长特性。
- 为全部 149 个配方手写独立成长树。
- 复杂方向型相邻能力。
- 每日随机偏好和主题橱窗对成长路线的影响。

## 后续扩展

后续可以逐步加入：

1. 顾客偏好路线：某配方经常卖给白领、亲子家庭或探店博主后，获得客群专属特性。
2. 手动专精选择：人气款或招牌款升级时，玩家从 2 个特性中选择 1 个。
3. 主题橱窗：夏日、复古、茶会等主题影响特性生成和相邻收益。
4. 陈列道具：蛋糕架、冷藏展示柜等道具与配方成长形成组合。
5. 配方变体：同一配方在图鉴中保留基础版，但橱窗中可切换小份、礼盒、大份。

## 验收标准

1. 任意新研发配方默认是试作品。
2. 制作和售卖指定次数后，配方能升级为稳定款。
3. 售卖并触发相邻加成后，配方能升级为人气款。
4. 达到指定制作、售卖和相邻触发条件后，配方能升级为招牌款。
5. 成长数据能保存和读取。
6. 橱窗售卖结算能正确读取成长加成。
7. 配方图鉴和橱窗格子能展示当前阶段、当前特性和下一阶段条件。
8. 未成长的低级配方、成长后的低级配方和新解锁高级配方都各有价值，不出现单一最优解。
