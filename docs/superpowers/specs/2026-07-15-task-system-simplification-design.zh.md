# 任务系统精简设计

日期：2026-07-15  
状态：设计已确认，待实施计划  
适用项目：`D:\Project\ProjectRest\project-rest-new`

## 1. 背景

当前任务目录包含 6 个教学任务、15 个构筑课程、5 个阶段评鉴、5 个经营合同以及 9 个资源或功能任务。任务面板又把它们拆成“主线课程”“经营合同”“资源支线”“自动化”“待领取”5 个页签。

这种结构把一次操作、一次练习、阶段考核、日常目标和奖励状态都提升成了同级任务分类。玩家会同时看到多个“进行中”目标，并可能遇到顶部显示“进行中 7”，所选页签却显示“暂无任务”的矛盾。

本设计对任务系统做减法：前期用少量带子目标的任务完成强引导，中期只保留必要的构筑过渡，Lv.3 后全面转为一次性综合构筑挑战，Lv.6 后才使用可重复合同与铜、银、金评级。

本设计覆盖并取代既有《橱窗构筑任务路线重设计》中有关任务数量、阶段评鉴、任务分类和五页签的规定；统一营业报告、30 秒营业边界、Lv.6+合同快照等未冲突设计继续有效。

## 2. 目标

1. 教学任务从 6 个减少到 3 个，但完整保留采集、制作、上架、营业、成交和结算反馈。
2. Lv.1～Lv.5 固定成长任务从 20 个减少到 7 个。
3. 任意时刻只展示 1 个当前目标和最多 3 个支线任务。
4. 任务页签从 5 个减少到“当前目标”“支线任务”2 个。
5. “待领取”成为顶部统一操作，不再是任务页签或活动任务。
6. Lv.3～Lv.5 每项挑战只有一套清晰完成标准；铜、银、金只属于 Lv.6+可重复经营合同。
7. 顶部计数只统计玩家实际可见、可处理的内容。

## 3. 非目标

- 不改变标准营业轮固定 30 秒、轮内补货、余货处理和完整结算边界。
- 不改变 Lv.1 以后由金币和累计口碑决定店铺升级的规则。
- 不重做 Lv.6+合同生成、合同快照和铜银金评价算法，除非实施时发现它们与新任务入口存在直接接口冲突。
- 不新增独立课程页、评鉴页、合同页或奖励页。
- 不恢复“查看售价和待售时间”任务、提示或前置条件。
- 不做旧任务 ID、旧进度、旧页签或旧存档迁移；开发验证使用新存档。

## 4. 采用方案与备选方案

采用“3 个教学任务 + 7 个成长任务 + 2 个页签”。合并后的教学及 Lv.1～Lv.2 任务使用可逐项勾选的子目标，整卡完成后统一领取奖励。

未采用的方案：

- 保守压缩：保留约 10 个成长任务和 3 个页签。改动较小，但课程与评鉴仍有较多重复。
- 激进压缩：只保留 2 个教学任务、每级 1 个里程碑和单一任务流。数量最少，但会削弱 Lv.0～Lv.2 对真实操作的解释。

## 7. 成长任务

成长路线采用单链前置关系：

```text
销售节奏
→ 余货决策
→ 形成基础组合
→ 完成紧凑构筑
→ 库存压力挑战
→ 连锁效率挑战
→ 招牌构筑挑战
```

任务必须同时满足最低等级和前置任务条件才可成为当前目标。玩家升级速度快于任务路线时，仍只展示最前面的未完成任务。成长任务不阻塞店铺升级。

即使店铺已经达到 Lv.6，只要 7 个成长任务尚未全部完成，“当前目标”仍优先显示最前面的未完成成长任务；全部完成后才在该位置显示 Lv.6+合同选择入口。这一顺序只影响任务面板的目标路线，不限制普通营业或店铺升级。

## 8. 子目标语义

教学和 Lv.1～Lv.2 任务使用`objectives`数组。每个子目标至少包含：

- 唯一`id`；
- 玩家可见`title`和进度文案；
- 接受的事件；
- 条件与目标值；
- 可选的即时流程效果。

每个子目标独立保存完成状态。已完成子目标不会因后续失败或重复事件回退，也不会重复触发即时流程效果。整张任务的所有子目标完成后，任务才进入待领取状态。

如果一个子目标包含多个营业报告指标，这些指标必须在同一份完整营业报告中同时成立。不同子目标可以由不同营业轮完成。中途退出、未结算或报告不完整的营业轮不能完成营业类子目标。

普通金币、口碑、星辉和等级奖励只存放在任务级`reward`中。子目标级只允许使用完成后立即继续教学所必需的流程效果；首个教学任务开放圆锅是本设计唯一必需用例。

## 9. Lv.6+经营合同

铜、银、金只允许出现在`round_contracts`：

- 铜表示合同基础完成档位；
- 银、金表示同一合同的更高表现；
- 达到更高档位自动满足较低档位；
- 合同可以重复挑战并刷新最佳成绩。

教学任务和成长任务均不包含`tiers`或`required_tier`。配置校验发现这些字段时必须报错。Lv.3～Lv.5挑战只有第 7 节规定的一套完成标准。

Lv.6+尚未选择合同时，“当前目标”显示 3 个合同候选，但它们属于一个“选择合同”操作位，不计为 3 个进行中任务。选择后只显示已选合同。

## 10. 两页签任务面板

### 10.1 当前目标

“当前目标”只显示以下一个位置：

1. 最前面的未完成教学任务；或
2. 最前面的、等级已满足的未完成成长任务；或
3. Lv.6+已选择的经营合同；或
4. Lv.6+尚未选择合同时的合同选择入口。

没有满足等级的下一项成长任务时，显示“当前成长目标已完成，继续经营或提升店铺等级。”合同选择入口显示“请选择一个经营合同作为本轮目标。”

### 10.2 支线任务

“支线任务”合并日常资源任务与自动化解锁任务：

- 每个既有日常刷新周期从当前符合条件的日常定义中选择最多 2 个；
- 同一刷新周期选择结果固定，反复打开面板不能重抽；
- 本周期内完成已选日常后不补入新的日常；
- 满足开放条件的自动化解锁任务最多显示 1 个，多个同时满足时选择排序最前者；
- 因可选任务不足而少于 2 个日常属于正常情况；
- 未被选中的日常定义不进入活动任务集合，也不计入进行中数量；
- 全部完成时显示“今日支线已全部完成。”

因此支线同时最多显示 3 个任务：2 个日常任务和 1 个自动化解锁任务。

### 10.3 待领取

删除“待领取”页签。任务完成后立即从活动列表移除，奖励进入面板顶部“一键领取奖励（N）”。下一项成长任务的开放依据是前置任务已经完成，不要求前一项奖励先领取。

没有奖励时按钮显示“暂无可领取奖励”并禁用。重复点击、重复刷新或重复应用同一完成事件都不能重复发奖。

### 10.4 顶部摘要

摘要固定使用：

```text
当前目标 N｜支线 N｜待领取 N
```

“当前目标”只能为 0 或 1；合同选择入口作为一个可处理位置计为 1。“支线”只能为 0～3。摘要直接读取两个页签实际展示的条目和待领取集合，不读取未经曝光的完整活动定义集合。

## 11. 状态与数据流

玩家可见状态统一为：

```text
未开放 → 当前进行中 → 待领取 → 已领取
```

完成任务与领取奖励是两个独立状态。待领取任务不属于进行中任务。

运行数据流：

```text
读取并校验四类任务配置
→ 根据等级、前置状态和刷新周期选出当前目标与支线
→ 真实交互事件更新对应子目标
→ 完整营业报告判定营业类子目标或单一挑战标准
→ 所有子目标完成后写入任务完成状态
→ 任务退出活动列表，奖励进入顶部待领取集合
→ 下一项成长任务自动成为当前目标
→ 玩家一键领取全部待领取奖励
```

## 12. 组件职责

- `TaskCatalogService`：读取四个任务分组，校验任务、子目标、前置关系和评级字段边界。
- `TaskService`：处理子目标进度、单链当前目标、支线选择、完成状态与奖励领取。
- `GameState`：保存任务完成状态、子目标进度、当前刷新周期选中的日常任务和合同快照。
- `TaskOverlay`：只维护`current`和`side`两个筛选 ID，显示实际条目、顶部摘要和统一领取操作。
- `main_view.gd`：协调打开任务面板和刷新状态，不维护第二份筛选白名单或任务分类规则。
- 营业报告与合同服务：继续提供营业指标和 Lv.6+评级，不承担页签分类或活动任务计数。

稳定页签结构、列表容器、详情容器和领取按钮继续放在任务面板场景文件中；脚本只负责绑定任务数据、刷新状态和处理信号。

## 13. 配置与运行异常

- 任务 ID、子目标 ID 重复：配置校验失败。
- 子目标缺少事件、条件、目标或玩家可见名称：配置校验失败。
- 前置任务不存在或形成循环：配置校验失败。
- 教学或成长任务包含铜银金字段：配置校验失败。
- 营业类条件引用统一营业报告不存在的字段：配置校验失败，该任务不进入玩家列表。
- 当前筛选 ID 无效：面板自动回到“当前目标”。
- 营业报告缺失、未完整结算或被重复应用：不推进任务，并保留可诊断日志。
- 同一子目标事件重复发送：只保留一次完成状态，即时效果只应用一次。
- 同一奖励重复领取：状态检查拒绝重复发奖。

## 14. 验证标准

### 14.1 配置验证

- 目录恰好包含 3 个教学任务和 7 个成长任务。
- 不再存在`build_courses`、`stage_evaluations`和旧任务 ID。
- 四个任务分组、所有任务 ID、子目标 ID、前置关系和营业报告字段引用有效。
- 教学与成长任务没有评级字段；经营合同保留合法的铜银金档位。

### 14.2 任务服务验证

- 子目标能够跨事件、跨营业轮独立完成；同一复合子目标只能由同一份完整报告完成。
- 教学圆锅解锁只触发一次，整卡奖励只能领取一次。
- 任意时刻当前目标最多 1 个，支线最多 3 个。
- 日常选择在刷新周期内稳定，完成后不补位，未选任务不计入活动数量。
- 前一任务待领取时，下一项成长任务仍能成为当前目标。
- Lv.3～Lv.5只按单一完成标准判定。

### 14.3 任务面板验证

- 只显示“当前目标”“支线任务”两个页签。
- 两个页签可以正常切换，筛选 ID 不会被主视图中的旧白名单拒绝。
- 顶部摘要与实际条目数量完全一致。
- 空状态分别说明等级不足、等待选择合同或今日支线完成，不再笼统显示“暂无任务”。
- “待领取”没有页签；顶部领取按钮正确显示数量并阻止重复领取。

### 14.4 真实交互路径

- 新游戏能通过真实采集、制作、上架、开始营业、真实成交和完整结算完成 3 个教学任务。
- Lv.1、Lv.2子目标能通过真实营业轮报告完成。
- Lv.3库存压力、Lv.4连锁效率、Lv.5招牌构筑均能由对应等级当前开放内容完成。
- Lv.6+能从 3 个合同候选中选择一个，并继续使用铜银金评价。

### 14.5 回归验证

- 标准营业仍固定 30 秒。
- 轮内补货、余货、清仓、布局收益、营业金币和报告结果语义不变。
- 店铺升级仍只使用金币与累计口碑，成长任务不会直接阻塞升级。
- 自动化解锁条件和合同快照仍能正常工作。
- Godot headless 自检从包含`project.godot`的目录运行，并使用可写`--log-file`路径。

## 15. 实施边界

本设计适合作为一个实施计划，按以下依赖顺序落地：

1. 调整任务目录和配置校验。
2. 实现子目标进度与新的活动任务选择规则。
3. 替换任务内容、奖励映射和星辉奖励 ID。
4. 将任务面板改为两个页签并统一顶部计数和领取入口。
5. 更新任务相关自检并走通真实新游戏路径。

实施不得为维持旧测试而恢复被删除的任务、五页签或旧筛选 ID。旧测试应跟随新任务合同更新。
