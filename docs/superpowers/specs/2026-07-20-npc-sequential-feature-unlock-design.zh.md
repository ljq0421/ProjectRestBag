# NPC 顺序功能解锁与等级内容开放设计

日期：2026-07-20
目标项目：`D:\Project\ProjectRest\project-rest-new`

## 1. 背景

`project-rest-new` 已有外婆 NPC 主持的新手引导，当前业务顺序为采购、产出、研发、制作、上架、构筑规则、橱窗调整、开始营业、橱窗经营和完成。现有引导会自动切页、显示目标箭头，并通过真实操作事件推进。

当前引导仍然只是提示层：底部入口、研发制作工作台、构筑规则和营业按钮并没有统一的永久门禁。`WorkbenchLauncher` 已提供入口启用接口，但主流程尚未接入。采购页和产出页也主要依赖单项 `unlock_level` 过滤内容；四个产地当前均标记为 Lv.0，未形成真实的来源级锁定。

本设计将新手提示升级为两层渐进开放体系：

1. 外婆主线按真实业务操作依次开放核心板块与功能。
2. 进入采购和产出板块后，再由店铺等级依次开放来源、产地、食材、工具与设备。

## 2. 设计目标

- 新存档只开放采购，且采购页只有农场区域可用、只有水稻种子可购买。
- 所有未开放入口、区域和操作保持可见并统一带锁。
- 只有真实成功操作可以开放下一项核心功能。
- “我自己来”只停止当前阶段提示，不推进业务阶段、不开放功能。
- 功能开放永久、单向、可保存；重播引导不得重新上锁。
- 采购与产出的具体内容继续随 Lv.0–Lv.5 逐批开放。
- 取消三个 Lv.0 教学任务；教学结束后再开放任务系统。
- 教学结束只升至 Lv.1并开放任务，不赠送金币或星辉。
- 避免玩家因跳过提示、零成交、存档中断、旧存档或缺失前置状态而软锁。

## 3. 非目标

- 不重做外婆对话框的视觉结构、目标箭头或动态定位系统。
- 不把研发、制作、上架拆成三个新页面。
- 不改变 Lv.1–Lv.5 现有单项食材与配方的整体等级路线；本设计只增加来源级门禁并修正 Lv.0 起点。
- 不重做长期自动化、橱窗扩建、配方成长或设备成长系统。
- 不让任务系统反向控制核心新手功能是否开放。

## 4. 核心原则

### 4.1 教学状态与功能状态分离

外婆引导只负责对话、箭头、自动路由和提示显隐。核心功能是否开放由独立的永久解锁账本决定。

因此：

- 玩家确认普通对话不会开放功能。
- 玩家点击“我自己来”不会开放功能。
- 玩家重播外婆引导不会重新上锁。
- 玩家只有在真实业务操作成功后才会获得下一项功能。

任务属于教学结束后的辅助入口，是唯一由最终对话确认开放的例外；该确认只有在“至少售出 1 份商品并完成结算”的真实里程碑已经持久化后才可执行。

### 4.2 解锁只增不减

核心解锁账本中的功能只能从未开放变为开放。加载存档时允许补齐遗漏前置，但不允许因为版本变化、引导重播或字段缺失反向关闭已使用过的功能。

### 4.3 板块开放与内容开放分层

核心主线回答“能不能进入这个板块或使用这项功能”；等级内容门禁回答“板块内部有哪些来源、产地和物品可用”。

例如：产出板块在购买水稻种子后开放，但 Lv.0 只能操作农场。养殖场与水塘到 Lv.1 才开放，林场到 Lv.2 才开放。

## 5. 核心解锁主线

| 阶段 | 当前开放内容 | 必须发生的真实成功事件 | 新开放内容 |
| --- | --- | --- | --- |
| 新存档 | 采购 | 无 | 采购页可进入；其他入口全部带锁 |
| 采购 | 农场采购区、水稻种子 | 成功购买至少 1 份水稻种子 | 产出、库存 |
| 产出 | 仅农场 | 手动成功收获大米 | 研发、蒸煮一体的圆锅 |
| 研发 | 研发输入与圆锅 | 成功研发米浆饮 | 制作、甜品图鉴 |
| 制作 | 米浆饮制作 | 米浆饮制作完成并真正进入成品库存 | 上架 |
| 上架 | 米浆饮上架操作 | 成功将米浆饮放入橱窗 | 橱窗顶部构筑规则按钮 |
| 构筑规则 | 指定规则入口 | 从橱窗顶部按钮成功打开规则弹窗 | 橱窗拖动与旋转操作 |
| 橱窗调整 | 拖动、旋转 | 米浆饮真实拖动和旋转各成功一次 | 开始营业按钮 |
| 开始营业 | 营业按钮 | 成功启动一轮真实营业 | 橱窗经营入口 |
| 橱窗经营 | 经营状态页 | 成功打开橱窗经营页 | 进入“等待成交与结算”阶段 |
| 经营结算 | 已开放的经营闭环 | 完成一轮至少售出 1 份商品的结算 | 外婆最终对话 |
| 完成 | 最终对话 | 玩家确认结束引导 | 店铺升至 Lv.1、开放任务 |

只有橱窗顶部 `RulebookButton` 的真实成功打开事件可以开放橱窗调整。“查看全部规则”等其他入口只打开弹窗，不推进核心主线。

制作阶段以成品真正入库为成功点，不以点击制作按钮或进入制作队列为成功点。开始营业阶段以业务服务成功创建运行中营业轮为成功点，不以按钮点击为成功点。

## 6. 外婆引导流程

### 6.1 步骤调整

现有步骤在 `storefront` 后新增 `settlement`：

```text
purchase
-> output
-> research
-> craft
-> list
-> rulebook
-> arrange
-> business
-> storefront
-> settlement
-> complete
```

打开橱窗经营页后，外婆提示玩家观察第一轮真实成交并完成结算。只有一轮有成交的结算完成后，才进入最终对话。

### 6.2 “我自己来”

当前“跳过本步”改名为“我自己来”，语义固定为：

- 收起并停止本阶段的外婆对话和目标箭头。
- 不改变当前核心解锁阶段。
- 不补材料、不伪造业务事件、不完成任务、不发奖励。
- 玩家自行完成当前真实操作后，正常开放下一功能，并在下一阶段重新显示外婆。
- 玩家点击下一项锁定功能时，可以重新唤起外婆对当前前置目标的说明。

引导状态增加本阶段提示已主动停止的持久字段。阶段变化后，旧阶段的停止状态自然失效。

### 6.3 最终对话

第一轮有成交的营业结算完成后，外婆显示最终说明：

> 接下来就交给你啦。外婆不在的时候，可以查看“任务”，帮助你更好地经营店铺哦。

玩家确认后：

1. 标记核心新手主线完成。
2. 店铺升至 Lv.1。
3. 永久开放任务入口。
4. 刷新 Lv.1 新开放的采购、产出、食材、工具和设备。
5. 不发放额外金币。
6. 不发放星辉。

重播外婆引导不会再次修改等级或重复开放任务。

## 7. 采购与产出的等级内容门禁

### 7.1 来源级开放等级

采购页六个区域继续保持同页可见，未开放区域显示锁、开放等级和第一批代表内容。

| UI 区域 | 开放等级 | 首批代表内容 |
| --- | ---: | --- |
| 农场 | Lv.0 | 水稻种子 |
| 养殖场 | Lv.1 | 小鸡仔 |
| 林场 | Lv.2 | 草莓、蓝莓、香蕉种子 |
| 水塘 | Lv.1 | 泉水引 |
| 辅料 | Lv.1 | 白糖 |
| 工具 | Lv.1 | 农场加速器 |

产出页四个产地继续保持同页占位：

| 产地 | 开放等级 |
| --- | ---: |
| 农场 | Lv.0 |
| 养殖场 | Lv.1 |
| 水塘 | Lv.1 |
| 林场 | Lv.2 |

当前 `PRODUCTION_SITES` 把四个产地都标记为 Lv.0。本设计要求将来源等级改为真实业务门禁，而不是让未开放区域显示成可用但内容为空。

### 7.2 单项内容开放

来源开放后，区域内的单项食材、投入品和工具继续使用各自 `unlock_level`。等级不足的未来内容仍显示为锁定行，并优先使用现有 `mystery_name`，避免提前公布全部食材名称。

代表性节奏如下：

| 等级 | 代表性新增内容 |
| ---: | --- |
| Lv.0 | 水稻种子、大米、首个米浆饮闭环 |
| Lv.1 | 小麦、小鸡仔、泉水引、白糖、农场加速器、研磨机 |
| Lv.2 | 草莓/蓝莓/香蕉、小牛犊、乳制辅料、烤箱、林场 |
| Lv.3 | 红豆/黑芝麻、多种水果、蜜蜂群、海盐、冷藏柜 |
| Lv.4 | 南瓜/糯米、小鸭苗、薄荷/咖啡、酵母、煎烤盘 |
| Lv.5 | 栗子/燕麦、小羊羔、坚果/茶类/杏仁、搅拌机 |

每次等级提升后同时刷新采购和产出。一次等级提升开放的多个来源与物品合并为一条等级解锁通知，不连续弹出多个窗口。

### 7.3 Lv.0 初始资源

新存档保持 120 金币和 10 份泉水。泉水解释为外婆留下的首批材料，用于完成第一个米浆饮研发闭环。

初始库存不再提供 `spring_water_starter`。水塘在 Lv.1 开放后，玩家再通过采购泉水引进入可持续产出。

## 8. 统一锁定状态

### 8.1 底部入口

- 所有入口始终保留位置和名称。
- 未开放入口降低视觉强调并显示统一锁标记。
- 锁定入口仍然接收点击，用于展示原因；不能直接依赖原生 `disabled` 后静默无响应。
- 核心主线锁显示具体前置操作，例如“先在农场购买 1 份水稻种子”。
- 等级锁显示“店铺 Lv.X 开放”。
- 长期系统锁显示真实条件，例如“首次获得星辉后开放”。

### 8.2 页面与操作

- 研发尚未开放时，工作台整体显示锁层和“先手动收获大米”。
- 研发开放后，只开放研发输入；制作区域继续带锁。
- 首个配方研发成功后原位开放制作；上架仍带锁。
- 首批成品真正入库后原位开放上架。
- 构筑规则、拖动、旋转、开始营业分别使用独立门禁。
- 锁定控件开放后原位移除锁，不改变布局位置。

### 8.3 解锁反馈

一次真实操作开放功能时，反馈顺序固定为：

1. 业务操作返回成功。
2. 永久解锁账本写入新功能并保存。
3. 对应锁标记消失，入口短暂暖色高亮。
4. 显示一条紧凑的“新功能开放”通知。
5. 外婆展开下一阶段说明；玩家确认后再自动进入目标页。

同一操作开放核心功能和辅助入口时合并提示。例如首次成功购买水稻种子同时开放产出与库存，只显示一条组合通知。

## 9. 状态与服务职责

### 9.1 `core_feature_unlocks`

新增永久字典，作为核心功能开放的唯一真值。功能 ID 固定包含：

- `purchase`
- `output`
- `inventory`
- `research`
- `craft`
- `catalog`
- `list`
- `rulebook`
- `arrange`
- `business`
- `storefront_manage`
- `task`
- `starlight`

新存档只写入 `purchase`。其余 ID 只能通过本设计指定的成功事件写入。

### 9.2 `core_unlock_progress`

新增永久字典，记录需要组合判定的真实里程碑，例如：

- 米浆饮是否成功拖动。
- 米浆饮是否成功旋转。
- 是否成功打开橱窗经营页。
- 是否完成有成交的营业结算。

这些字段属于核心业务解锁，不再依赖 `tutorial_guide_showcase_moved` 等纯教学字段。

### 9.3 解锁服务

新增单一核心解锁服务，职责包括：

- 定义功能 ID、前置关系和顺序。
- 处理真实成功事件并返回本次新增开放项。
- 格式化锁定原因。
- 对加载状态执行前置闭包和证据修复。
- 保证同一功能不会重复通知或重复产生副作用。

服务不持有 UI 节点，不负责外婆台词，也不发任务奖励。

`TutorialProgress` 继续负责对话步骤，但不得成为功能门禁真值。`main_view.gd` 负责把真实业务成功结果交给核心解锁服务，再刷新页面和外婆引导。

## 10. 任务系统重设计

从 `game_data.json` 删除以下三个教学任务：

- `tutorial_l0_first_product`
- `tutorial_l0_open_shop`
- `tutorial_l0_first_business`

同时删除：

- 三个教学任务之间的前置关系。
- `growth_l1_sales_rhythm` 对 `tutorial_l0_first_business` 的前置引用。
- 星辉奖励配置中对 `tutorial_l0_first_business` 的 2 星辉映射。
- 只服务于这三个教学任务的通知和测试断言。

任务入口开放后，`growth_l1_sales_rhythm` 成为第一项成长任务，并通过 Lv.1 与任务入口开放状态控制可用性。

教学期间：

- 不累计成长任务。
- 不累计每日任务。
- 不展示任务完成弹窗、领取入口或角标。

最终对话确认并开放任务后，才开始记录任务事件。玩家不会看到已经完成的教学任务，也不会被要求重复教学动作。

## 11. 星辉入口

教学完成不发放星辉，星辉入口继续保持锁定。

后续成长任务真正增加 `recipe_starlight_total` 或可用星辉时，永久开放 `starlight`。星辉入口开放与具体自动化模块开放分离：进入星辉页不代表产出或厨房自动化已经开放，自动化仍使用现有等级、累计星辉和练习任务条件。

## 12. 保存、加载与防软锁

### 12.1 原子顺序

真实业务操作、核心解锁写入和存档必须处于同一条成功链：

```text
业务验证成功
-> 修改业务状态
-> 记录核心里程碑
-> 开放下一功能
-> 保存
-> 刷新 UI 与通知
```

失败操作不得写入里程碑或开放功能。

### 12.2 加载修复

加载时执行以下修复：

- 后续功能已开放时，补齐其全部前置功能。
- 已研发米浆饮时，至少补开研发、制作与图鉴。
- 已有米浆饮成品库存或可靠制作完成记录时，补开上架。
- 已有橱窗商品时，补开规则。
- 已有营业中、待结算或历史营业记录时，补开调整、营业和橱窗经营。
- 店铺等级不低于 Lv.1或任务系统已有有效后续进度时，补开完整核心经营闭环与任务。
- `recipe_starlight_total > 0` 时补开星辉。

修复只补开，不扣资源、不补任务奖励、不重放通知。

### 12.3 旧存档

旧存档缺少 `core_feature_unlocks` 时，根据等级、引导步骤、已研发配方、库存、橱窗商品、营业状态和任务状态一次性重建。不得默认只开放采购，否则会把已有经营存档锁回新手阶段。

## 13. 异常行为

- 首轮零成交：完成结算但不结束引导、不升级、不开放任务；外婆解释没有成交，并允许玩家补货、调整后再开一轮。
- 当前营业仍在运行：结算步骤显示等待状态，不允许伪造完成。
- 目标控件不存在、不可见或尺寸为零：保留当前阶段和锁定原因，不推进步骤。
- 正式弹窗阻塞：临时隐藏引导层，不改变核心解锁或本阶段提示停止状态。
- 锁定入口被点击：展示真实前置条件；核心下一入口可以重新唤起外婆说明。
- 一次等级提升开放多项内容：合并通知并一次刷新，避免弹窗队列淹没最终对话。
- 重播引导：不修改核心解锁、等级、任务状态、星辉或来源等级。

## 14. 预计实现边界

主要变更范围：

- `scripts/game_state.gd`：核心解锁账本、里程碑、保存加载与旧存档重建。
- 新增核心解锁服务脚本：顺序、条件、锁定原因和前置闭包。
- `scripts/tutorial_progress.gd`：新增结算阶段，改写“我自己来”，取消功能真值职责。
- `scripts/tutorial_dialogue_catalog.gd`：新增结算与最终任务开放台词。
- `scripts/main_view.gd`：业务成功事件接入、入口门禁、锁定反馈、等级刷新和任务事件总闸。
- `scripts/catalog.gd`：采购区域与产地开放等级，Lv.0 初始内容修正。
- `game_data.json`：删除三个教学任务及旧前置、奖励映射。
- 工作台启动器、采购区域、产出区域和橱窗按钮脚本/场景：统一锁标记与点击反馈。
- 聚焦自检：核心顺序、等级边界、任务起点、星辉入口、保存加载与 UI 锁定契约。

不为本功能拆分或重写无关的经营、库存、橱窗模拟和自动化服务。

## 15. 验证策略

### 15.1 核心状态自检

- 新存档只开放 `purchase`。
- 每个指定成功事件只开放预期功能。
- 失败操作、普通页面访问、其他规则入口和“我自己来”均不开放功能。
- 拖动与旋转必须各成功一次后才开放营业。
- 有成交结算才能进入最终对话。
- 最终确认只升到 Lv.1并开放任务，不增加金币或星辉。
- 重复事件、重播引导和重复加载不会重复副作用。

### 15.2 等级边界自检

- Lv.0 采购仅农场可用，且只有水稻种子可购买。
- Lv.0 产出仅农场可操作。
- Lv.1 开放养殖场、水塘、辅料、工具及相应 Lv.1 内容。
- Lv.2 开放林场及相应 Lv.2 内容。
- Lv.3–Lv.5 单项内容继续遵循目录等级。
- 等级不足的来源、产地和物品可见、带锁且不可操作。

### 15.3 任务与星辉自检

- 三个旧教学任务不存在。
- 教学期间成长任务与每日任务均不累计。
- 任务开放后 `growth_l1_sales_rhythm` 成为第一项成长任务并正常累计。
- 教学完成不产生星辉。
- 第一次真实获得星辉时开放星辉入口，自动化模块仍保持各自条件。

### 15.4 UI 与恢复自检

- 所有未开放入口、区域和操作显示统一锁标记。
- 点击锁定项显示准确原因，不能静默无响应。
- 锁定与解锁不会改变稳定布局位置。
- 存档加载执行前置闭包与业务证据修复。
- 旧存档不会被重新锁回新手阶段。
- 零成交、弹窗阻塞、目标缺失和制作中断均不会软锁。

Godot headless 验证必须从 `project-rest-new` 目录运行，并为每次命令提供可写的 `--log-file`。最终同时执行项目加载检查与 `git diff --check`。

## 16. 验收标准

- 新玩家从水稻种子开始，在外婆指引下依次掌握完整经营闭环。
- 任意时刻都能看见未来功能，但能清楚理解锁定原因和下一步目标。
- 只有真实业务成功能开放下一核心功能。
- 采购与产出具有持续到 Lv.5 的清晰内容增长，而不是一次性全部开放。
- 外婆引导结束前没有任务干扰，结束后任务页从真正的后续经营目标开始。
- 金币来自经营，星辉来自成长任务，外婆主线不混入无来源的经济奖励。
- 保存、加载、重播、零成交和旧存档均不会造成永久软锁或重复奖励。
