## 1. 文档目标

本文档是《邻街甜品店》的第一版可开发策划案。它承接 `doc/v1.md` 的治愈系甜品店愿景，也保留 `doc/v2.md` 的 Godot 原型边界，目标是让开发可以直接据此拆分任务并实现一个完整可玩的 PC 单机 MVP。

本版本不追求商业完整版内容量，而是优先验证三件事：

1. 玩家是否愿意反复尝试“食材 + 设备 = 新品”的配方发现。
2. 新品是否能通过上架、营业、顾客反馈形成经营决策。
3. 店铺升级是否能持续提供新食材、新设备、新顾客和新目标。

## 2. 游戏定位

### 2.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 游戏名 | 邻街甜品店 |
| 类型 | PC 单机、休闲模拟经营、配方收集 |
| 操作方式 | 键鼠优先，后续可适配手柄 |
| 视角与表现 | 2D UI 主导，少量店铺氛围插画或图标 |
| 首版目标时长 | 1.5-3 小时完成等级 1 到等级 5 |
| 付费设想 | 买断制单机，MVP 阶段不接入商业化 |

### 2.2 体验关键词

- 轻松：没有破产、倒闭、体力、抽卡、广告。
- 清晰：每次失败试做都给方向性线索。
- 有反馈：新品会改变顾客购买结果，营业结算会说明原因。
- 可收集：食材、设备、甜品、顾客反馈都能沉淀到图鉴或日志。
- 可扩展：MVP 的数据结构能支撑后续装修、NPC、节日和剧情扩展。

### 2.3 与参考作品的关系

本作参考《洋果子店rose2》的核心乐趣：通过食材组合和制作方式发现新甜品，再把新甜品用于经营循环。但本作在题材、配方数据、顾客反馈、数值、UI 和故事包装上做原创处理。

MVP 不复制复杂体量，也不照搬手游式长线资源消耗。重点是把“猜配方”和“经营反馈”打通，让玩家知道自己为什么研发、为什么上架某种甜品，以及下一步应该尝试什么。

## 4. 世界观与叙事包装

玩家接手一间位于社区街角的小甜品店。店铺背后有一小片可恢复的农场，镇外还有合作牧场和鱼塘。店铺原本只卖几种基础点心，但周围居民口味各异：学生喜欢便宜甜口，白领偏好咖啡和巧克力，亲子家庭需要水果和经典口味，健身居民希望清爽低负担。

玩家要通过采购、种植、养殖、收获、试做新品、观察顾客反馈，让这间小店从“刚开张的小铺”成长为“街区名店”。

MVP 的叙事只承担三个功能：

1. 给经营目标一个温暖背景。
2. 解释顾客反馈为什么重要。
3. 为后续 NPC、剧情和社区事件留下入口。

MVP 不写长篇剧情，不做分支对话。文案集中在开局提示、顾客反馈、研发线索、升级祝贺和等级 5 完成提示。

## 5. 核心循环

### 5.1 主循环

```text
获取食材
  -> 农场/牧场/鱼塘挂机收获
  -> 研发试做
  -> 解锁新品或获得线索
  -> 生产甜品
  -> 生产页上架并即时售卖
  -> 橱窗查看在售商品
  -> 获得金币、口碑、反馈
  -> 升级店铺
  -> 解锁新食材、新设备、新顾客、新配方空间
```

### 5.2 单轮游玩节奏

每 5-10 分钟玩家应完成一次明确推进：

- 解锁 1 个新甜品。
- 发现一种顾客偏好缺口。
- 凑齐升级所需金币、口碑或关键食材。
- 收获一批农场、牧场或鱼塘产物。
- 通过失败线索缩小试做范围。
- 调整橱窗后看到销量变化。

### 5.3 长期目标

MVP 的长期目标是达到店铺等级 5，并解锁至少 15 个甜品。等级 5 后不强制结束，可继续收集剩余配方、优化营业收益和查看图鉴。

## 6. 玩家资源

| 资源 | 用途 | 获取 | 设计原则 |
| --- | --- | --- | --- |
| 金币 | 采购、解锁产出场景、升级 | 售卖甜品 | 前期不紧张，后期用于推动升级和加速补货 |
| 口碑 | 升级、解锁高级客群 | 满足顾客偏好 | 体现经营质量，而不是单纯刷钱 |
| 店铺等级 | 控制内容解锁 | 金币 + 口碑升级 | 作为 MVP 的主进度线 |
| 食材库存 | 研发、生产 | 采购、农场、牧场、鱼塘 | 数值要简单，避免仓储管理负担 |
| 成品库存 | 上架售卖 | 生产 | 让生产和营业有明确连接 |
| 已解锁配方 | 决定可生产甜品 | 研发成功 | 收集目标的核心 |
| 研发线索 | 指导下一次试做 | 研发失败 | 避免纯随机试错 |

### 6.1 初始状态

- 金币：120。
- 口碑：0。
- 店铺等级：0。
- 橱窗槽位：1。
- 每轮顾客数：0；米浆饮上架后升到 Lv.1 并立即进入正式营业结算。
- 已解锁配方：无。
- 可见采购：农作 `水稻种子`、水塘 `泉水`、配料 `白糖`、工具 `灵巧的双手`。
- 可用研发工具：灵巧的双手。
- 已解锁产出场景：农场 1 块田地。
- 新手目标：种植并收获水稻，研发米浆饮，制作并上架米浆饮后自动升到 Lv.1。

### 6.1.1 Lv.0 新手生产线

Lv.0 是正式生产线的第一段，不是临时流程。玩家在 Lv.0 使用后续同一套采购、产出、研发、生产、上架和橱窗展示机制，只是可用内容被限制在新手线。

流程：

1. 在 `采购` 页默认打开 `农作` tab，获得或购买 `水稻种子`。
2. 在 `采购` 页的 `水塘` tab 获得或购买 `泉水`。
3. 在 `采购` 页的 `配料` tab 获得或购买 `白糖`。
4. 在 `农场` 种植 `水稻种子`。`水稻种子` 只用于种植，收获产物是 `水稻`。
5. 首次收获 `水稻` 完成任务 1：`收获第 1 批水稻`，奖励并弹窗解锁工具 `蒸煮一体的圆锅`。
6. 在 `研发` 页左键点击材料 `水稻`、`泉水`、`白糖`，并选择工具 `蒸煮一体的圆锅`，解锁 `米浆饮`。
7. 解锁 `米浆饮` 完成任务 2：`解锁第 1 份食谱`，奖励并弹窗解锁工具 `研磨机`。
8. 在 `生产` 页制作 `米浆饮`。制作完成后在生产页直接点击 `上架`。
9. `米浆饮` 上架后自动从 Lv.0 升到 Lv.1，并立即结算一轮营业。

`橱窗` 页始终展示正在上架的商品；当前阶段不提供上架、开始营业等操作，后续可扩展为增加槽位等经营升级入口。

### 6.2 经济原则

- 研发失败会消耗材料，但成本不应让玩家卡死。
- 基础食材价格低，玩家可连续尝试数次；农场、牧场、鱼塘提供稳定补给，减少纯金币采购压力。
- 售价和产出份数要保证正确生产后总体正收益。
- 升级成本应鼓励玩家优化橱窗，而不是长时间重复点击营业。

### 7.2 食材来源规则

食材有两种获取路径：

1. **采购**：花费金币立即获得，适合补齐缺口、快速研发、避免等待。
2. **自产**：通过农场、牧场、鱼塘挂机产出，适合稳定补给和长期规划。

MVP 中所有食材都允许通过采购获得，防止玩家被产出等待卡住；有主要来源的食材会在对应场景中以更低成本或免费产出。主要来源影响推荐玩法，不限制配方使用。例如鸡蛋和牛奶的主要来源是牧场，但牧场解锁前仍可通过采购获得。

### 7.3 采购规则

采购界面只显示当前等级已解锁食材。玩家选择数量后购买，系统立即扣金币并增加库存。

MVP 的数量单位是“份”，不细分克、毫升、个。每次研发或生产按配方消耗固定份数，默认每种材料消耗 1 份。

### 7.4 采购交互要求

- 食材卡显示名称、价格、库存、标签和解锁等级。
- 金币不足时购买按钮禁用，并显示“金币不足”。
- 支持单次购买 1、5、10 份。
- 购买后在反馈栏追加日志，例如“购买草莓 x5，花费 40 金币”。

## 8. 农场、牧场与鱼塘

### 8.1 设计定位

农场、牧场、鱼塘是 MVP 的轻挂机食材来源。它们不是完整农场游戏，也不要求玩家进行复杂地图操作。它们的作用是让食材来源从“只花金币购买”扩展为“经营产出 + 金币补货”，增强计划感。

### 8.2 场景分工

| 场景 | 解锁等级 | 主要产物 | MVP 操作 |
| --- | ---: | --- | --- |
| 农场 | 1 | 草莓、蓝莓、香蕉、苹果、柠檬、红豆、蜂蜜、坚果 | 选择作物，等待若干营业轮后收获 |
| 牧场 | 2 | 鸡蛋、牛奶、黄油、奶油、芝士、酸奶 | 派送饲料订单，等待若干营业轮后收获 |
| 鱼塘 | 3 | 海盐、鱼胶、珍珠粉等后续水产材料 | MVP 只做场景入口和 1 个水产测试产物 |

说明：当前 18 个 MVP 配方暂不强依赖水产材料。鱼塘进入 MVP 的目的，是提前建立“第三类产出场景”的结构，为后续布丁、果冻、海盐焦糖、水产限定配方扩展做准备。

### 8.3 产出规则

MVP 不使用真实时间，使用“营业轮数”推进产出。

| 场景 | 基础槽位 | 成熟条件 | 单次产出 |
| --- | ---: | --- | --- |
| 农场 | 2 | 经过 2 轮营业 | 目标作物 x3 |
| 牧场 | 1 | 经过 2 轮营业 | 目标产物 x4 |
| 鱼塘 | 1 | 经过 3 轮营业 | 海盐 x2 |

玩家每次营业结算后，所有已安排的产出槽位进度 +1。达到成熟条件后，场景页显示“可收获”。收获后食材进入库存，槽位变为空闲。

### 8.4 成本与限制

- 农场播种消耗少量金币，默认是该食材采购价的 30%。
- 牧场派送饲料订单消耗少量金币，默认是该食材采购价的 40%。
- 鱼塘投喂消耗少量金币，默认是该食材采购价的 40%。
- 同一槽位同一时间只能安排 1 种产物。
- 玩家可以取消未成熟任务，但不返还成本。
- 达到成熟后不会腐烂，不增加惩罚压力。

### 8.5 解锁与升级关系

| 店铺等级 | 解锁 |
| ---: | --- |
| 1 | 农场，2 个农场槽位，可种草莓 |
| 2 | 牧场，1 个牧场槽位，可收鸡蛋、牛奶、奶油 |
| 3 | 鱼塘入口，1 个鱼塘槽位；农场新增红豆；牧场新增芝士 |
| 4 | 农场新增坚果；牧场新增酸奶 |
| 5 | 产出场景不再新增机制，只用于支撑招牌甜品生产 |

### 8.6 UI 交互要求

主界面增加“产出”标签，内部用分段按钮切换农场、牧场、鱼塘。

每个产出槽位显示：

- 当前产物。
- 剩余营业轮数。
- 预计产出数量。
- 开始、取消、收获按钮。

反馈栏日志示例：

```text
农场开始种植草莓，预计 2 轮营业后收获。
牧场送来了牛奶 x4。
鱼塘收获了海盐 x2。
```

## 10. 配方系统

### 10.1 判定规则

每个配方由“设备 + 必须材料”判定。研发时玩家选择：

- 1 个设备。
- 2-3 个材料。材料可以是食材，也可以是允许作为中间材料的成品。

判定原则：

1. 设备必须正确。
2. 所有必须材料必须被选中。
3. 额外材料不直接导致失败。
4. 如果同一组合可命中多个配方，优先解锁材料数量更多、解锁等级更高的配方。

## 11. 研发系统

### 11.1 操作流程

1. 玩家进入“研发”标签。
2. 选择一个设备。
3. 从材料列表选择 2-3 个材料。
4. 系统展示预计消耗。
5. 点击“试做”。
6. 根据判定结果展示成功卡片或失败线索。

### 11.2 成功反馈

研发成功时：

- 消耗所选材料各 1 份。
- 解锁新配方。
- 奖励口碑 2-5 点，等级越高的配方奖励越高。
- 在反馈栏追加“新品研发成功”日志。
- 在图鉴中显示完整配方信息。

成功弹窗内容：

- 甜品名称。
- 标签。
- 售价。
- 产出份数。
- 一句风味描述。

### 11.3 失败反馈

研发失败时：

- 消耗所选材料各 1 份。
- 不扣金币。
- 记录一条线索到反馈栏和图鉴线索区。

失败线索优先级：

| 优先级 | 条件 | 文案 |
| ---: | --- | --- |
| 1 | 存在同材料但设备错误的配方 | 这个组合也许不适合当前设备。 |
| 2 | 存在只差 1 个材料的配方 | 味道接近了，但还缺少某种{材料类型}。 |
| 3 | 可命中但等级不足 | 店铺经验还不足以稳定制作这种新品。 |
| 4 | 材料标签有部分相近 | 这些风味有一点方向，但还没有形成稳定商品。 |
| 5 | 完全无关 | 这次试做没有形成稳定商品。 |

### 11.4 防卡死规则

- 若玩家金币低于 30 且基础食材库存不足 6 份，系统可提供一次“邻居试吃补给”：获得面粉、鸡蛋、牛奶、白糖各 2 份。
- 补给每天最多 1 次。MVP 没有真实天数时，可用“每 5 次营业刷新 1 次”替代。
- 该规则用于避免研发失败导致无法继续，不作为主要资源来源。

## 12. 生产系统

生产是短时倒计时行为。配方在配置中显式声明 2 / 4 / 8 秒复杂度时长；点击制作后立即扣除材料，到期后成品自动入库。

### 12.1 操作流程

1. 进入“生产”标签。
2. 查看已解锁配方列表。
3. 选择配方。
4. 系统展示所需材料、当前库存、产出份数。
5. 点击“制作”。
6. 立即消耗材料并开始一个制作队列。
7. 倒计时结束后增加成品库存，并在此时结算配方成长、设备成长、任务和新手引导。

### 12.2 批量规则

普通手动制作每次只启动 1 批，不提供“制作 5 批”。

- 每次点击：立即消耗配方材料各 1 份，启动一个制作队列；完成后获得配方产出份数。
- “制作全部”：按当前顺序为每个材料充足的成品配方各启动 1 个队列；中间材料加工仍即时完成。
- 当前阶段不做设备排产：设备只要解锁，同一设备可以支撑任意数量并行制作队列。
- 配方行聚合显示“制作中 xN｜最近完成 N 秒”，不为每批制作单独增加一行。
- 离线只推进已经开始的普通手动制作队列，不会在离线期间自动创建新队列；完成的成品自动入库并汇总提示。
- 自动化规则仍可选择 1 / 5 批，但每条规则同一时刻至多有 1 个活动队列；不同规则及手动队列可以并行。

### 12.3 生产反馈

开始制作与在线完成时分别显示：

```text
已开始制作：海绵杯蛋糕，预计 2 秒。
制作完成：1 个队列，共获得 3 份成品。
```

如果材料不足：

```text
库存不足，缺少：鸡蛋。
```

## 13. 橱窗系统

橱窗决定营业时哪些成品可以被购买。

### 13.1 槽位数量

| 店铺等级 | 槽位数 |
| ---: | ---: |
| 1 | 3 |
| 2 | 4 |
| 3 | 4 |
| 4 | 5 |
| 5 | 5 |

### 13.2 上架规则

- 每个槽位选择 1 种成品。
- 可以多个槽位上架同一种成品，但 MVP 不建议默认引导这样做。
- 槽位只绑定商品类型，不锁定数量。
- 营业时从成品库存中扣除实际售出的份数。
- 成品库存为 0 的商品会显示“缺货”，仍可保留在槽位中，但营业会产生缺货反馈。

### 13.3 操作要求

- 橱窗页显示每个槽位的商品、库存、售价、标签。
- 可一键清空槽位。
- 更换槽位商品不消耗资源。
- 有未上架商品时，生产页应提示“可前往橱窗上架”。

### 14.1 顾客表

| --- | --- | --- | ---: | ---: | --- |

| office_worker | 加班白领 | 苦甜, 浓郁 | 35 | 2 | 偏好咖啡、巧克力、奶油 |

| fitness_neighbor | 健身居民 | 清爽, 低负担 | 35 | 3 | 喜欢酸奶、清爽、水果 |
| old_regular | 老街熟客 | 经典, 甜 | 30 | 3 | 偏好朴素熟悉的点心 |
| blogger | 探店博主 | 招牌, 稀有 | 50 | 5 | 追求高价值和特色标签 |

说明：`低价` 和 `稀有` 不是甜品标签，而是购买判定中的派生条件。

### 14.2 每轮顾客数

| 店铺等级 | 顾客数 |
| ---: | ---: |
| 1 | 6 |
| 2 | 8 |
| 3 | 10 |
| 4 | 12 |
| 5 | 14 |

### 14.3 顾客生成

每轮营业时，从当前等级已解锁的顾客池中随机生成顾客。生成权重：

- 当前等级新解锁顾客权重略高，帮助玩家感知新需求。
- 等级 1 保证至少出现 3 名学生。
- 等级 5 保证至少出现 1 名探店博主。

### 14.4 商品评分

每个顾客从橱窗中选择得分最高且有库存的商品。

```text
基础得分 = 标签匹配数 * 10
价格惩罚 = max(0, 售价 - 预算) * 1
低价加成 = 售价 <= 20 且顾客偏好低价 ? 8 : 0
招牌加成 = 商品有招牌标签且顾客偏好招牌 ? 12 : 0
最终得分 = 基础得分 + 低价加成 + 招牌加成 - 价格惩罚
```

购买规则：

- 最终得分大于 0：购买得分最高商品。
- 最终得分小于等于 0：顾客离开并留下反馈。
- 如果得分最高商品缺货，检查下一高分商品；若都缺货，记录缺货反馈。

### 14.5 营业结算

玩家在 `生产` 页把成品甜品点击 `上架` 后，系统立即结算一轮营业。`橱窗` 页只展示当前在售商品和库存，不提供“开始营业”操作。

结算展示：

- 售出数量。
- 获得金币。
- 获得口碑。
- 缺货次数。
- 未满足偏好。
- 最受欢迎商品。

口碑获得：

```text
每次成功购买口碑 = 1 + 标签匹配数
探店博主购买招牌商品额外 +3
```

### 14.6 反馈示例

- “放学学生买走了黄油曲奇：价格合适，而且很甜。”
- “加班白领没有找到苦甜或浓郁的甜品。”
- “亲子家庭想买草莓牛乳杯，但库存已经卖完。”
- “探店博主被邻街招牌芭菲吸引，发布了好评。”

## 18. 美术与音效方向

### 18.1 MVP 美术

MVP 可以使用简洁 2D UI、色块、图标和少量临时素材。优先保证可读性和操作效率。

建议风格：

- 温暖但不单调的社区甜品店配色。
- 白色、浅粉、薄荷绿、深咖啡作为基础组合。
- 食材和甜品图标可以先用文字卡片代替，后续替换为手绘图标。
- 按钮和卡片圆角克制，信息密度适合 PC 屏幕。

### 18.2 音效

MVP 可先不接入完整音频，但应预留事件：

- 研发成功。
- 研发失败。
- 制作完成。
- 产物成熟或收获。
- 售出商品。
- 升级成功。

后续可加入轻柔背景音乐、烤箱叮声、收银声和门铃声。

| recipe_book.gd | 研发匹配、配方解锁、失败线索生成 |
| shop_simulation.gd | 顾客生成、商品评分、购买判定、营业结算 |
| save_system.gd | JSON 存档读写、版本兼容 |
| main_view.gd | 引用场景节点、绑定按钮事件、刷新页面状态；不负责动态创建主页面布局 |
| mvp_self_check.gd | 自动检查核心数据和主要流程 |

### 19.4 数据组织

第一版推荐把静态数据写在 `catalog.gd` 的字典中。原因：

- 内容量小，调试直接。
- 不需要额外资源导入流程。
- 方便测试脚本直接读取。

当配方超过 50 个或需要策划独立维护时，再迁移到 JSON、CSV 或 Godot Resource。

### 19.5 存档字段

存档路径：

```text
user://neighbor_dessert_save.json
```

存档字段：

```json
{
  "version": 1,
  "coins": 120,
  "reputation": 0,
  "shop_level": 1,
  "ingredient_inventory": {},
  "product_inventory": {},
  "production_slots": [],

  "display_slots": [],
  "discovered_hints": {},
  "feedback_log": [],
  "business_runs": 0

```

### 19.6 自动保存

以下行为后自动保存：

- 采购成功。
- 安排、取消或收获产出槽位。
- 研发成功或失败。
- 生产成功。
- 橱窗变更。
- 营业结算。
- 升级成功。

读取失败时：

- 备份损坏存档为 `.broken` 文件。
- 创建新存档。
- 在状态栏显示“存档读取失败，已创建新存档”。

## 20. 开发阶段

### 20.1 阶段 1：数据与状态

目标：让核心数据可被脚本读取和修改。

任务：

- 创建 `catalog.gd` 静态数据。
- 创建 `game_state.gd`。
- 实现库存增减、金币口碑增减、等级读取。
- 实现基础存档读写。

验收：

- 新游戏能生成初始状态。
- 修改金币、库存、已解锁配方后能保存并读取。
- 所有食材、产出场景、设备、配方、顾客 ID 唯一。

### 20.2 阶段 2：产出场景

目标：让食材获取从纯采购扩展为采购 + 自产。

任务：

- 实现农场、牧场、鱼塘静态数据。
- 实现产出槽位的开始、推进、收获、取消。
- 营业后推进产出进度。
- 实现产出场景 UI。

验收：

- 农场能种植并收获草莓。
- 牧场能安排并收获牛奶或鸡蛋。
- 鱼塘能安排并收获海盐。
- 未成熟时不能收获，成熟后不会腐烂。
- 产出进度能保存并读取。

### 20.3 阶段 3：研发与生产

目标：验证“食材 + 设备 = 新品”的核心乐趣。

任务：

- 实现研发匹配。
- 实现研发失败线索。
- 实现配方解锁。
- 实现即时生产。

验收：

- 正确组合能解锁所有 18 个配方。
- 错误设备返回设备线索。
- 差 1 个材料返回材料类型线索。
- 材料不足时不能研发或生产。

### 20.4 阶段 4：橱窗与营业

目标：让新品进入经营循环。

任务：

- 实现橱窗槽位。
- 实现顾客生成。
- 实现商品评分和购买判定。
- 实现营业结算。

验收：

- 上架商品能被顾客购买。
- 标签匹配会明显影响销量和口碑。
- 缺货会产生反馈。
- 没有合适商品时顾客会离开并说明偏好缺口。
- 每次营业后产出槽位进度正确推进。

### 20.5 阶段 5：升级与图鉴

目标：形成完整 MVP 进度线。

任务：

- 实现升级消耗和解锁。
- 实现图鉴页面。
- 实现未解锁线索展示。
- 实现等级 5 完成提示。

验收：

- 玩家可从等级 1 升到等级 5。
- 升级后新食材、设备、顾客、槽位立即可用。
- 图鉴能显示已解锁配方完整信息。
- 等级 5 展示 MVP 完成提示。

### 20.6 阶段 6：UI 整理与自检

目标：让原型可稳定试玩。

任务：

- 在 `Main.tscn` 中完成单主界面多标签 UI 布局。
- `main_view.gd` 只做节点引用、事件绑定和状态刷新，避免在代码里动态创建页面组件。
- 补齐按钮禁用原因。
- 补齐反馈日志和状态栏。
- 创建自动自检脚本。
- 调整数值节奏。

验收：

- 不看代码也能完成一轮采购、自产收获、研发、生产、上架、营业、升级。
- 关键错误有可见提示。
- 自检脚本通过。
- 试玩可在 1.5-3 小时达到等级 5。

## 21. 自动化自检

建议创建 `res://tests/mvp_self_check.gd`，使用 headless Godot 执行。

自检内容：

1. 静态数据完整性：
   - 食材 ID 唯一。
   - 产出场景 ID 唯一。
   - 设备 ID 唯一。
   - 配方 ID 唯一。
   - 配方引用的材料都存在于食材或可作为中间材料的配方。
   - 顾客引用的偏好标签可被商品或派生规则处理。

2. 核心流程：
   - 初始状态正确。
   - 可购买基础食材。
   - 可安排农场产出并在营业后推进进度。
   - 可收获成熟产物并进入食材库存。
   - 可研发 `海绵杯蛋糕`。
   - 可生产 `海绵杯蛋糕`。
   - 可上架并营业出售。
   - 金币和口碑结算变化合理。

3. 升级流程：
   - 满足消耗时可升级。
   - 升级后解锁内容可见。
   - 槽位数量随等级正确变化。

4. 存档：
   - 保存后读取状态一致。
   - 产出槽位保存后读取状态一致。
   - 缺字段存档能用默认值补齐。

## 22. MVP 验收标准

### 22.1 功能验收

- 能购买当前等级已解锁食材。
- 能安排农场、牧场、鱼塘产出。
- 营业后产出进度会推进。
- 成熟产物能被收获进食材库存。
- 能用正确组合解锁 18 个配方。
- 错误组合能返回有方向的线索。
- 已解锁甜品能被生产。
- 成品能被放入橱窗槽位。
- 营业能按顾客偏好出售商品。
- 售卖后金币、口碑、库存正确变化。
- 缺货和不匹配会产生顾客反馈。
- 满足条件后能升级店铺。
- 升级能解锁新内容。
- 图鉴能展示已解锁配方和未解锁线索。
- 退出重进后能恢复存档。

### 22.2 体验验收

- 玩家 5-10 分钟内能完成一次明显推进。
- 玩家能理解采购是加速补货，自产是稳定补给。
- 玩家能从反馈中理解下一步该研发或上架什么。
- 研发失败不会让玩家长期停滞。
- 营业不是纯自动结算，橱窗选择会明显影响结果。
- 等级 5 前持续有新内容出现。

### 22.3 完成定义

MVP 达成条件：

- 玩家可以从新存档经营到店铺等级 5。
- 自动自检通过。
- 至少 15/18 个配方可通过正常游玩解锁。
- 农场、牧场、鱼塘至少各能完成 1 次产出闭环。
- 所有主界面按钮都有有效或禁用反馈。
- 无阻断性崩溃、死循环、存档损坏。

## 23. 主要风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 试做过于随机 | 玩家不知道该放什么材料 | 失败线索按设备、缺材料、等级不足分层 |
| 自产系统拖慢节奏 | 玩家等产出而不继续经营 | 所有核心食材仍可采购，自产只负责降低成本和制造规划感 |
| UI 信息过载 | 单主界面太挤 | 使用左侧标签切换，右侧只保留最近日志 |
| 营业缺少掌控感 | 玩家只是在点结算 | 让橱窗标签匹配决定销量和口碑 |
| 经济节奏拖慢 | 升级需要重复刷钱 | 第一版升级成本偏宽松，试玩后再上调 |
| 复合配方困惑 | 玩家不知道成品也能研发 | 只保留一条复合链，并在图鉴给明确线索 |
| 存档问题阻断试玩 | 读取失败无法继续 | 损坏存档备份并创建新存档 |

## 24. 后续版本方向

MVP 验证通过后，建议按以下顺序扩展：

1. 产出场景升级：田地扩容、动物产出差异、鱼塘水产配方。
2. 常客系统：给顾客加入名字、来访记录和专属偏好。
3. 轻装修：家具影响客流、口碑或某类标签销量。
4. 社区事件：雨天、考试周、节日集市改变需求。
5. NPC 剧情：把常客转为角色，解锁专属配方。
6. 四季食材：引入季节限定食材和限时配方。
7. 生产队列：让设备成为时间管理资源。
8. 更多配方链：从 18 个扩展到 60 个以上。

## 25. 设计结论

《邻街甜品店》MVP 的核心不是内容堆量，而是验证一个清晰闭环：

```text
玩家规划食材来源 -> 观察顾客需求 -> 尝试研发新品 -> 用新品改善橱窗 -> 营业反馈证明选择有效 -> 升级获得新可能
```

只要这个闭环成立，后续的装修、NPC、四季、剧情、更大配方库和更深的农牧鱼塘经营都可以自然扩展。第一版开发应严格守住 MVP 边界，优先做出稳定、可玩、反馈明确的单界面经营原型。
