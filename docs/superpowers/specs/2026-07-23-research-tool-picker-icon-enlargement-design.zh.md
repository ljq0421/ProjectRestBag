# 研发工具选择弹窗图标放大设计

## 目标

放大研发工具选择弹窗中的六张工具卡片及其设备图标，使玩家能够直接辨认
`device_v1` 设备素材。调整只作用于弹窗，不改变研发页面左侧的已选工具主槽。

## 已确认的现状

- 弹窗使用三列两行布局，当前尺寸为 `720×408`。
- 每张工具卡片当前为 `168×120`。
- 卡片内部仍使用 `research_input_slot.tscn` 的 `52×52` 默认图标框。
- 弹窗卡片与左侧主槽复用同一场景，但左侧主槽会通过
  `_set_research_input_slot_visual(..., fill_slot = true)` 单独覆盖为全填充。
- `device_v1` 图标是 `1024×1024` 正方形透明 PNG，设备主体保留了不同方向的
  透明边距。

## 视觉与交互合同

1. 六张弹窗工具卡片统一调整为 `168×168`。
2. 弹窗调整为 `720×504`，继续使用三列两行、`16px` 横纵间距、
   `64px` 水平内容边距和 `48px` 垂直内容边距。
3. 每张卡片的 `TextureRect` 填满整个 `168×168` 卡片。
4. 图标继续使用 `STRETCH_KEEP_ASPECT_CENTERED`，保持比例、居中显示且不裁切。
5. 弹窗卡片不显示底部名称条和名称文字。
6. 卡片 Tooltip 只显示对应工具名称。
7. 左侧已选工具主槽继续保持 `104×104`、名称条可见和现有 Tooltip，不受影响。

“填满卡片”指纹理节点边界填满 `168×168`。PNG 自身的透明留白继续保留，
不对源图片进行裁边、重采样或覆盖。

## 实现边界

`scripts/main_view.gd` 继续负责动态创建弹窗卡片。扩展
`_set_research_input_slot_visual()`，允许调用方分别控制图标是否填满卡片以及
名称层是否显示。弹窗卡片调用全填充并关闭名称层；现有主槽和材料槽沿用当前
参数行为。

`RESEARCH_TOOL_PICKER_CELL_SIZE` 改为 `Vector2(168, 168)`，
`RESEARCH_TOOL_PICKER_POPUP_SIZE` 改为 `Vector2i(720, 504)`。
不调整 `workbench_pages.tscn` 中已确认的弹窗皮肤、网格列数、边距或间距。

## 失败与回退行为

设备纹理缺失时保持现有行为：图标节点隐藏，卡片仍可通过 Tooltip 说明工具名称，
不会新增占位图或改变设备选择逻辑。

## 验证

扩展 `tests/research_input_strip_self_check.gd`，在真实打开弹窗后验证：

- 弹窗为 `720×504`。
- 六张卡片均为 `168×168`。
- 每张卡片的图标节点填满父卡片并保持等比居中模式。
- 名称条与名称文字均隐藏。
- Tooltip 与工具名称一致。
- 左侧主槽仍为 `104×104`，名称层继续可见。
- 选择工具仍会关闭弹窗、更新选择且保留已选材料。

随后运行聚焦测试、`mvp_self_check.gd`、Godot 项目解析和
`git diff --check`。

## 非目标

- 不修改 `device_v1` PNG。
- 不修改设备解锁、研发、成长或配方逻辑。
- 不改变弹窗列数、主题皮肤或卡片间距。
- 不修改左侧已选工具主槽、材料槽或其他图标卡片。
- 不改动其他 checkout。
