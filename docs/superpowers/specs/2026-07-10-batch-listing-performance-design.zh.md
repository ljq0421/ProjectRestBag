# “上架全部”性能优化设计

## 目标

将“研发制作”和库存弹层中的批量上架从“逐份复用单件拖拽完整流程”改为“批量更新状态，结束后统一持久化和刷新”，消除库存数量增长时的明显卡顿。

## 保持不变的行为

- 单件按钮上架、库存拖拽、橱窗移动与旋转继续使用 `_drop_showcase_data()`，其即时反馈、存档和刷新行为不变。
- 批量上架仍按已解锁配方顺序寻找第一个可用区域；已摆放的标准变体继续追加库存。
- 橱窗无可用区域或现有摆位变体不兼容时，跳过该配方并继续处理后续配方。
- 最终状态文案仍为“已上架 N 份成品。”或“没有可上架的成品库存。”。
- `TutorialProgress.on_product_displayed()` 接收实际批量数量，任务累计语义不变。

## 状态路径

`_list_all_available_products()` 对每个有库存的配方只执行一次批量操作：

1. 读取该配方当前全部成品库存。
2. 已摆放时，计算一次售卖时间并调用 `add_display_item_stock(recipe_id, quantity, ...)`。
3. 未摆放时，用无 UI 副作用的查位 helper 找到首个可用区域，计算一次预览加成，然后调用 `list_display_item(recipe_id, cells, quantity, ...)`。
4. 同步一次兼容 `display_slots` 数据。
5. 仅在新增摆位改变布局时使橱窗加成缓存失效。

批量函数内部不调用 `_save_game()`、库存网格刷新、橱窗网格重建或通知弹窗。现有两个入口在批量结束后各自执行一次存档和一次最终刷新。

## 回归验证

- 直接调用 `_list_all_available_products()` 时，全部库存被转入橱窗。
- 批量函数内部不创建存档文件。
- 批量函数内部不替换已有橱窗按钮节点。
- 从研发制作按钮和库存弹层按钮进入时，最终存档与 UI 仍会刷新。
- 原有单件拖拽、摆位、锁定格、移动、旋转和售卖自检继续通过。
