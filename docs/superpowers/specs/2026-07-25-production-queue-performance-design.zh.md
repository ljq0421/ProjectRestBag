# 制作队列性能修复设计

日期：2026-07-25  
项目：`project-rest-new`

## 1. 背景与已确认事实

制作队列重构后，`main_view.gd::_process()` 每秒调用
`_refresh_production_workbench()`。该刷新同时执行以下工作：

1. 计算制作队列进度；
2. 完整构建“可制作”配方列表；
3. 完整构建“缺材料”配方列表；
4. 配方选择器打开时，再次完整构建上述两个列表；
5. 重新绑定队列行、配方卡片、拖拽数据与槽位样式。

当前运行存档包含 79 个已解锁配方和 4 个加工项目。修复前实测：

| 操作 | 单次耗时 |
| --- | ---: |
| 计算队列条目 | 约 0.21 ms |
| 构建可制作列表 | 约 26.5 ms |
| 构建缺材料列表 | 约 348.4 ms |
| 普通制作台刷新 | 约 452 ms |
| 配方选择器打开时刷新 | 约 742 ms |
| 选择器打开时整页刷新 | 约 914 ms |

主要耗时来自配方列表构建中的重复扫描和重复深拷贝。`Catalog` getter
使用 `duplicate(true)` 返回嵌套数据副本，而列表构建的辅助函数会在每个
配方、每种材料和每个显示字段中重复调用这些 getter。

## 2. 目标

1. 每秒计时刷新不得重建配方选择器数据。
2. 一次状态刷新最多完整扫描一次可用配方和加工项目。
3. 同一次扫描同时生成“可制作”和“缺材料”两组数据及其数量。
4. 配方选择器打开、切换页签和操作后的显示结果保持正确。
5. 队列进度、完成反馈、成品库存拖拽和稳定排序保持现有契约。
6. 修复后不改变全项目现有 `Catalog.get_*()` 的复制语义。

## 3. 非目标

本次不包含：

- 全局替换或删除 `Catalog.get_*()` 中的 `duplicate(true)`；
- 改变制作时长、并发上限、完成结算或存档格式；
- 改变配方选择器布局、文案、搜索语义或排序规则；
- 改变补货、制作、加工、上架和批量操作的业务授权；
- 为所有项目页面建立通用响应式状态框架；
- 修改现有未跟踪的配方图片资源。

全局 Catalog 只读接口属于后续独立优化。若实施，应新增明确的只读快照
或引用 API，迁移并验证调用方后再考虑改变旧 getter 语义。

## 4. 方案比较

### 4.1 采用方案：拆分刷新频率并合并配方扫描

- 每秒只更新队列进度和剩余时间；
- 状态事件触发一次完整制作台刷新；
- 一次配方扫描同时产出两个页签的数据；
- 选择器刷新复用同一份快照；
- 页签切换只切换快照中的可见数组，不重新扫描业务数据。

该方案直接移除已确认的高频阻塞，同时保持变更范围集中。

### 4.2 未采用：仅缓存配方选择器最终结果

该方案可以减少重复计算，但若没有明确失效边界，库存、队列、解锁和补货
变化后容易显示旧数据。它还不能解决首次构建中的重复扫描。

### 4.3 未采用：全局改变 Catalog getter 语义

生产代码中存在 179 处相关 getter 调用。直接返回共享字典虽然可能提高
其他页面性能，但会扩大验证范围，并可能让调用方的意外修改污染全局数据。
这不是修复当前卡顿所必需的条件。

## 5. 刷新架构

### 5.1 每秒队列刷新

新增轻量队列刷新路径
`_refresh_production_queue_tick(now_unix)`：

1. 调用 `state.recipe_production_queue_summary(now_unix)`；
2. 合并现有完成反馈和持久化成品行；
3. 更新已有队列行的进度、剩余时间和完成反馈；
4. 只在队列身份确实变化时新增、删除或移动行；
5. 不计算配方选择器列表，不更新配方卡片。

`_process()` 在完成手动与自动制作结算后调用该轻量路径。制作完成导致的
库存或队列结构变化继续通过现有事件刷新路径同步。

### 5.2 事件级制作台刷新

`_refresh_production_workbench()` 保留为状态事件级入口：

1. 完整刷新队列结构；
2. 构建一次配方选择器快照；
3. 更新右侧“可制作 / 缺材料”数量；
4. 若选择器已打开，直接使用同一快照刷新当前页签。

它继续由页面打开、制作、加工、补货、上架、批量操作、解锁变化和完整
页面刷新调用，但不再由每秒时钟无条件调用。

### 5.3 配方选择器快照

新增单次构建函数 `_build_production_picker_snapshot()`，返回：

```gdscript
{
	"craftable": Array,
	"missing": Array,
	"craftable_count": int,
	"missing_count": int
}
```

构建过程只遍历一次已解锁配方和可用加工项目。每个项目只计算一次：

- 当前批次数与剩余容量；
- 缺失材料；
- 补货报价与是否可补货；
- 库存和是否可上架；
- 材料摘要；
- 不可用原因；
- 搜索文本；
- 显示图标。

根据缺失材料结果，将同一个完成条目放入对应数组。两个数组分别保持现有
排序规则。

### 5.4 Catalog 数据边界

单次快照构建开始时获取一次所需 Catalog 数据：

- recipes；
- ingredients；
- devices；
- processing recipes。

快照辅助函数通过参数使用这些局部数据，不在内部重新调用 Catalog getter。
这些数据仅作读取，不写回、不修改嵌套条目。

本次不改变 Catalog 公共接口，以免影响项目其他 179 处生产调用。

### 5.5 选择器复用与失效

`main_view.gd` 保存最近一次选择器快照。规则如下：

- 打开选择器时强制构建新快照；
- 制作、加工、补货、上架、批量操作或完整页面刷新后构建新快照；
- 页签切换和搜索输入只复用当前快照；
- 每秒仅推进倒计时，不使快照失效；
- 手动或自动制作完成时，现有完成结算路径触发事件级刷新；
- 关闭选择器后允许保留快照，但下次打开仍重新构建。

卡片显示不是业务授权。玩家执行操作时继续使用现有业务函数重新验证真实
库存、容量、金币、解锁和橱窗状态。

## 6. 队列行增量更新

`ProductionWorkbench` 区分结构刷新和计时刷新：

- 结构刷新可以创建、删除、移动和完整配置配方行；
- 计时刷新只更新已存在行的三个批次槽位及队列摘要；
- 若轻量刷新发现意外的新行或缺失行，回退到该行的完整配置，不丢失显示。

`ProductionQueueRecipeRow` 的槽位样式按视觉状态复用。只有
`active / completed / empty` 状态变化时才创建或替换样式；进度数值与剩余
文本变化不再每秒新建 `StyleBoxFlat`。

已完成成品的拖拽字典、图标和静态身份信息只在结构或库存状态变化时重新
配置，不在单纯倒计时刷新中重复复制。

## 7. 正确性与异常处理

- 空队列仍显示现有空状态；
- 完成反馈到期后槽位恢复正确状态；
- 成品库存仍可与最多三批活动制作共存；
- 拖走最后一件成品后，持久化记录和队列行仍按现有规则清理；
- 自动制作新增批次后必须出现在下一次事件级刷新中；
- 选择器打开期间制作完成时，两个页签、数量和卡片库存同步刷新；
- 若快照为空或数据类型异常，显示现有空状态，不保留上一轮错误卡片；
- 不吞掉现有保存、通知或错误提示。

## 8. 验证

### 8.1 聚焦自检

新增或扩展聚焦测试，验证：

1. 每秒队列刷新不会调用配方选择器快照构建；
2. 一次制作台事件刷新只构建一次快照；
3. 选择器页签切换不重新扫描配方；
4. 制作、补货、上架后当前快照和卡片正确更新；
5. 队列进度、完成反馈、稳定排序和成品拖拽保持有效；
6. 空队列和 79 个已解锁配方两种数据规模均可工作。

### 8.2 回归测试

至少运行：

- `production_queue_scene_self_check.gd`
- `production_recipe_picker_self_check.gd`
- `production_queue_interaction_self_check.gd`
- `recipe_production_ui_self_check.gd`
- `recipe_production_timing_self_check.gd`
- `automation_settlement_self_check.gd`
- `mvp_self_check.gd`

Godot 4.6.1 headless 命令必须传入可写的 `--log-file` 路径。

### 8.3 运行时性能验收

使用与诊断阶段相同的 79 配方存档测量：

- 每秒队列刷新目标低于 5 ms；
- 选择器打开状态不得每秒重建配方快照；
- 一次选择器快照构建目标低于 100 ms；
- 选择器打开时的操作后完整刷新目标低于 200 ms；
- 操作过程中不再出现约 0.7 至 0.9 秒的周期性主线程阻塞。

时间阈值用于当前开发机器的聚焦验收，不作为跨硬件确定性单元测试断言。
