# 研发覆盖层与常驻制作区域设计

日期：2026-07-23  
项目：`project-rest-new`

## 1. 背景

当前主界面右侧工作台同时承载两类内容：

- 上方研发输入区：研发说明、研发设备、研发材料槽和研发执行按钮。
- 下方制作区域：厨房排程、已解锁配方列表、单项制作/补货/上架、批次进度，以及批量制作/上架/补货操作。

底部 `WorkbenchLauncher` 已有星辉、任务、库存、图鉴、采购、产出和经营中心七个入口。这些入口打开覆盖层；研发则是右侧默认页，因此当前导航层级不一致，也压缩了制作区域的常驻展示空间。

## 2. 目标

1. 把研发输入区从右侧常驻区域中摘出，改为底部入口打开的独立覆盖层。
2. 让当前制作区域占满释放后的右侧空间。
3. 保持当前制作区域的内容、操作和业务规则不变。
4. 保持研发选择、等待、结果、锁定说明和教程路径有效。
5. 让研发与其他底部入口遵循同一套覆盖层导航语义。

## 3. 非目标

本次不新增“制作队列管理器”，也不改变制作模型。

明确不包含：

- 新增暂停、取消、调序或手动领取成品。
- 改变并行制作、每个配方九批上限或自动完成入库规则。
- 改变制作、补货、上架和批量操作的业务逻辑。
- 重新设计现有制作行、进度条或厨房自动化面板。
- 新增存档字段或存档迁移。

“制作区域保持当前是什么就是什么”是本设计的硬边界。

## 4. 布局与导航

### 4.1 右侧常驻区域

右侧默认内容改为 `ProductionWorkbench`，占据当前右侧工作台除底部启动栏以外的全部高度。

它由现有制作相关内容拆出并原样保留：

- `KitchenAutomationPanel`
- `RecipeScroll`
- `RecipeRows`
- 配方行内的制作、补货、上架按钮
- 独立批次进度条
- 制作全部、上架全部和一键补货等当前已解锁的批量操作

本次只扩大可用高度，不改变这些控件的内容密度、排序、按钮语义或刷新规则。

### 4.2 研发覆盖层

新增独立 `ResearchOverlay`，承载当前所有研发专属内容：

- 研发状态和选择摘要
- 研发设备槽
- 六个研发材料槽
- 研发设备选择器
- 研发执行按钮
- 现有锁定原因、材料不足、等待和结果反馈

研发进度和结果弹窗继续覆盖在研发面板之上。结果确认后返回研发面板，并刷新右侧制作区域。

### 4.3 底部入口

`WorkbenchLauncher` 新增一个与现有入口同规格的 `64×64` 研发按钮。

按钮顺序确定为：

1. 星辉
2. 任务
3. 库存
4. 图鉴
5. 研发
6. 采购
7. 产出
8. 经营中心

研发放在图鉴与采购之间，使配方信息、研发和原料采购形成相邻功能组。八个按钮沿用当前间距、主题变化、图标尺寸和底部对齐方式。

## 5. 场景边界

将当前 `ResearchWorkbench` 按职责拆为两个场景：

- `ProductionWorkbench`：只负责常驻制作区域。
- `ResearchOverlay`：只负责研发输入和研发动作。

稳定结构和布局保留在 `.tscn` 中；脚本负责：

- 绑定当前 `GameState` 和 `Catalog`
- 刷新研发选择与制作数据
- 转发按钮信号
- 切换覆盖层
- 保持教程目标和可见反馈

不在运行时反复重挂同一组控件，也不复制第二套研发或制作状态。

## 6. 状态与数据流

### 6.1 打开与关闭研发

1. 玩家点击底部研发按钮。
2. 全局覆盖层切换为研发模式。
3. 研发面板读取现有 `selected_research_material_ids` 和 `selected_research_tool_id`。
4. 玩家关闭研发面板后，覆盖层关闭，右侧制作区域仍保持显示。
5. 再次打开研发时，当前研发选择继续保留。

### 6.2 研发材料选择

1. 玩家在研发面板点击材料槽。
2. 库存选择器临时显示在研发流程之上。
3. 选择或取消材料后返回研发面板，而不是退回右侧制作区域。
4. 研发材料耗尽时继续沿用当前自动移除和状态提示规则。

覆盖层需要记录“库存选择器由研发面板打开”这一返回上下文，但不新增持久化存档字段。

### 6.3 研发结果

1. 玩家执行研发。
2. 继续使用当前固定等待时长、进度弹窗和结果确认流程。
3. 成功研发产生的新配方写入现有状态。
4. 研发面板刷新当前选择与提示。
5. 常驻制作区域刷新配方列表；关闭研发后新配方立即可见。

### 6.4 制作刷新

制作区域继续读取现有 `recipe_production_queue_summary()`，沿用当前在线完成、离线结算和自动入库流程。研发覆盖层的开关不得暂停制作计时，也不得清空制作行或批次进度。

## 7. 锁定与异常反馈

- 研发入口在未解锁时仍保持可见。
- 玩家可以打开研发面板查看解锁条件。
- 未解锁时研发执行按钮保持锁定，并显示当前真实原因。
- 材料不足、设备未解锁、配方批次达到上限、补货不可用等状态继续使用当前禁用原因、工具提示和状态栏反馈。
- 研发覆盖层关闭或切换失败时不得修改研发选择或制作状态。
- 不通过教程跳过、入口可见性或界面切换伪造解锁。

## 8. 教程兼容

现有教程路由需要按新的职责边界调整：

- `research` 步骤打开研发覆盖层，并依次定位研发材料槽、设备槽和研发执行按钮。
- 研发材料库存选择器打开时，教程箭头定位真实库存项；选择后返回研发覆盖层。
- `craft` 和 `list` 步骤不再把研发当作默认页。它们关闭阻挡操作的覆盖层，并直接定位常驻制作区域中的真实制作或上架按钮。
- 教程跳过只隐藏引导，不打开研发、不授予配方，也不改变制作状态。

## 9. 预期代码影响

主要涉及：

- `scenes/Main.tscn`
- `scenes/ui/navigation/workbench_launcher.tscn`
- `scenes/ui/pages/research_workbench.tscn`
- 新的制作工作台或研发覆盖层场景
- `scripts/main_view.gd`
- `scripts/ui/navigation/workbench_launcher.gd`
- 与覆盖层模式、教程路由和节点路径相关的聚焦测试

实现时允许调整文件名以符合现有目录约定，但不得把稳定面板结构重新堆回 `main_view.gd`。

## 10. 验收标准

### 10.1 布局

- 底部存在八个 `64×64` 入口。
- 研发位于图鉴与采购之间。
- 制作区域始终位于右侧并占满研发区释放后的高度。
- 研发覆盖层打开时，下方制作区域保持存在且状态不被重建。

### 10.2 真实交互

- 使用真实鼠标按下和释放可以打开、关闭研发覆盖层。
- 从研发打开材料选择器后，完成选择会返回研发覆盖层。
- 在研发、库存及其他覆盖层之间切换不会丢失研发材料和设备选择。
- 研发成功后，右侧制作区域出现新配方。
- 未解锁研发时能看到准确的前置条件，且不能执行研发。

### 10.3 回归

- 制作计时和离线完成保持通过。
- 单配方九批上限保持通过。
- 制作完成自动入库和可见反馈保持通过。
- 制作、补货、上架及批量操作保持通过。
- 研发等待、结果、补货和线索系统保持通过。
- 教程研发、制作和上架步骤继续命中真实控件。
- 其他底部覆盖层的打开、切换和关闭行为保持通过。

### 10.4 验证方式

- 新增或更新场景结构自检，验证节点归属、底部入口顺序和垂直占用关系。
- 新增真实输入路径自检，验证研发入口和嵌套库存选择器的返回路径。
- 更新覆盖层状态与教程路由自检。
- 运行现有制作计时、制作 UI、研发补货、研发等待和工作台覆盖层回归。
- Godot 无头测试必须传入位于可写目录的 `--log-file`，不得使用 `NUL`。
